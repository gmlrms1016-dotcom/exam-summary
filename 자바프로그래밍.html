2. 자바의 태동과 WORA ★핵심2주차

기계어(0·1) → 어셈블리어(니모닉) → 고급언어(C/C++, Java, C#) 순으로 발전했습니다.

시기내용
1991선마이크로시스템즈 제임스 고슬링의 그린 프로젝트 (초기명 오크 OAK)
1995자바 발표 · 목적은 플랫폼 독립성
2009오라클이 선마이크로시스템즈 인수
WORA (Write Once Run Anywhere) — 한 번 작성한 코드가 모든 플랫폼에서 실행
용어설명
바이트코드 (byte code)자바 소스를 컴파일한 CPU 중립적 목적코드 · .class 에 저장
JVM (Java Virtual Machine)바이트코드를 인터프리터 방식으로 해석·실행하는 가상기계
⚠️ JVM 자체는 플랫폼에 종속적(OS마다 별도 제공)이지만, 바이트코드는 플랫폼 독립적입니다.
컴파일: 자바 .java → .class / C .c → .obj → .exe

// switch 문 — 학점 매기기
switch (score/10) {
  case 10:
  case 9:  grade='A'; break;    // break 없으면 다음 case로 계속(fall-through)

객관식

1자바의 WORA 에 대한 설명으로 옳은 것은?

정답 A — Write Once Run Anywhere — 바이트코드(.class)를 각 OS 의 JVM 이 실행합니다.

2자바의 기본 타입(8개) 이 아닌 것은?

정답 C — String 은 클래스(레퍼런스 타입)입니다. 기본 타입 = boolean · char · byte · short · int · long · float · double

3System.out.println((int)2.9 + 1.8); 의 출력은?

정답 B — (int)2.9 가 먼저 2가 되고 2 + 1.8 = 3.8. (int)(2.9 + 1.8) 이면 4

4do-while 문의 특징으로 옳은 것은?

정답 C — do-while 은 실행 후 조건을 검사해서 최소 1번 실행됩니다. 반복조건을 생략하면 컴파일 오류.

5정수를 0으로 나눌 때 발생하는 예외는?

정답 B — 0으로 나누기 = ArithmeticException · 정수가 아닌 문자열 변환 = NumberFormatException · Scanner 입력 타입 불일치 = InputMismatchException

6JVM 에 대한 설명으로 옳지 않은 것은?

정답 B — JVM 자체는 플랫폼 종속적(OS 마다 제공)이고, 바이트코드가 플랫폼 독립적입니다.

7switch 문의 case 값으로 쓸 수 없는 것은?

정답 D — case 값은 문자 · 정수 · 문자열 리터럴만 가능 (실수 불가)

8다음 배열 선언 중 컴파일 오류가 나는 것은?

정답 C — 자바는 선언할 때 크기를 지정할 수 없음 → int a[10]; 은 컴파일 오류

9Scanner 로 정수를 입력받는 메서드는?

정답 B — next() 문자열 · nextInt() 정수 · nextDouble() 실수 · nextBoolean() 논리값

10main() 메소드의 원형에 반드시 들어가는 것이 아닌 것은?

정답 D — public static void main(String[] args) — 반드시 public · static · void, 매개변수는 문자열 배열
