2. 자바의 태동과 WORA ★핵심2주차

기계어(0·1) → 어셈블리어(니모닉) → 고급언어(C/C++, Java, C#) 순으로 발전했습니다.

시기내용
1991선마이크로시스템즈 제임스 고슬링의 그린 프로젝트 (초기명 오크 OAK)
1995자바 발표 · 목적은 플랫폼 독립성
2009오라클이 선마이크로시스템즈 인수
WORA (Write Once Run Anywhere) — 한 번 작성한 코드가 모든 플랫폼에서 실행
용어설명
바이트코드 (byte code)자바 소스를 컴파일한 CPU 중립적 목적코드 · .class 에 저장
JVM (Java Virtual Machine)바이트코드를 인터프리터 방식으로 해석·실행하는 가상기계
⚠️ JVM 자체는 플랫폼에 종속적(OS마다 별도 제공)이지만, 바이트코드는 플랫폼 독립적입니다.
컴파일: 자바 .java → .class / C .c → .obj → .exe

3. 자바 vs C/C++ 실행 환경2주차

구분내용
자바링크 과정 없음 · 필요한 클래스를 실행 중 동적 로딩(클래스로더)
C/C++컴파일 → 링크로 하나의 .exe 생성 · 플랫폼마다 다시 컴파일 필요
속도 개선JIT(Just In Time) 컴파일러가 바이트코드를 해당 CPU 기계어로 변환

4. JDK · JRE · API2주차

JDK(개발 키트) = 개발도구 + JRE  /  JRE(실행 환경) = JVM + 표준 라이브러리
도구설명
javac자바 소스를 바이트코드로 변환하는 컴파일러
java자바 응용프로그램 실행기
javadoc소스로부터 HTML API 문서 생성
jar클래스들을 압축한 아카이브(.jar) 생성
javap클래스파일의 바이트코드를 보여주는 디어셈블러
jdb디버거

자바 API = JDK에 포함된 클래스 라이브러리. 패키지(package) 단위로 제공되며 필요한 것만 import 해서 사용합니다. Java 9부터 모듈(module) 프로그래밍이 도입되었습니다.

5. 자바의 특성 ★암기2주차

특성설명
플랫폼 독립성어디서든 동일하게 실행
객체지향상속성 · 다형성 · 캡슐화
가비지 컬렉션메모리 반환 기능 없이 new(할당)만 있고 JVM이 자동 회수 → 실시간 시스템엔 부적합
멀티스레드운영체제 도움 없이 자체 지원
안전성타입 체크 엄격 · 포인터 개념 없음
⚠️ 하나의 소스(.java)에 여러 클래스를 쓸 수 있지만 public 클래스는 1개만 가능하고, 파일명 = public 클래스명 이어야 합니다.
IDE: 이클립스(Eclipse) · IntelliJ IDEA

7. 타입 변환 ★시험단골3주차

구분설명
자동 형변환작은 타입 → 큰 타입 · 컴파일러가 자동
강제 형변환(캐스팅)큰 타입 → 작은 타입 · ()로 지정 · 값 손실 우려
System.out.println((int)2.9 + 1.8);      // 3.8  ← (int)2.9=2, 2+1.8
System.out.println((int)(2.9 + 1.8));    // 4    ← 4.7을 int로
System.out.println((int)2.9 + (int)1.8); // 3    ← 2+1

byte b = 127; int i = 100;
System.out.println(b + i);          // 227
System.out.println((byte)(b + i));  // -29  ← 손실 발생

조건문

// switch 문 — 학점 매기기
switch (score/10) {
  case 10:
  case 9:  grade='A'; break;    // break 없으면 다음 case로 계속(fall-through)
  case 8:  grade='B'; break;
  case 7:  grade='C'; break;
  case 6:  grade='D'; break;
  default: grade='F';           // 일치하는 것 없을 때 (생략 가능)
}
⚠️ case 값은 문자·정수·문자열 리터럴만 가능합니다. (실수·변수·수식 불가)
조건문이 너무 많으면 다중 if-else 대신 switch 사용을 권장합니다.
