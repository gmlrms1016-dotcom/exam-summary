5. inode와 링크 ★핵심3주차

inode = 파일의 정보(크기·소유자·권한·데이터 위치)를 담은 고유 번호표. 파일 1개당 1개. 이름이 달라도 inode가 같으면 같은 파일입니다.

구분명령inode원본 삭제 시
하드 링크ln 원본 링크원본과 동일내용 유지
심볼릭 링크ln -s 원본 링크새 번호연결 끊김
cp /etc/hosts ex_data     # 실습용 원본
ls -i                     # inode 확인
ln    ex_data ex_data.ln  # 하드 링크
ln -s ex_data ex_data.sl  # 심볼릭 링크

202726865 ex_data         ← 원본
202726865 ex_data.ln      ← 같은 inode!
202727542 ex_data.sl      ← 다른 inode!

rm ex_data                # 원본 삭제
  ex_data.ln  → 384바이트 그대로 살아있음
  ex_data.sl  → ex_data 를 가리키지만 대상이 없어 깨짐
touch ex_data             # 재생성하면 심볼릭 링크 복구
심볼릭 링크는 Windows의 바로 가기와 같은 개념입니다.

6. 접근 권한 (chmod) ★핵심3주차

① 기호 모드 (심볼릭 모드)

구분값
대상u 소유자 · g 그룹 · o 기타 · a 전체
연산+ 추가 · - 제거 · = 지정
권한r 읽기 · w 쓰기 · x 실행
chmod u+w centos_cp.txt      # 소유자에게 쓰기 추가
chmod u-w centos_cp.txt      # 소유자 쓰기 제거 → -r--r--r--
chmod u+x,go+w story.txt     # 쉼표로 여러 대상 동시 지정
chmod u-x,go-w story.txt     # 원상복구

② 8진수(숫자) 모드

u (소유자)g (그룹)o (기타)
권한읽기(r)·쓰기(w)·실행(x)읽기(r)·쓰기(w)·실행(x)읽기(r)·쓰기(w)·실행(x)
자릿값400 + 200 + 10040 + 20 + 104 + 2 + 1
각 자리는 r=4, w=2, x=1 의 합 → 755=rwxr-xr-x · 644=rw-r--r-- · 777=rwxrwxrwx
chmod 775 centos_cp.txt      # -rwxrwxr-x
rm -i yesterday.txt          # -i : 삭제 전 하나씩 확인(대화식)

12. ★시험문제 — DNF 작동 흐름도 (그림 4-111)4주차

dnf install 패키지이름 명령이 내부적으로 작동하는 순서 — 4주차 수업 화면에 시험문제로 나온 그림입니다.

순서하는 일
①dnf install 입력
②/etc/yum.repos.d/ 디렉터리의 repo 파일을 열어서 URL 주소 확인
③전체 패키지 목록 파일 요청 (내 컴퓨터 → 저장소)
④전체 패키지 목록 파일만 다운로드 (저장소 → 내 컴퓨터)
⑤설치할 패키지와 관련된 패키지의 이름을 화면에 출력
⑥'y' 를 입력하면 설치에 필요한 패키지 파일 요청 (내 컴퓨터 → 저장소)
⑦설치할 패키지 파일을 다운로드해서 자동 설치 (저장소 → 내 컴퓨터)
외우는 요령 — 입력 → repo 확인 → 목록 요청 → 목록만 다운 → 이름 출력 → y 입력 · 파일 요청 → 파일 다운 · 자동 설치
요청(③⑥)은 내 컴퓨터 → 저장소, 다운로드(④⑦)는 저장소 → 내 컴퓨터 · 목록(③④)을 먼저 받고 파일(⑥⑦)은 y 를 누른 뒤
저장소 = baseos · appstream · 기타 패키지 · 패키지 목록 (인터넷으로 연결) · 교재 예시는 실습 11 의 mysql8.4-errmsg, 핵심 repo 파일은 rocky.repo
⑥ 의 끝 단어는 사진에서 가려져 있어 '요청' 은 추정입니다.

객관식

1프롬프트 기호 # 이 뜻하는 것은?

2하드 링크에 대한 설명으로 옳은 것은?

정답 C — 하드 링크(ln)는 원본과 같은 inode 라 원본을 지워도 내용이 남습니다. 새 inode · 연결 끊김 · 바로 가기는 심볼릭 링크(ln -s)의 특징입니다.

3chmod 755 파일 을 실행한 뒤의 권한은?

정답 A — r=4, w=2, x=1 → 7=rwx, 5=r-x 이므로 rwxr-xr-x 입니다. (644=rw-r--r--, 777=rwxrwxrwx, 775=rwxrwxr-x)

4사용자 계정 정보(UID·GID·홈 디렉터리·셸)가 들어 있는 파일은?

정답 C — /etc/passwd = 사용자 계정 · /etc/group = 그룹 · /etc/shadow = 암호(해시)

5비어 있지 않은 디렉터리까지 강제로 삭제하는 명령은?

정답 B — rmdir 은 빈 디렉터리만 삭제, rm -i 는 삭제 전 하나씩 확인, rm -rf 는 강제 삭제(주의!)입니다.

6/etc/shadow 에서 암호 필드가 ! 나 * 로 시작하는 계정은?

7rmdir 명령에 대한 설명으로 옳은 것은?

정답 A — rmdir 은 빈 디렉터리만 삭제. 내용이 있으면 rm -rf 를 씁니다.

8user100:x:1001:1001::/home/user100:/bin/bash 에서 세 번째 필드 1001 의 의미는?

정답 B — /etc/passwd = 이름 : x : UID : GID : 설명 : 홈 : 셸 → 세 번째가 UID, 네 번째가 GID

9chmod 기호 모드에서 대상 g 가 뜻하는 것은?

정답 B — u 소유자 · g 그룹 · o 기타 · a 전체

10rm -i yesterday.txt 에서 -i 옵션의 의미는?

정답 B — -i = interactive, 삭제 전 확인. 강제는 -f, 재귀는 -r

11usermod -l manager master 를 실행한 결과로 옳은 것은?

정답 B — usermod -l 새이름 기존이름 — 새 이름이 앞, 기존 이름이 뒤입니다.

12groupadd -g 2018 -o db_space 에서 -o 옵션의 의미는?

13/etc/gshadow 에서 gp_zone::: 처럼 두 번째 칸이 비어 있는 것은?

정답 A — gshadow = 그룹명 : 암호 : 관리자 : 소속 사용자. gpasswd -r gp_zone 으로 암호를 지우면 빈칸이 됩니다.

14rpm -Uvh mysql8.4-* 가 실패한 이유와 해결 방법으로 옳은 것은?

정답 B — rpm 은 의존성을 스스로 해결하지 못합니다. dnf -y install mysql8.4-* 는 종속 꾸러미 4개까지 받아 설치했습니다.
