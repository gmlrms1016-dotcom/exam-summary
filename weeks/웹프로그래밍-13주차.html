🎬 13주차 그림 — 새 창으로 크게 보기

  • 콜백 → 콜백 지옥 (안으로 계속 들어감) · Promise 3가지 상태 · async / await · 실행 순서 (동기 → Promise → 타이머)

1. ✍️ “콜백함수 넘기기 뜻?” — 함수를 다른 함수의 인자로 넘기기

function greet(name, callback) {          // callback = 인자로 받은 '함수' (아직 실행 안 함)
    console.log(`Hello, ${name}!`);       // 먼저 인사 → Hello, Rahul!
    callback();                           // 받은 함수를 '나중에 불러 줌' → sayGoodbye() 실행
}                                         // greet 끝

function sayGoodbye() {                   // 넘겨줄 함수
    console.log("Goodbye!");              // Goodbye!
}                                         // sayGoodbye 끝

greet("Rahul", sayGoodbye);               // sayGoodbye 를 () 없이 넘김 = 함수 그 자체를 넘김 (실행 결과가 아님)
Hello, Rahul!
Goodbye!
  • 🤖 greet("Rahul", sayGoodbye()) 처럼 괄호를 붙여 넘기면 그 자리에서 먼저 실행돼 Goodbye! 가 먼저 찍히고, 결과 undefined 가 넘어가 TypeError: callback is not a function (node 확인)
  • 🤖 콜백함수 넘기기 = 함수를 값처럼 다른 함수의 인자로 넘겨서, 받은 함수가 알맞은 때(일이 끝난 뒤 등)에 대신 불러 주게 하는 것 · sayGoodbye 처럼 괄호 없이 넘김 (sayGoodbye() 로 넘기면 그 자리에서 실행된 결과(undefined)가 넘어감)
  • 비동기에서 쓰는 이유 — 데이터를 받는 데 시간이 걸리니 “다 받으면 이 함수를 불러 줘” 하고 넘겨 둠 (fetchData(processData) · 2초 뒤 Processing data: Here is your data.)

2. 콜백 지옥 (callback hell) — 콜백 안에 콜백 안에 콜백

function getUser(id, callback) {                      // 1초 뒤 사용자 정보를 콜백으로
  setTimeout(() => {                                  // 1000ms 뒤 실행
    console.log(`Fetched user with ID: ${id}`);       // Fetched user with ID: 1
    callback({ id, name: "Rahul" });                  // {id: 1, name: "Rahul"} 를 넘김
  }, 1000);                                           // setTimeout 끝
}                                                     // getUser 끝

function getPosts(user, callback) {                   // 그 사용자의 글 목록
  setTimeout(() => {                                  // 다시 1초 뒤
    console.log(`Fetched posts for ${user.name}`);    // Fetched posts for Rahul
    callback(["Post1", "Post2"]);                     // 글 2개를 넘김
  }, 1000);                                           // setTimeout 끝
}                                                     // getPosts 끝

function getComments(post, callback) {                // 그 글의 댓글
  setTimeout(() => {                                  // 다시 1초 뒤
    console.log(`Fetched comments for ${post}`);      // Fetched comments for Post1
    callback(["Comment1", "Comment2"]);               // 댓글 2개를 넘김
  }, 1000);                                           // setTimeout 끝
}                                                     // getComments 끝

getUser(1, (user) => {                                // ① 사용자를 받으면
  getPosts(user, (posts) => {                         // ② 그 안에서 글을 받고
    getComments(posts[0], (comments) => {             // ③ 또 그 안에서 첫 글의 댓글을 받음 → 안으로 계속 들어감 = 콜백 지옥
      console.log("Comments:", comments);             // Comments: [ 'Comment1', 'Comment2' ]
    });                                               // ③ 끝
  });                                                 // ② 끝
});                                                   // ① 끝
Fetched user with ID: 1
Fetched posts for Rahul
Fetched comments for Post1
Comments: [ 'Comment1', 'Comment2' ]
  • 1초 · 2초 · 3초에 한 줄씩 — 앞 작업이 끝나야 다음 작업을 시작해서 들여쓰기가 계속 깊어짐 → 읽기 · 고치기 어려움 = 콜백 지옥
  • 해결 방법 2가지 (✍️ “JS 비동기작업 { 1) Promise 객체 2) }”) → ① Promise ② async / await

3. 해결 ① Promise — 3가지 상태 · then · catch

📄 수업 파일 주석 — 결과를 나타내는 3가지 상태: 대기(Pending) 아직 결과를 받지 못한 상태 · 이행(Fulfilled) 연산이 성공적으로 완료된 상태 · 거부(Rejected) 연산이 실패한 상태

const promise = new Promise((resolve, reject) => {    // 만들면 대기(Pending)
  const success = true;                               // 성공했다고 가정
  if (success) resolve("작업 완료");                   // 성공 → 이행(Fulfilled) · 값 "작업 완료"
  else reject("작업 실패");                            // 실패 → 거부(Rejected) · 이유 "작업 실패"
});                                                   // Promise 끝

promise                                               // 결과가 나오면
  .then((res) => console.log(res))                    // 이행이면 then → 작업 완료
  .catch((err) => console.error(err));                // 거부면 catch → 작업 실패
작업 완료
  • success = false 로 바꾸면 catch 쪽이 실행돼 작업 실패 (console.error)

4. 해결 ② async / await — 비동기를 동기 코드처럼

  • 📄 async 함수 = 항상 Promise 를 반환 (return 값이 Promise.resolve(값) 으로 감싸짐) → then · catch 를 쓸 수 있음
  • 📄 await = Promise 의 연산이 끝날 때까지 함수 실행을 일시중지 → 동기 함수처럼 보이게 · async 함수 안에서만 쓸 수 있음
    • ⚠️ 팩트체크 — 일반 함수 안에서 쓰면 node 오류 SyntaxError: await is only valid in async functions and the top level bodies of modules → 정확히는 async 함수 안 또는 모듈(<script type="module">)의 맨 바깥에서도 돼요 · 수업 범위에서는 “async 함수 안에서” 로 기억
async function myAsyncFunction() {                    // async → 항상 Promise 를 돌려줌
  return "Hello, Async!";                             // = Promise.resolve("Hello, Async!")
}                                                     // 함수 끝

myAsyncFunction()                                     // Promise 가 돌아옴
  .then(res => console.log(res));                     // 이행 값 → Hello, Async!
Hello, Async!
  • 📄 같은 일을 두 방식으로 — Promise 방식 return fetch('/api/user').then((res) => res.json()).catch(…) · async/await 방식 const res = await fetch('/api/user'); return await res.json(); 를 try { … } catch (err) { … } 로 감쌈

5. 🤖 실행 순서 — 동기 → Promise(then) → 타이머

수업 파일을 한 번에 실행하면 (아래 ⚠️ 처럼 이름을 고친 뒤) 이 순서로 찍혀요:

Hello, Rahul!
Goodbye!
other work ....
작업 완료
Hello, Async!
Fetched user with ID: 1
Data fetched!
Processing data: Here is your data.
Fetched posts for Rahul
Fetched comments for Post1
Comments: [ 'Comment1', 'Comment2' ]
  • 🤖 동기 코드를 먼저 끝까지 (Hello · Goodbye · other work ....) → 그다음 Promise 의 then (작업 완료 · Hello, Async!) → 그다음 시간이 된 타이머 순서 (1초 사용자 → 2초 Data fetched · posts → 3초 comments)
  • ⚠️ 수업 파일에는 fetchData 라는 이름의 함수가 2개 (2번 콜백 예제 · 5번 await 예제) — 함수 선언은 끌어올려져(호이스팅) 나중 것이 앞 것을 덮어써서, fetchData(processData) 가 await 예제 쪽을 부름 → fetch("~") 가 실패 (node: Failed to parse URL from ~ 로 멈춤 · 브라우저: 콘솔 오류). 위 순서는 두 번째 이름을 fetchData2 로 바꿔서 실행한 결과예요

6. ✍️ HTTP 메서드 — GET · POST · PUT · DELETE

  • ✍️ “get, post, put, delete 들을 HTTP 메서드라고 함” — 서버에 보내는 요청의 종류 (12주차 ✍️ 요청 방식 · CRUD 와 이어짐)
  • 🤖 fetch(주소) 처럼 아무것도 안 정하면 GET · 다른 메서드는 fetch(주소, { method: "POST" }) 처럼 정함 (수업 파일에는 GET 예만 있음)

7. 한 줄 정리

  • 콜백 = 함수를 인자로 넘겨 나중에 불러 주게 함 (괄호 없이 넘김) · 콜백 안에 콜백 → 콜백 지옥
  • 해결 ① Promise — 상태 3가지 대기(Pending) · 이행(Fulfilled) · 거부(Rejected) · resolve → then · reject → catch
  • 해결 ② async / await — async 함수는 항상 Promise 반환 · await 는 끝날 때까지 기다림 · async 함수 안에서만
  • 실행 순서 = 동기 → Promise then → 타이머 · GET · POST · PUT · DELETE = HTTP 메서드
