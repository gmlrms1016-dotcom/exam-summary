9주차 · 4장 클래스 — this() · 오버로딩 · 접근 지정자 · static · 객체 배열

포인트핵심 · 답그림
this()같은 클래스의 다른 생성자 호출 · 생성자 안에서만 · 반드시 첫 문장 · new Book() → this("", "") → 돌아와서 “기본 생성자 호출됨” (출력 첫 줄)①
메소드 오버로딩이름 같고 매개변수 개수 · 타입이 다름 · 리턴 타입은 상관없음 (리턴 타입만 다르면 already defined 오류) · getSum(1.1, 2.2) → 3.3000000000000003②
✍️ 접근 지정자private(클래스 안) < 디폴트(✍️ 아무것도 안 씀 · 같은 패키지) < protected(같은 패키지 + 자식 클래스) < public(모든 클래스) · 예제 4-10 aClass.b = 10; → b has private access③
✍️ static클래스당 하나 · 클래스 로딩 때 생김 · 모든 객체가 공유 · Counter → gongyuCount 2 · instanceCount 1 · 1 · static 메소드는 non-static 멤버 · this 를 못 씀 · Calc.abs(-5) → 5④
객체 배열Book[] book = new Book[2]; → 칸은 null → book[i] = new Book(…) 로 객체 생성 · 빼먹으면 NullPointerException⑤
for-each (복습)for (int point : pointsArr) → 80 이상만 82점 · 95점 · 88점

10주차 · 5장 상속 — extends · 생성자 호출 순서 · super() · toString

포인트핵심 · 답그림
상속 · extends부모 = 슈퍼 클래스 · 자식 = 서브 클래스 · class ColorPoint extends Point · 클래스 다중 상속 X (extends A, B → 컴파일 오류) · 횟수 무제한 · 최상위 조상 java.lang.Object⑥ ⑨
상속과 private서브 객체 안에 슈퍼 멤버도 들어 있지만 private 은 서브 클래스도 직접 X (x has private access in Point) → 부모의 생성자 · 메소드로⑥
생성자 호출 순서서브 객체 생성 → 둘 다 실행 · 호출은 서브 → 슈퍼 · 실행은 슈퍼 → 서브 (13쪽) · ConstructorEx2 → 생성자A / 생성자B⑦
super 가 없으면컴파일러가 첫 줄에 super(); → 슈퍼의 기본 생성자 · new BBB(5) 여도 AAA() → 생성자A / 매개변수생성자B · 슈퍼에 기본 생성자가 없으면 컴파일 오류 (17쪽)⑧
super(…)슈퍼 생성자를 직접 고름 · super(x) → AAAA(int x) → 매개변수생성자A5 / 매개변수생성자B5 · 반드시 첫 줄 (둘째 줄 → call to super must be first statement)⑦ ⑧
super.메소드()부모의 메소드 호출 · super.printInfo() (TV · Student · Customer · Magazine) · print 로 이어서 마지막 println → 한 줄⑨
과제 4 toStringpublic String toString() 을 다시 써서 문자열을 돌려줌 · TextBook → super.toString() + " 학년학기 : " + … · println(t1) 만 써도 자동 호출 · public 빼면 오류 · super. 없이 부르면 StackOverflowError⑨

11주차 · 5장 상속 (2) — 오버라이딩 · 동적 바인딩 · 추상 클래스 · 인터페이스

포인트핵심 · 답그림
메소드 오버라이딩슈퍼 클래스 메소드를 서브 클래스에서 재정의 — 이름 · 매개변수 타입과 개수 · 리턴 타입까지 모두 동일 (32쪽) · Weapon fire() 1 → Cannon fire() 10 · @Override 는 선택 · 접근 범위를 좁히면 오류⑩
동적 바인딩실행할 메소드를 실행 시에 결정 → 오버라이딩된 메소드가 항상 호출 (39쪽) · Weapon w = new Cannon(); w.fire() → 10 · paint() 안의 draw() 도 실제 객체 것⑩
오버로딩 vs 오버라이딩오버로딩 = 이름 같고 매개변수가 다름 · 같은 클래스 · 정적 바인딩(컴파일 시) / 오버라이딩 = 모두 동일 · 상속 관계 · 동적 바인딩 (42쪽) · super.메소드() 는 정적 바인딩 (40쪽)⑩
추상 메소드 · 추상 클래스abstract · 몸체 없이 ; · 추상 메소드가 하나라도 있으면 클래스 앞에 abstract 필수 · 객체 생성 불가 (Calculator is abstract; cannot be instantiated) · 다 구현 안 하면 자식도 abstract (43 ~ 46쪽) · CalcMain 5 · -1 · 3.0⑪
인터페이스 구성상수 = public static final 생략 · 추상 메소드 = public abstract 생략 · default 메소드는 구현 클래스에 자동 상속 · 필드(변수) 선언 불가 (52 · 54쪽) · 객체 생성 불가 · 레퍼런스 변수는 가능 (55쪽)⑫
implements추상 메소드를 모두 구현 · 구현할 때 public 필수 (빼면 weaker access privileges 오류 · 60쪽) · 여러 개 동시 구현 가능⑫ ⑬
상속 + 다중 구현인터페이스끼리 extends (여러 개 가능) · 클래스는 extends 하나 + implements 여러 개 — class SmartPhone extends PDA implements MobilePhoneInterface, MP3Interface (예제 5-9)⑬
추상 클래스 vs 인터페이스공통: 객체 생성 X · 다형성 / 추상 클래스 = 일반 메소드 · 변수 필드 O / 인터페이스 = 변수 필드 X · protected X · 다중 상속 O (62쪽)⑭
