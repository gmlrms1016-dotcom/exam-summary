7주차 — 🔥 ALTER · Quiz 7-3 dept · dmember (7주차 자세히)

  • 🔥 ✍️ 필기 — ALTER ADD 가 시험에 나옴 (“추가하는 게 시험문제임”) · 7주차 내용은 시험의 10%
  • ALTER (DDL) = 테이블 구조 변경 — 추가 ALTER TABLE project ADD budget int; (기존 행의 budget 은 NULL) · 수정 ALTER TABLE project MODIFY projname varchar(20); (✍️ MySQL · Oracle 문법, MS-SQL 은 다름) · 삭제 ALTER TABLE project DROP COLUMN budget;
  • 🔥 Quiz 7-3 (8 · 9쪽 시험 페이지) — 생성 순서 dept → dmember (부모 → 자식) · 삭제 순서 dmember → dept (자식 → 부모) · 입력 순서 dept → dmember · dmember.dept_id 자료형 = char(3) (참조하는 열과 같게) · FK 테이블명 dept · FK 열 dept_id
  • 9쪽 빈칸: 1) dmember 2) dept 3) CREATE 4) PRIMARY · (빈칸) CREATE · 5) char(3) · (빈칸) PRIMARY · 6) FOREIGN KEY(dept_id) REFERENCES dept(dept_id)
  • 순서를 어기면 — 자식 먼저 CREATE 1824 · 자료형 다름 3780 · 부모 먼저 DROP 3730 · 없는 학과 입력 1452
  • DCL = GRANT(권한부여 · TO) · REVOKE(권한취소 · FROM) — 중간고사엔 안 나옴 · 데이터베이스 사용자 = DBA(root) · 응용 프로그래머 · 일반(최종) 사용자

6주차 — 무결성 제약조건 · SELECT · UPDATE · DELETE (6주차 자세히)

✍️ 필기 — 오늘 하는 실습이 다 중간고사 시험 예상문제 (실습 6-1 customer SELECT · Quiz 6-1 직원 SELECT · 실습 6-2 주소록 UPDATE/DELETE · 실습 6-03 부서/사원 참조 무결성) · 교재(생능) 1 · 2 · 3장 / 5장 p132~147 · p170~174 · p176 / 6장 p188~199 · p207~210
무결성 제약조건내용SQL범위
개체 무결성 (엔티티)기본키는 널 값을 가질 수 없다 — ✍️ “객체”라고 쓰면 오답PRIMARY KEY중간
참조 무결성 ★참조하는 테이블의 외래키 값은 참조되는 테이블의 기본키 값에 반드시 존재 — ✍️ 하는 / 되는 빈칸FOREIGN KEY중간
키 제약조건키는 중복된 값을 갖지 않는다UNIQUE기말
도메인 제약조건값의 범위 · 기본값CHECK · DEFAULT기말
  • ⭐ 강조 — 참조 무결성 검사가 필요한 곳 = 부모 UPDATE · DELETE, 자식 INSERT · UPDATE (부모 입력 · 자식 삭제는 제약 없음) · 1-2 부모 수정 Error 1451 · 1-6 자식을 없는 값으로 수정 Error 1452
  • ⭐ 강조 — SELECT 실행 순서 FROM → WHERE → SELECT · 관계 연산자 > >= = <>/!= <= < · 이하 <= 는 그 값도 포함
  • ⭐ 강조 — UPDATE 테이블 SET 필드=값, 필드=값 WHERE …; · DELETE FROM 테이블 WHERE …; — ✍️ DELETE 는 레코드 단위라 필드명 · * 안 씀 · (MySQL) SET SQL_SAFE_UPDATES = 0;
  • ⭐ 강조 — 수강(학번, 과목번호, 성적): 후보키 = 기본키 (학번, 과목번호) · 대체키 없음 · (학번, 과목번호, 성적) 은 최소성 위배 → 수퍼키
  • ✍️ 필기 — 용어 같은 말: 투레행(투플 = 레코드 = 행) · 필속열(필드 = 속성 = 열 = 컬럼) · 테이블 = 릴레이션 · 차수 = 필드 개수 · 카디날리티 = 레코드 개수 · 스키마 = 내포(정적) · 인스턴스 = 외연(동적)

5주차 — 키 5종 · 뷰 · 널 값 · INSERT (5주차 자세히)

키성질 ★
수퍼키유일성
후보키유일성 + 최소성
기본키중복불가 · 필수입력 (후보키 중 선택한 하나)
대체키후보키 중 기본키로 뽑히지 않은 키
외래키다른 릴레이션의 기본키를 참조
  • ⭐ 강조 — 신입생: 후보키 {학번}·{주민등록번호} / 기본키 {학번} / 대체키 {주민등록번호} · (학번,주민등록번호)·(주민등록번호,이름) 은 최소성 위배 → 후보키 아님(수퍼키)
  • ⭐ 강조 — 뷰(view) = 가상의 테이블 · 장점 보안 · 사용의 편의성 · CREATE VIEW 뷰이름 as SELECT … FROM …; / DROP VIEW 뷰이름;
  • ⭐ 강조 — 뷰에 INSERT 하면 기반 테이블에 저장되고, 뷰에 없는 열은 NULL·기본값 · 뷰 이름 뒤 괄호로 뷰의 열 이름 바꾸기 가능
  • ⭐ 강조 — 널 값(NULL) = 알려지지 않은 값, 0도 공백도 아님 · 따옴표 붙인 'NULL' 은 글자
  • ⭐ 강조 — INSERT 5가지: 열이름 생략 · NULL · 열 순서 변경 · 열 일부만 · DEFAULT (TIMESTAMP DEFAULT NOW() = 현재 시각 자동)
  • ⭐ 강조 — 릴레이션 특성 4가지: 투플 유일성 · 무순서성 / 속성 무순서성 · 원자성
  • ⭐ 강조 — 데이터 모델 3요소 SOC(구조 · 연산 · 제약조건) · 스키마 = 구조 + 제약조건 명세
  • ✍️ 필기 — 논리적 독립성(개념↔외부) · 물리적 독립성(내부↔개념·외부) · 파일시스템 단점 중복성·종속성 ↔ DBMS 장점 독립성

4주차 — 강의자료 시험범위 페이지 ★ (4주차 자세히)

페이지외울 내용
3p정의 4: 공유 · 통합(중복 최소화) · 저장 · 운영 / 특징 4: 실시간 접근 · 계속 변화 · 동시 공유 · 내용 기반 참조
4p파일시스템 단점: 중복성 · 종속성 ↔ DBMS 장점: 중복 최소화 · 독립성 증진 / DBMS 단점: 고비용 · 회복 기법 복잡 / 발전: 1세대 네트워크·계층 → 2세대 관계 → 3세대 객체지향·객체관계 → 4세대 NoSQL·NewSQL
5p + 25p외부 스키마 → 개념 스키마 → 내부 스키마 (ANSI/SPARC)
7p빈칸: CREATE TABLE · NOT NULL · PRIMARY KEY(학과번호)
21p빈칸: int · varchar(50) · char(2) · NOT NULL · PRIMARY KEY(번호) · FOREIGN KEY(학과번호) REFERENCES 학과(학과번호)
24p스키마 = 구조와 제약조건에 대한 명세 · 표기법 학생(학번, 이름, 학년, 성별) · 인스턴스 = 실제 저장된 값
32p메타데이터 = 데이터에 관한 데이터 · 데이터 사전 = 시스템 카탈로그 · 데이터 디렉토리
34p데이터 모델 3요소 = 구조 · 연산 · 제약조건
41p차수 = 애트리뷰트(열) 수 · 카디널리티 = 투플(행) 수 · 도메인 = 값들의 집합
42p신입생(학번, 주민등록번호, 이름, 주소, 학과명) · 차수 5 · 카디널리티 4 · 기본키 학번
  • ⭐ 강조 — 외래키: 참조되는 기본키 값에 반드시 존재(참조 무결성) · NULL 허용 · 데이터 형식 동일
  • ⭐ 강조 — 테이블 2개: 생성·입력은 부모 → 자식, 삭제는 자식 → 부모
  • ⭐ 강조 — 논리적 독립성: 개념 스키마가 변해도 외부 스키마 영향 없음 / 물리적 독립성: 내부 스키마가 변해도 개념·외부 영향 없음
  • ⚠️ 정정 — 필기의 "차수 = 행 수 / 카디널리티 = 열 수"는 반대입니다

3주차 — DBMS · 데이터언어 · 기본키 (3주차 자세히)

  • ⭐ 강조 — 파일시스템 단점: 데이터 중복성 · 종속성 / DBMS 장점: 중복 최소화 · 데이터 독립성 / DBMS 단점: 비용 · 교육
  • ⭐ 강조 — DB 특성 4가지: 실시간 접근 · 계속 변화 · 동시 공유 · 내용으로 참조
  • ⭐ 강조 — 구성요소: 데이터 · 하드웨어 · DBMS · 사용자 (+데이터언어) / 사용자 3종: DBA · 응용프로그래머 · 일반사용자
  • ⭐ 강조 — DDL CREATE ALTER DROP(DBA) · DML INSERT SELECT UPDATE DELETE(일반사용자) · DCL GRANT REVOKE(DBA)
  • ⭐ 강조 — 기본키 = 각 투플을 유일하게 구별 · 중복 불가 · 필수 입력 / 복합키 예: 수강 = {학번, 과목번호}
  • 32p 기본키 찾기: 인사기록 = 사원번호 / 가족관계 = {사원번호, 이름} / 거래처 = {사원명, 거래처}
  • Workbench: 한 줄 Ctrl+Enter / 여러 줄 Ctrl+Shift+Enter
