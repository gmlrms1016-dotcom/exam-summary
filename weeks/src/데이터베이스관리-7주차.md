> 🔥 **시험 (✍️ 필기)** — “**오늘 나오는 것은 시험에서 10%가 나온다**” · **ALTER ADD (시험에 나옴)** — “**추가하는 게 시험문제임**” · 강의자료 **8 · 9쪽(Quiz 7-3) = 시험에 나오는 페이지** · DDL · DML · DCL **약어도 시험에 나옴** · DML 은 **시험의 70%** (직접 쓰는 문법이 나올 수 있음) · **GRANT · REVOKE 는 중간고사에 안 나옴**

> 📚 **중간고사 범위 (✍️)** — 교재 **1 · 2 · 3장(중요) · 5 · 6장** · 수업은 **2주차 ~ 7주차** · **중간고사는 객관식이 없음** → SQL 을 직접 쓰고 빈칸을 채우는 연습이 중요해요.

## 1. 🔥 데이터베이스 언어(SQL) 3가지 — 약어도 시험 ✍️
| 종류 | 약어 (✍️ 시험) | 명령 | ✍️ 필기 |
|---|---|---|---|
| 데이터 **정의어** | **DDL** (Data Definition Language) | `CREATE` · `DROP` · `ALTER` | ALTER **10%** 나옴 |
| 데이터 **조작어** | **DML** (Data Manipulation Language) | `SELECT` · `INSERT` · `UPDATE` · `DELETE` | 시험에 **70%** · 직접 쓰는 문법이 나올 수 있음 |
| 데이터 **제어어** | **DCL** (Data Control Language) | `GRANT` · `REVOKE` | 중간고사엔 안 나옴 |

> 📌 DDL = 테이블 **구조(틀)** 를 만들고 · 바꾸고 · 없앰 / DML = 테이블 안의 **데이터(행)** 를 조회 · 입력 · 수정 · 삭제 / DCL = 사용자 **권한**을 주고 · 뺏음

## 2. 데이터베이스 사용자 ✍️
| 사용자 | 하는 일 |
|---|---|
| 1. **데이터베이스 관리자 (DBA)** | ✍️ **root** — 데이터베이스 전체를 만들고 관리 · 사용자 권한 관리 (GRANT · REVOKE) |
| 2. **응용 프로그래머** | 데이터베이스를 쓰는 프로그램(앱)을 만드는 사람 |
| 3. **일반 사용자 (최종 사용자)** | 만들어진 프로그램으로 데이터를 조회 · 입력하는 사람 |

## 3. 🔥 [실습 7-2] ALTER — 필드 추가 · 수정 · 삭제 (6쪽)
> **ALTER** = 테이블의 **구조를 변경** (필드 추가 / 수정 / 삭제) — 강의자료 6쪽 · 문제: 1) budget 필드를 추가하라(int) 2) projname 필드의 데이터형식을 수정하라(varchar) 3) budget 필드를 삭제하라

### ① 🔥 필드 추가 — ADD (✍️ “추가하는 게 시험문제임”)
```sql
-- [실습 7-2] project 테이블 만들기 (수업 코드)
CREATE TABLE project (                          -- project 테이블 만들기 시작
     projno           int	      NOT NULL ,     -- 프로젝트 번호 — 정수 · 필수
     projname       char(20) ,                  -- 프로젝트 이름 — 고정 20자 문자
     period           int                       -- 기간 — 정수
);                                              -- CREATE TABLE 끝 (기본키 없음)
INSERT INTO project VALUES(111,'작전중',2);      -- 111 · 작전중 · 2
INSERT INTO project VALUES(222,'특공대',3);      -- 222 · 특공대 · 3
INSERT INTO project VALUES(444,'다모여',1);      -- 444 · 다모여 · 1
INSERT INTO project VALUES(333,'유레카',2);      -- 333 · 유레카 · 2

-- 1) budget 필드를 추가하라 : 데이터형식 int   ← ✍️ "추가하는 게 시험문제임"
ALTER TABLE project                             -- project 테이블의 구조를 바꾼다
ADD budget int;                                 -- budget(int) 열을 맨 끝에 추가 → 기존 4행의 budget 은 값이 없어서 NULL
DESC project;                                   -- 구조 확인 (MySQL) → projno · projname · period · budget 4개 필드
SELECT * FROM project;                          -- 4행 × 4열 — budget 칸은 전부 NULL
```
`SELECT * FROM project;` 의 결과 — budget 은 값을 넣은 적이 없어서 **NULL**

| projno | projname | period | budget |
|---|---|---|---|
| 111 | 작전중 | 2 | NULL |
| 222 | 특공대 | 3 | NULL |
| 444 | 다모여 | 1 | NULL |
| 333 | 유레카 | 2 | NULL |

### ② 필드 수정 — MODIFY (MySQL · Oracle)
```sql
-- 2) projname 필드의 데이터형식을 수정하라 : varchar
ALTER TABLE project                             -- project 테이블의 구조를 바꾼다
MODIFY projname varchar(20);                    -- projname 의 자료형 char(20) → varchar(20) (데이터는 그대로)
DESC project;                                   -- projname 의 Type 이 varchar(20) 으로 바뀐 것 확인
```
> ✍️ **필기** — “이건 **MySQL · Oracle** 에서 돌아가고 **MS-SQL 은 다른 문법**이다” (🤖 MS-SQL 은 `ALTER TABLE project ALTER COLUMN projname varchar(20);`) · 사이트 채점기(SQLite)는 MODIFY 를 지원하지 않아서 결과 표 없이 문법만 실었어요.

### ③ 필드 삭제 — DROP COLUMN
```sql
-- 3) budget 필드를 삭제하라 (위에 이어서)
CREATE TABLE project (                          -- 같은 project 테이블
     projno           int	      NOT NULL ,     -- 프로젝트 번호
     projname       char(20) ,                  -- 프로젝트 이름
     period           int                       -- 기간
);                                              -- CREATE TABLE 끝
INSERT INTO project VALUES(111,'작전중',2);      -- 데이터 4행
INSERT INTO project VALUES(222,'특공대',3);      -- 〃
INSERT INTO project VALUES(444,'다모여',1);      -- 〃
INSERT INTO project VALUES(333,'유레카',2);      -- 〃
ALTER TABLE project ADD budget int;             -- 1) budget 추가 → 열 4개
ALTER TABLE project                             -- 구조를 다시 바꾼다
DROP COLUMN budget;                             -- budget 열을 통째로 삭제 → 그 열의 값도 같이 사라짐
SELECT * FROM project;                          -- 처음처럼 projno · projname · period 3열
```
`SELECT * FROM project;` 의 결과 — budget 열이 없어짐

| projno | projname | period |
|---|---|---|
| 111 | 작전중 | 2 |
| 222 | 특공대 | 3 |
| 444 | 다모여 | 1 |
| 333 | 유레카 | 2 |

| 할 일 | 문법 | 예 |
|---|---|---|
| 필드 **추가** | `ALTER TABLE 테이블 ADD 필드 자료형;` | `ALTER TABLE project ADD budget int;` |
| 필드 **수정** | `ALTER TABLE 테이블 MODIFY 필드 자료형;` | `ALTER TABLE project MODIFY projname varchar(20);` |
| 필드 **삭제** | `ALTER TABLE 테이블 DROP COLUMN 필드;` | `ALTER TABLE project DROP COLUMN budget;` |

> ⚠️ **정정 (내 필기)** — 첫 필기의 `ADD budget char(20)` → 문제는 **int** · `MODIFY budget int` / 실습 코드의 `MODIFY budget varchar(20)` → 문제 2번은 **projname** 을 varchar 로 · 첫 필기의 `DROP COLUMN budget;` 앞에 **`ALTER TABLE project`** 가 빠졌어요 (ALTER 는 세 가지 모두 `ALTER TABLE 테이블명` 으로 시작). ALTER(DDL)는 **구조**를, UPDATE(DML)는 **값**을 바꿔요.

## 4. 🔥 [Quiz 7-3] 테이블 2개 — dept · dmember (8 · 9쪽 = 시험에 나오는 페이지)
### 8쪽 — 기본키 · 외래키 주의사항 · 테이블명세서
| 8쪽 질문 | 답 | 까닭 |
|---|---|---|
| 1) 테이블 **생성** 순서는? | **dept → dmember** (부모 → 자식) | 자식을 먼저 만들면 참조할 부모가 없음 → Error **1824** |
| 2) 테이블 **삭제** 순서는? | **dmember → dept** (자식 → 부모) | 부모를 먼저 지우면 자식이 참조 중 → Error **3730** |
| 3) 데이터 **입력** 순서는? | **dept → dmember** (부모 → 자식) | 부모에 없는 학과 번호를 넣으면 → Error **1452** |

| 테이블명세서 ? 칸 | 답 |
|---|---|
| dmember.dept_id 의 **데이터 형식** | **char(3)** — 참조하는 `dept.dept_id` 와 **같은 자료형** (다르면 Error 3780 · 4주차 필기 “FOREIGN KEY 는 참조하는 열과 데이터 형식이 같아야”) |
| **FK 테이블명** | **dept** |
| **FK 열 이름** | **dept_id** |

### 9쪽 — 빈칸 1) ~ 6)
| 빈칸 | 답 |
|---|---|
| 1) `DROP TABLE if exists ( 1 );` | **dmember** (자식 먼저) |
| 2) `DROP TABLE if exists ( 2 );` | **dept** |
| 3) `( 3 ) TABLE dept (` | **CREATE** |
| 4) `( 4 ) KEY(dept_id)` | **PRIMARY** |
| (번호 없음) `(   ) TABLE dmember (` | **CREATE** |
| 5) `dept_id ( 5 ) ,` | **char(3)** |
| (번호 없음) `(   ) KEY(name)` | **PRIMARY** |
| 6) `CONSTRAINT fk_dmember_dept ( 6 )` | **FOREIGN KEY(dept_id) REFERENCES dept(dept_id)** |

```sql
-- [Quiz 7-3] dept(부모) · dmember(자식) — 9쪽 빈칸을 채운 완성 코드
use testdb;                                     -- 수업은 testdb (강의자료는 studydb)

DROP TABLE if exists dmember;                   -- 1) 삭제는 자식 먼저 → dmember
DROP TABLE if exists dept;                      -- 2) 그다음 부모 → dept

CREATE TABLE dept (                             -- 3) CREATE — 생성은 부모 먼저
  dept_id   char(3)		    NOT NULL ,           -- 학과 번호 — 문자 3자리 · 필수
  name      varchar(20) ,                       -- 학과 이름 — 최대 20자
  PRIMARY KEY(dept_id)                          -- 4) PRIMARY — dept_id 가 기본키
);                                              -- dept 끝

CREATE TABLE dmember (                          -- (빈칸) CREATE — 자식 테이블
  name      varchar(10)             NOT NULL ,  -- 이름 — 최대 10자 · 필수
  dept_id   char(3) ,                           -- 5) char(3) — 참조하는 dept.dept_id 와 같은 자료형
  PRIMARY KEY(name)    ,                        -- (빈칸) PRIMARY — name 이 기본키
  CONSTRAINT fk_dmember_dept FOREIGN KEY(dept_id) REFERENCES dept(dept_id)   -- 6) 외래키: dept_id 는 dept(dept_id) 에 있는 값만
);                                              -- dmember 끝

INSERT INTO dept VALUES('100', '컴퓨터공학과');   -- 입력도 부모 먼저 — 100 · 컴퓨터공학과
INSERT INTO dept VALUES('101', '산업공학과');     -- 101 · 산업공학과

insert into dmember values('김광식','100');       -- 100 은 dept 에 있음 → 성공
insert into dmember values('김현정','101');       -- 101 있음 → 성공
insert into dmember values('조영수','101');       -- 성공
insert into dmember values('윤희근','100');       -- ✍️ 본인 이름 1개 추가 (과제 요구)

select * from dept;                             -- 학과 2행
select * from dmember;                          -- 학생 4행

COMMIT;                                         -- 확정 (MySQL)
```
`select * from dept;`

| dept_id | name |
|---|---|
| 100 | 컴퓨터공학과 |
| 101 | 산업공학과 |

`select * from dmember;` — 실제 MySQL 8.4 결과 (외래키 dept_id 인덱스 순서로 나와요 · 행 순서는 채점하지 않아요)

| name | dept_id |
|---|---|
| 김광식 | 100 |
| 윤희근 | 100 |
| 김현정 | 101 |
| 조영수 | 101 |

> ⚠️ **정정 (내 필기)** — 필기의 `1)dept 2)dmember` → 삭제는 **자식 먼저**라 **1) dmember · 2) dept** (내 완성 코드도 dmember 를 먼저 지웠어요) · 필기의 `5)FOREIGN KEY REFERENCE dept(dept_id);` → **5) 는 dept_id 의 자료형 char(3)** 이고 외래키는 **6)** · 그리고 **REFERENCE<u>S</u>** (S 가 빠지면 문법 오류) · 강의자료는 데이터베이스 **studydb**, 수업은 **testdb** 에서 했어요.

### 이런 순서로 하면 오류 (채점기로 직접 확인)
| 잘못한 것 | 결과 |
|---|---|
| dmember 를 dept 보다 **먼저 CREATE** | ❌ Error **1824** Failed to open the referenced table 'dept' |
| dmember.dept_id 를 **int** 로 (부모는 char(3)) | ❌ Error **3780** … are incompatible (자료형이 달라요) |
| dept 를 dmember 보다 **먼저 DROP** | ❌ Error **3730** Cannot drop table 'dept' referenced by a foreign key constraint |
| `insert into dmember values('홍길동','999');` (999 학과 없음) | ❌ Error **1452** Cannot add or update a child row: a foreign key constraint fails |

## 5. [실습 7-1] GRANT · REVOKE — 사용자 권한 관리 (✍️ 중간고사엔 안 나옴)
> 원본 실습은 **학과** 테이블, 수업은 ✍️ **project 테이블**로 했어요 (사진 · 필기). 4 · 5쪽.
```sql
-- (root) 1. 데이터베이스 생성
CREATE DATABASE testdb                          -- root 가 쓸 데이터베이스
   default character set utf8mb4;               -- 한글 · 이모지까지 저장되는 문자 집합
CREATE DATABASE kimdb                           -- kim 사용자가 쓸 데이터베이스
   default character set utf8mb4;               -- 〃

-- (root) 2. 사용자 생성 — ✍️ 수업은 GUI(Workbench)로 kim 을 만들었음
CREATE USER 'kim'@'localhost' IDENTIFIED BY 'kim';         -- 4쪽: 아이디 kim · 비밀번호 kim (이 컴퓨터에서만 접속)
GRANT ALL ON kimdb.* TO 'kim'@'localhost' WITH GRANT OPTION;   -- 4쪽: kimdb 의 모든 권한 + 남에게 줄 수 있는 권한까지

-- (root) 4. 권한부여 — testdb.project 를 kim 이 조회 · 입력할 수 있게
GRANT SELECT, INSERT ON testdb.project TO 'kim'@'localhost';   -- ✍️ 사진에서는 'kim'@'127.0.0.1' (localhost 와 같은 뜻의 IP)

-- (kim) 접속해서 확인
use kimdb;                                      -- kim 의 데이터베이스로
select * from project;                          -- ✍️ error — kimdb 에는 project 가 없음
select * from testdb.project;                   -- ✍️ ok — 데이터베이스이름.테이블이름 으로 root 의 표를 조회 (SELECT 권한)
insert into testdb.project value(999,'가나다',10);   -- INSERT 권한이 있어서 성공 (MySQL 은 VALUE 도 VALUES 처럼 받아 줌)

-- (root) 권한취소 — INSERT 만 뺏기
REVOKE INSERT ON testdb.project FROM 'kim'@'localhost';    -- 이제 kim 은 조회만 가능 → 다시 insert 하면 권한 오류
```
> 📌 GRANT 는 **TO** 사용자, REVOKE 는 **FROM** 사용자 · `testdb.project` = 데이터베이스 **testdb** 의 테이블 **project** · 사이트 채점기는 데이터베이스 · 사용자가 하나뿐이라 GRANT · REVOKE 는 실행 결과 없이 실었어요.
