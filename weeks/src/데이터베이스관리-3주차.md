## 1. 파일시스템 vs DBMS
- ⭐ **강조** — DBMS = 데이터베이스를 관리하는 시스템 소프트웨어. 사용자·응용프로그램과 DB 사이의 인터페이스 역할
- 파일시스템 단점: ① 데이터 중복성 ② 데이터 종속성(프로그램 변경 시 데이터도 변경)
- ⭐ **강조** — DBMS 장점: ① 중복 최소화 ② 데이터 독립성
- ✍️ **필기** — DBMS 단점: 비용, 교육
- 대표 DBMS: MySQL, Oracle, MS SQL, DB2, MariaDB, CUBRID, PostgreSQL

## 2. 데이터베이스 개념 — 정의와 특성
- ⭐ **강조** — DB 정의 4가지: 공유(shared) · 통합(integrated) · 저장(stored) · 운영(operational)
- ⭐ **강조** — DB 특성 4가지: 실시간 접근 · 계속 변화 · 동시 공유 · 내용으로 참조
  - 한 조직의 여러 응용시스템이 데이터를 공유할 수 있도록 통합·저장한 운영 데이터의 집합체

## 3. 데이터베이스 시스템 구성요소 · 사용자
- ⭐ **강조** — 구성요소: 데이터(데이터베이스) · 하드웨어(HW) · DBMS · 사용자 · (데이터언어)
- ⭐ **강조** — 사용자 3종: 데이터베이스 관리자(DBA) · 응용프로그래머 · 일반사용자(end user)
- DBA = 슈퍼유저: DB를 구축하고 시스템을 자체적으로 운영·통제
  - DBA 역할: 구조 정의, 무결성 제약조건, 보안·접근권한, 백업·회복, 성능 감시·재구성

## 4. 데이터 언어 (SQL) ★핵심
- ⭐ **강조** — DDL(데이터 정의어): CREATE · ALTER · DROP [담당: DBA]
- ⭐ **강조** — DML(데이터 조작어): INSERT · SELECT · UPDATE · DELETE [담당: 일반사용자]
- ⭐ **강조** — DCL(데이터 제어어): GRANT · REVOKE (+DENY) [담당: DBA]

## 5. 키(Key) ★핵심
- ⭐ **강조** — 기본키(Primary Key): 각 투플을 유일하게 구별하는 하나 이상의 속성 집합 — 중복 불가 · 필수 입력
- 외래키(Foreign Key): 다른 테이블을 참조하는 키
- ⭐ **강조** — 복합키 예 — 수강 테이블 기본키 = {학번, 과목번호}
```sql
CREATE TABLE 수강(
  학번 char(5),
  과목번호 char(5),
  성적 int,
  PRIMARY KEY(학번, 과목번호)   -- 복합키
);
```
- ✍️ **필기** — [Quiz 32p 기본키 찾기 — 내 답] 인사기록: 사원번호 / 가족관계: {사원번호, 이름} / 거래처: {사원명, 거래처}

## 6. MySQL 실습 (제품 · customer)
```sql
USE testdb;
DROP TABLE if exists 제품;
CREATE TABLE 제품(
  제품번호 char(3) NOT NULL,
  제품명 varchar(20),
  재고량 int,
  단가 int,
  제조업체 varchar(20),
  PRIMARY KEY(제품번호)
);
INSERT INTO 제품 VALUES('P01','그냥만두',5000,4500,'대한식품');
-- 제품명, 재고량 검색
SELECT 제품명, 재고량 FROM 제품;
-- 제조업체가 '대한식품'인 제품명·단가·제조업체 검색
SELECT 제품명, 단가, 제조업체 FROM 제품 WHERE 제조업체='대한식품';
```
```sql
-- customer 테이블
CREATE TABLE customer(
  cno char(4) NOT NULL PRIMARY KEY,
  cname varchar(10) NOT NULL,
  city varchar(20),
  point int
);
insert into customer values('c101','홍길동','서울',500);
select * from customer;
```
