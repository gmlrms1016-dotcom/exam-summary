| 페이지 | 외울 내용 |
|---|---|
| **3p** | 정의 4: 공유 · 통합(중복 최소화) · 저장 · 운영 / 특징 4: 실시간 접근 · 계속 변화 · 동시 공유 · 내용 기반 참조 |
| **4p** | 파일시스템 단점: 중복성 · 종속성 ↔ DBMS 장점: 중복 최소화 · 독립성 증진 / DBMS 단점: 고비용 · 회복 기법 복잡 / 발전: 1세대 네트워크·계층 → 2세대 관계 → 3세대 객체지향·객체관계 → 4세대 NoSQL·NewSQL |
| **5p + 25p** | 외부 스키마 → 개념 스키마 → 내부 스키마 (ANSI/SPARC) |
| **7p** | 빈칸: `CREATE TABLE` · `NOT NULL` · `PRIMARY KEY(학과번호)` |
| **21p** | 빈칸: `int` · `varchar(50)` · `char(2)` · `NOT NULL` · `PRIMARY KEY(번호)` · `FOREIGN KEY(학과번호) REFERENCES 학과(학과번호)` |
| **24p** | 스키마 = 구조와 제약조건에 대한 명세 · 표기법 학생(학번, 이름, 학년, 성별) · 인스턴스 = 실제 저장된 값 |
| **32p** | 메타데이터 = 데이터에 관한 데이터 · 데이터 사전 = 시스템 카탈로그 · 데이터 디렉토리 |
| **34p** | 데이터 모델 3요소 = 구조 · 연산 · 제약조건 |
| **41p** | 차수 = 애트리뷰트(열) 수 · 카디널리티 = 투플(행) 수 · 도메인 = 값들의 집합 |
| **42p** | 신입생(학번, 주민등록번호, 이름, 주소, 학과명) · 차수 5 · 카디널리티 4 · 기본키 학번 |

- ⭐ **강조** — 외래키: 참조되는 기본키 값에 반드시 존재(**참조 무결성**) · **NULL 허용** · 데이터 형식 동일
- ⭐ **강조** — 테이블 2개: 생성·입력은 **부모 → 자식**, 삭제는 **자식 → 부모**
- ⭐ **강조** — 논리적 독립성: 개념 스키마가 변해도 외부 스키마 영향 없음 / 물리적 독립성: 내부 스키마가 변해도 개념·외부 영향 없음
- ⚠️ **정정** — 필기의 "차수 = 행 수 / 카디널리티 = 열 수"는 **반대**입니다

## 3주차 — DBMS · 데이터언어 · 기본키 ([3주차 자세히](데이터베이스관리-3주차.html))
- ⭐ **강조** — 파일시스템 단점: 데이터 **중복성 · 종속성** / DBMS 장점: **중복 최소화 · 데이터 독립성** / DBMS 단점: 비용 · 교육
- ⭐ **강조** — DB 특성 4가지: 실시간 접근 · 계속 변화 · 동시 공유 · **내용으로 참조**
- ⭐ **강조** — 구성요소: 데이터 · 하드웨어 · DBMS · 사용자 (+데이터언어) / 사용자 3종: DBA · 응용프로그래머 · 일반사용자
- ⭐ **강조** — DDL `CREATE ALTER DROP`(DBA) · DML `INSERT SELECT UPDATE DELETE`(일반사용자) · DCL `GRANT REVOKE`(DBA)
- ⭐ **강조** — 기본키 = 각 투플을 유일하게 구별 · 중복 불가 · 필수 입력 / 복합키 예: 수강 = {학번, 과목번호}
- 32p 기본키 찾기: 인사기록 = 사원번호 / 가족관계 = {사원번호, 이름} / 거래처 = {사원명, 거래처}
- Workbench: 한 줄 Ctrl+Enter / 여러 줄 Ctrl+Shift+Enter

## 1~2주차 — DB 개념 · MySQL 기본 실습
- ⭐ **강조** — 데이터베이스 = 한 조직의 여러 응용시스템이 공유할 수 있도록 **통합 · 저장**한 **운영 데이터**의 집합체
- ⭐ **강조** — 실습 4단계: 데이터베이스(스키마) 생성 → 테이블 생성 → 데이터 입력 → 데이터 조회
- 자료형: 1byte = 8bit · 문자형 1byte · 정수형 int 4byte · `char(n)` 고정 길이(주민번호) / `varchar(n)` 가변 길이(주소)
