# 마운트 · 링크 · 권한 · 사용자관리

> 🐧 **운영체제실습 3주차** — 마운트 / inode·링크 / 접근 권한 / 사용자·그룹 관리. 실습 터미널 기록을 주제별로 재정리했습니다. (명령·출력 원본 로그 전체는 노션 페이지 토글에 보존)

## 1. 마운트(mount)와 저장장치
> 💡 **mount** = 저장장치(디스크·DVD·USB)를 디렉터리 트리의 특정 위치에 연결하는 것. 연결을 끊을 때는 **umount**. 리눅스는 마운트해야 장치에 접근할 수 있습니다.

### 1-1. 마운트 목록 확인
```bash
mount          # 현재 마운트된 모든 파일시스템 목록
```
| 출력 | 의미 |
|---|---|
| /dev/sda2 on / type xfs | 주 디스크가 루트(/)에 xfs로 마운트 |
| devtmpfs on /dev | 장치 파일 시스템 |
| tmpfs on /dev/shm | 메모리 기반 임시 파일시스템 |
| proc on /proc | 프로세스 정보 가상 파일시스템 |
| sysfs on /sys | 커널·장치 정보 |
| cgroup2 on /sys/fs/cgroup | 자원 제어 그룹 |

### 1-2. DVD(CD) 마운트 후 비교
CD를 넣고 세팅하면 마운트 목록 **맨 아래에 한 줄이 추가**됩니다.
```bash
/dev/sr0 on /run/media/root/Rocky-10-0-x86_64-dvd type iso9660
      (ro,nosuid,nodev,relatime,nojoliet,check=s,map=n,blocksize=2048,
       uid=0,gid=0,dmode=500,fmode=400,iocharset=utf8,uhelper=udisks2)
```
> 🔎 **포인트** — `/dev/sr0`(광학드라이브)가 `/run/media/root/...` 에 **iso9660** 형식으로 마운트됨. `ro` 는 읽기 전용.

### 1-3. 마운트된 DVD 내용 확인
```bash
root@localhost:~# cd /run/media/root/Rocky-10-0-x86_64-dvd/
root@localhost:/run/media/root/Rocky-10-0-x86_64-dvd# ls -l
합계 25
drwxr-xr-x 1 root root 2048 2025년  6월  1일 AppStream
drwxr-xr-x 1 root root 2048 2025년  6월  1일 BaseOS
drwxr-xr-x 1 root root 2048 2025년  6월  1일 EFI
-r--r--r-- 1 root root 2204 2025년  6월  1일 LICENSE
drwxr-xr-x 1 root root 2048 2025년  6월  1일 images
-r--r--r-- 1 root root   89 2025년  6월  1일 media.repo

root@localhost:~# umount /dev/cdrom     # 사용 후 마운트 해제
```
> 💾 **리눅스 USB 포맷 호환** — **FAT**(File Allocation Table) : **O** (인식 가능) · **NTFS** : **X** (기본 상태에서는 인식 불가)

## 2. inode와 링크
> 💡 **inode** = 파일의 정보(크기·소유자·권한·데이터 위치)를 담은 고유 번호표. 파일 1개당 1개. **이름이 달라도 inode가 같으면 같은 파일**입니다. → `ls -i` 로 확인

### 2-1. 하드 링크 vs 심볼릭 링크
| 구분 | 명령 | inode | 원본 삭제 시 |
|---|---|---|---|
| **하드 링크** | `ln 원본 링크명` | 원본과 **동일** | **내용 유지** (파일 살아있음) |
| **심볼릭 링크** | `ln -s 원본 링크명` | **새 번호** | **깨짐** (경로만 가리키므로) |

실습에서 확인한 inode 번호:
| 파일 | inode | 설명 |
|---|---|---|
| ex_data | 202726865 | 원본 |
| ex_data.ln | **202726865** | 하드 링크 — 원본과 같음 |
| ex_data.sl | 202727542 | 심볼릭 링크 — 다름 |

### 2-2. 실습 흐름
```bash
cp /etc/hosts ex_data        # 실습용 원본 생성
ls -i                        # inode 번호 확인
ln    ex_data ex_data.ln     # 하드 링크
ln -s ex_data ex_data.sl     # 심볼릭 링크
rm ex_data                   # 원본 삭제 → 링크 상태 비교
touch ex_data                # 원본 재생성 → 심볼릭 링크 복구
```
> ✅ **핵심 결과** — 원본(`ex_data`)을 지우면 `ex_data.ln`(하드) 은 **384바이트 그대로 살아있고**, `ex_data.sl`(심볼릭) 은 `ex_data` 를 가리키지만 **대상이 없어 깨진 링크**가 됩니다. 다시 `touch ex_data` 로 만들면 심볼릭 링크가 **되살아납니다**.

## 3. 파일·디렉터리 기본 작업
```bash
mkdir chap_05        # 실습 디렉터리 생성
cd chap_05           # 이동
pwd                  # /root/chap_05  현재 위치 확인
nano                 # 편집기 (Ctrl+X → Y → Enter 로 저장)
vi                   # 편집기
cp /etc/hosts centos_cp.txt    # 실습용 파일 복사
ls -l                # 상세 목록
```
> ⭐ **[내가 표시한 중요]** `ls -l` 결과 `-rw-r--r-- 1 root root 384 9월 10일 15:06 centos_cp.txt` → 권한 변경 실습의 **출발점**이 되는 기본 권한 `rw-r--r--` (644)

## 4. 접근 권한 (chmod) ★핵심
### 4-1. 기호 모드 (심볼릭 모드)
> 🔑 **대상** — `u` 소유자 · `g` 그룹 · `o` 기타 사용자 · `a` 전체 사용자 / **연산** — `+` 권한 추가 · `-` 권한 제거 · `=` 권한 지정 / **권한** — `r` 읽기 · `w` 쓰기 · `x` 실행

```bash
chmod u+w centos_cp.txt        # 소유자에게 쓰기 추가
chmod u-w centos_cp.txt        # 소유자 쓰기 제거 → -r--r--r--
chmod u+x,go+w story.txt       # 여러 대상을 쉼표로 동시 지정
chmod u-x,go-w story.txt       # 원상복구
```
> ⭐ **[내가 표시한 중요]** 기본 권한 `rw-r--r--` 에서 `d rwx rw- rw-` 로 변경했다가 다시 원상복구해서 `rw-r--r--` 로 바꾼다.

### 4-2. 8진수(숫자) 모드
|  | u (소유자) | g (그룹) | o (기타) |
|---|---|---|---|
| 권한 | 읽기(r) · 쓰기(w) · 실행(x) | 읽기(r) · 쓰기(w) · 실행(x) | 읽기(r) · 쓰기(w) · 실행(x) |
| 자릿값 | 400 + 200 + 100 | 40 + 20 + 10 | 4 + 2 + 1 |

> 🧮 각 자리는 **r=4, w=2, x=1** 을 더한 값 — `755` = rwx(4+2+1) r-x(4+1) r-x(4+1) · `644` = rw- r-- r-- · `775` = rwx rwx r-x

```bash
chmod 775 centos_cp.txt        # -rwxrwxr-x 로 변경
chmod 775 yesterday.txt
rm -i yesterday.txt            # -i : 삭제 전 하나씩 확인(대화식)
```

## 5. 사용자와 그룹 관리 ★핵심
### 5-1. 명령어
| 명령 | 설명 |
|---|---|
| `useradd user100` | 사용자 생성 |
| `useradd -g YHG user100` | **그룹을 지정**해서 사용자 생성 |
| `userdel -r user100` | 사용자 삭제 (`-r` 은 홈 디렉터리까지) |
| `groupadd YHG` | 그룹 생성 |
| `passwd user100` | 비밀번호 설정·변경 |
| `head` / `tail` / `tail -5` | 파일 앞·뒤 내용 확인 (`-5` 는 5줄) |

### 5-2. 관리 파일 3종
| 파일 | 내용 | 필드 구조 |
|---|---|---|
| `/etc/passwd` | 사용자 계정 정보 | 이름 : x : **UID** : **GID** : 설명 : 홈디렉터리 : 셸 |
| `/etc/group` | 그룹 정보 | 그룹명 : x : **GID** : 소속 사용자 |
| `/etc/shadow` | 암호화된 비밀번호 | 이름 : **암호화 해시** : 최종변경일 : … |

> 🔎 **실습에서 확인한 것** — `groupadd YHG` 로 만든 그룹(GID **1001**)에 `useradd -g YHG` 로 user100·user200을 넣으니 두 계정의 **GID가 똑같이 1001**로 찍힘 — `user100:x:1001:1001:...` / `user200:x:1002:1001:...` → **UID는 다르지만 GID는 같다** = 같은 그룹 소속

> ⚠️ `passwd` 실행 시 **8자 미만이면 경고**가 뜨고, 두 번 입력이 다르면 `죄송하지만, 비밀번호가 일치하지 않습니다` 오류가 납니다.

> 🔒 **/etc/shadow 필드 읽는 법** — `사용자명 : 암호화된비밀번호 : 최종변경일 : 최소 : 최대 : 경고 : 비활성 : 만료`. 해시의 `$y$` 는 **yescrypt** 알고리즘, `$j9T$` 는 파라미터, 그 다음이 **salt$해시**입니다. `!` 또는 `*` 로 시작하면(dnsmasq, tcpdump 등) **로그인 불가 계정**이라는 뜻입니다.
