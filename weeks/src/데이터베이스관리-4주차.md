## 2. 기본키 · 외래키 ★시험 (10p · 11p · 39p · 40p)
- ⭐ **강조** — 기본키(PRIMARY KEY): 각 투플을 유일하게 구별할 수 있는 하나 이상의 속성 집합 · **중복 불가 · 필수 입력(NOT NULL)**
- ⭐ **강조** — 외래키(FOREIGN KEY): 한 릴레이션의 **기본키를 참조**하는 키 · 참조되는 릴레이션의 기본키 값에 **반드시 존재**해야 한다 → **참조 무결성 제약조건**
- 외래키는 **널(NULL) 값 입력을 허용**한다
- ⭐ **강조** — (시험문제 · 필기) 외래키와 참조되는 기본키는 **데이터 형식이 같아야 한다** (학생.학과번호 int ↔ 학과.학과번호 int)
- 부모 테이블 = 기본키를 주는 쪽(학과) / 자식 테이블 = 외래키로 참조하는 쪽(학생)

## 3. 테이블 2개일 때 순서 ★시험단골 (12p · 19p · 44p)
- **테이블 생성 순서**: 부모(학과) → 자식(학생) — 참조할 기본키가 먼저 있어야 한다
- **데이터 입력 순서**: 부모(학과) → 자식(학생) — 학과번호가 없으면 학생 입력이 거부된다
- **테이블 삭제 순서**: 자식(학생) → 부모(학과) — 자식이 참조 중이면 부모를 지울 수 없다

## 4. 스키마와 인스턴스 (24p) ★시험
- ⭐ **강조** — 스키마(Schema): 데이터베이스를 구성하는 **구조와 제약조건**에 대한 명세를 기술한 것
- 데이터 구조(정적): 학생(학번, 이름, 학년, 성별)
- 제약 조건(동적): 학번 = 문자 4자리 / 이름 = 문자 최대 10자리 / 학년 = 정수 1~4 / 성별 = '남' 또는 '여'
- 인스턴스: 데이터베이스에 실제 저장된 값
- ⭐ **강조** — (시험문제) 스키마 표기법은 **테이블명(속성1, 속성2, …)** 으로 쓰고 **기본키에 밑줄**을 긋는다 — 예) 학생(번호, 이름, 학년, 분반, 학과번호)

## 5. 3단계 스키마 구조 · 데이터 독립성 (5p · 25~27p) ★시험
- **외부 스키마**: 사용자·응용프로그램이 보는 부분 구조 = 뷰(view) · 여러 개
- **개념 스키마**: 조직 전체의 논리적 구조(테이블 전체) · 데이터베이스마다 1개
- **내부 스키마**: 디스크에 실제로 저장되는 구조(저장 방식 · 인덱스)
- ⭐ **강조** — 논리적 데이터 독립성: **개념 스키마가 변해도 외부 스키마는 영향받지 않는다**
- ⭐ **강조** — 물리적 데이터 독립성: **내부 스키마가 변해도 개념·외부 스키마는 영향받지 않는다**
- 단계를 이어주는 것 = 사상(mapping): 외부/개념 사상, 개념/내부 사상 · 위로 갈수록 추상화 수준이 높다

## 6. 데이터 사전 · 메타데이터 (32p) ★시험
- ⭐ **강조** — 메타데이터(metadata): **데이터에 관한 데이터** (테이블 이름, 열 이름, 자료형, 제약조건)
- 데이터 사전(data dictionary) = **시스템 카탈로그** — 메타데이터를 모아 둔 곳
- 데이터 디렉토리(data directory): 데이터 사전의 데이터가 어디에 있는지 알려주는 정보
- 저장 위치: 사용자 데이터베이스(내가 만든 테이블) + 시스템 데이터베이스(데이터 사전 · 데이터 디렉토리)

## 7. 데이터 모델 (29~31p · 34p) ★시험
- ⭐ **강조** — 데이터 모델 3가지 요소: **① 구조(structure) ② 연산(operation) ③ 제약조건(constraint)**
- 데이터 모델 = 데이터베이스 구조를 명세하기 위한 개념 · 종류에 따라 저장 구조가 달라진다
- 종류: 계층형(HDBMS) · 네트워크형(NDBMS) · **관계형(RDBMS)** · 객체지향형(OODBMS) · 객체관계형(ORDBMS)
- 관계형 데이터베이스(37~38p): 연관된 데이터를 한 테이블에 다 넣지 않고 **여러 테이블로 나눈 뒤 관계(외래키)로 연결**해 조직화

## 8. 관계형 용어 (41p) ★필수암기 + 필기 정정
- 릴레이션(Relation) = 테이블: 행과 열로 구성된 2차원 테이블
- 투플(tuple) = 행(row) = 레코드: 특정 인스턴스에 관한 사실(값)들의 모임
- 애트리뷰트(attribute) = 열(column) = 필드 = 속성
- 도메인(Domain): 한 애트리뷰트에 나타날 수 있는 값들의 집합
- ⭐ **강조** — **차수(Degree) = 애트리뷰트(열)의 수**
- ⭐ **강조** — **카디널리티(Cardinality) = 투플(행)의 수**
- ⚠️ **정정** — 내 필기에는 "차수 = 행의 수 / 카디널리티 = 열의 수"로 적혀 있는데 **서로 바뀐 것**입니다. 41p 기준으로 위가 맞습니다. (표의 맨 윗줄 제목 칸 수 = 차수, 아래 쌓인 줄 수 = 카디널리티)

## 9. 실습 4-1 · 4-2 — 학과 · 학생 테이블 (14p~22p)
실습 순서: ① 데이터베이스(스키마) 생성 → ② 테이블 생성 → ③ 데이터 입력 → ④ 데이터 조회
```sql
-- 1단계: 스키마(데이터베이스) 생성
CREATE SCHEMA `studydb` DEFAULT CHARACTER SET utf8mb4;
USE studydb;
-- 데이터베이스 삭제
DROP DATABASE studydb;
```
내가 실습한 SQL (강의요약 4주차.txt):
```sql
use testdb;

DROP TABLE IF EXISTS 학생;     -- 자식부터 삭제
DROP TABLE IF EXISTS 학과;

CREATE TABLE 학과(
    학과번호  int          NOT NULL,
    학과명    varchar(30),
    PRIMARY KEY(학과번호)
);
INSERT INTO 학과 VALUES(1,'컴퓨터소프트웨어공학과');
INSERT INTO 학과 VALUES(2,'컴퓨터정보공학과');
INSERT INTO 학과 VALUES(3,'인공지능소프트웨어학과');

CREATE TABLE 학생(
    번호      int,
    이름      varchar(30),
    학년      int,
    분반      char(2),
    학과번호  int,
    PRIMARY KEY(번호),
    FOREIGN KEY(학과번호) REFERENCES 학과(학과번호)
);
INSERT INTO 학생 VALUES(1,'한지혜',1,'YB',1);
INSERT INTO 학생 VALUES(2,'이정우',1,'YA',1);
INSERT INTO 학생 VALUES(3,'오지영',2,'J1',2);
INSERT INTO 학생 VALUES(4,'강재미',1,'YB',1);
INSERT INTO 학생 VALUES(5,'박철호',2,'J1',2);
SELECT * FROM 학생;
SELECT * FROM 학과;
```
- ⚠️ 강의자료와 다른 점(시험은 강의자료 기준): 데이터베이스 testdb ↔ 강의노트 studydb / varchar(30) ↔ 명세서 학과명 varchar(50) · 이름 varchar(12) / '인공지능소프트웨어학과' ↔ 강의자료 '인공지능소프트웨어과'
- 테이블 명세서(16p · 20p) 항목: 테이블명 · 열 이름 · 데이터 형식 · NULL 유무 · 기본키 · 외래키 · FK 테이블명 · FK 열 이름

## 10. [Quiz] 42p 신입생 — 정답
신입생 테이블: 학번 / 주민등록번호 / 이름 / 주소 / 학과명, 데이터 4건(김광식 · 김정현 · 김현정 · 김현정)
- 1) 스키마 표기법: **신입생(학번, 주민등록번호, 이름, 주소, 학과명)** — 기본키 학번에 밑줄
- 2) 차수(degree) = **5** (열 5개)
- 3) 카디널리티(cardinality) = **4** (행 4개)
- 4) 기본키 = **학번** (이름은 동명이인 '김현정'이 있어 부적합)

이 표로 용어 같이 외우기:
- 표 전체 = **릴레이션**(Relation) = 테이블
- 가로 한 줄(1292001, 김광식, 서울 …) = **투플**(Tuple) = 행(row) = **레코드** → 4개이므로 카디널리티 4
- 세로 한 칸(이름 칸 전체) = **애트리뷰트**(Attribute) = 열(column) = 필드 = **속성** → 5개이므로 차수 5
- 학과명에 올 수 있는 값들 {컴퓨터공학과, 산업공학과} = **도메인**(Domain)
- 표에 실제로 들어 있는 값 = **인스턴스**
- 학번 = **기본키**(Primary Key) — 중복 불가 · 필수 입력
