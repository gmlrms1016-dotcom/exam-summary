## 1. 🔥 [Quiz 6] omember · group_ex — 외부조인 실행결과 (1교시 · 엑셀)
> 실습 엑셀 quiz-6-outer01 “실행결과는 무엇인가?” — 1) 내부조인 2) 왼쪽 외부조인 3) 오른쪽 외부조인 4) 완전 외부조인 (강의자료 4쪽 (복습) [Quiz11-6]) · ✍️ “**엑셀에서 문제 푸는거 시험에 나옴**” · ✍️ 내 답 = 엑셀 quiz-6-outer01-답안 시트

| omember.id | groupid | | group_ex.groupid | position |
|---|---|---|---|---|
| 100 | A | | A | 서울 |
| 101 | B | | B | 대구 |
| 102 | A | | C | 광주 |
| 103 | F | | D | 부산 |
| | | | E | 대전 |

```sql
-- 1) 동등조인 (엑셀: 내부조인)                              ✍️ 내 답
SELECT *                                                     -- ③ 4열 모두 (id · groupid · groupid · position)
FROM omember INNER JOIN group_ex                             -- ① omember 4행과 group_ex 5행의 짝 맞추기
ON omember.groupid=group_ex.groupid;                         -- ② groupid 가 같은 짝만 → A 2명 · B 1명 = 3행
```
| id | groupid | groupid | position |
|---|---|---|---|
| 100 | A | A | 서울 |
| 101 | B | B | 대구 |
| 102 | A | A | 서울 |

```sql
-- 2) 왼쪽외부조인
SELECT *
FROM omember LEFT OUTER JOIN group_ex                        -- ① 왼쪽(omember) 4행은 짝이 없어도 모두
ON omember.groupid=group_ex.groupid;                         -- ② 103 F 는 group_ex 에 F 가 없음 → 오른쪽 칸 NULL → 4행
```
| id | groupid | groupid | position |
|---|---|---|---|
| 100 | A | A | 서울 |
| 101 | B | B | 대구 |
| 102 | A | A | 서울 |
| 103 | F | NULL | NULL |

```sql
-- 3) 오른쪽외부조인
SELECT *
FROM omember RIGHT OUTER JOIN group_ex                       -- ① 오른쪽(group_ex) 5행은 짝이 없어도 모두
ON omember.groupid=group_ex.groupid;                         -- ② A 는 100 · 102 와 짝 (2행) · C · D · E 는 짝 없음 → 왼쪽 칸 NULL → 6행
```
| id | groupid | groupid | position |
|---|---|---|---|
| 100 | A | A | 서울 |
| 101 | B | B | 대구 |
| NULL | NULL | C | 광주 |
| NULL | NULL | D | 부산 |
| NULL | NULL | E | 대전 |
| 102 | A | A | 서울 |

```sql
-- 4) 완전외부조인 — MySQL 은 FULL OUTER JOIN 이 없어서 왼쪽 UNION 오른쪽
SELECT *
FROM omember LEFT OUTER JOIN group_ex                        -- ① 왼쪽 외부조인 4행
ON omember.groupid=group_ex.groupid
UNION                                                        -- ③ 합치고 겹치는 3행(100 · 101 · 102)은 한 번만
SELECT *
FROM omember RIGHT OUTER JOIN group_ex                       -- ② 오른쪽 외부조인 6행
ON omember.groupid=group_ex.groupid;                         -- → 4 + 6 − 3 = 7행
```
| id | groupid | groupid | position |
|---|---|---|---|
| 100 | A | A | 서울 |
| 101 | B | B | 대구 |
| 102 | A | A | 서울 |
| 103 | F | NULL | NULL |
| NULL | NULL | C | 광주 |
| NULL | NULL | D | 부산 |
| NULL | NULL | E | 대전 |

> ✍️ 내 답 4개 ✅ · 표는 **✍️ 내 엑셀 답** 순서 (MySQL 8.0.46 결과와 행 내용 · 개수가 같아요) · 🤖 A 그룹은 omember 에 **2명**(100 · 102) 이라 서울이 2번 나와요 · 🤖 `UNION ALL` 로 합치면 겹치는 3행이 두 번 나와 **10행** (MySQL 로 확인).

> 🤖 **행 순서** — ORDER BY 가 없으면 MySQL 이 정해요. 같은 8.0.46 인데도 이 맥은 1) 을 102 · 100 · 101 순서로, 3) 을 102 · 100 · 101 · C · D · E 순서로 보여 줬어요 (내 엑셀 답과 순서가 다름) → 시험 답은 **행의 내용 · 개수**를 정확히.

## 3. 🔥 [실습 1-1] 합집합 UNION · UNION ALL — 정회원 · 준회원 (2교시)
✍️ **필기** — “시험에는 합집합 · 교집합 · 차집합 중에서 **합집합 하나만** 출제함” · 수업요약 [실습 1-1-1] “UNION 와 UNION ALL 차이점”

| 정회원.번호 | 이름 | | 준회원.번호 | 이름 |
|---|---|---|---|---|
| 1 | 홍길동 | | 1 | 홍길동 |
| 2 | 임꺽정 | | 3 | 박찬호 |
| | | | 4 | 선동열 |

> 두 테이블 모두 (번호, 이름, 주민번호, 휴대폰번호, 이메일, 등록일) — 실습 SQL 주석 “집합연산 실습을 위해서 홍길동 동일한 데이터를 입력한다” → 홍길동은 정회원이면서 준회원.

```sql
-- 1) UNION 사용                                              ✍️ 내 답
select 번호,이름 from 정회원                                  -- ① 정회원 2행 (1 홍길동 · 2 임꺽정)
UNION                                                        -- ③ 합치고 중복(1 홍길동)은 한 번만 → 4행
select 번호,이름 from 준회원;                                 -- ② 준회원 3행 (1 홍길동 · 3 박찬호 · 4 선동열)
-- 2) UNION ALL 사용
select 번호,이름 from 정회원
UNION ALL                                                    -- 중복도 그대로 → 2 + 3 = 5행
select 번호,이름 from 준회원;
```
| 번호 | 이름 |
|---|---|
| 1 | 홍길동 |
| 2 | 임꺽정 |
| 3 | 박찬호 |
| 4 | 선동열 |

| 번호 | 이름 |
|---|---|
| 1 | 홍길동 |
| 2 | 임꺽정 |
| 1 | 홍길동 |
| 3 | 박찬호 |
| 4 | 선동열 |

| | UNION | UNION ALL |
|---|---|---|
| 중복 행 | **한 번만** (제거) | **그대로** (포함) |
| 정회원 2행 + 준회원 3행 | **4행** | **5행** |
| 관계대수 | 합집합 **∪** | 🤖 (릴레이션은 같은 투플이 없어서 ∪ 는 UNION 쪽) |

> ✍️ 내 답 ✅ — 학교 Workbench 캡처와 같아요 · 🤖 교집합 `INTERSECT` → 1 홍길동 · 차집합 (정회원 − 준회원) `EXCEPT` → 2 임꺽정 (강의자료 8쪽: 차집합 = MINUS (Oracle) · EXCEPT (MS SQL)) — **학교와 같은 MySQL 8.0.46 에서도 둘 다 돼요** (이 맥으로 확인) · 하지만 시험은 **합집합만**.

> 🤖 UNION 은 두 SELECT 의 **열 개수**가 같아야 해요 (다르면 ERROR 1222) · 결과 열 이름은 **첫 번째 SELECT** 것 · MySQL 은 자료형이 달라도 합쳐 버려요 (`select 이름 from 정회원 UNION select 번호 from 준회원` → 홍길동 · 임꺽정 · 1 · 3 · 4 — 실행해 봄) → 관계대수에서는 속성 개수 · 도메인이 같아야 **합병 가능**.

## 6. 🔥 [이론] 하위질의 — 서브질의 · 서브쿼리 · 부질의 (3교시)
✍️ **필기** — “[이론] 하위질의 : 서브질의, 서브쿼리, 부질의, subqury” · “시험에는 스칼라 · 인라인 · 하위질의 중에서 **하위질의 하나만** 출제함”

```sql
SELECT                                                       -- 바깥 질의
FROM
WHERE        (SELECT                                         -- 괄호 안 = 하위질의 (부질의)
              FROM
              WHERE              );                          -- ✍️ 수업 시간에 적은 틀
```

| 강의자료 20쪽 [요약] 중첩질의 | 괄호 위치 | 모양 | 시험 |
|---|---|---|---|
| 1. 스칼라 질의 | **SELECT** 절 안 | `SELECT ( SELECT … FROM … WHERE … ) FROM … WHERE …` | ✕ |
| 2. 인라인 뷰 (inline view) | **FROM** 절 안 | `SELECT … FROM ( SELECT … FROM … WHERE … ) as T WHERE …` | ✕ |
| 3. **하위 질의** | **WHERE** 절 안 | `SELECT … FROM … WHERE … ( SELECT … FROM … WHERE … )` | 🔥 **이것만** |

| 수업요약 [이론] | 뜻 |
|---|---|
| `IN` | 하위질의 결과 **목록 중 하나**와 같으면 참 (21번) |
| `ALL` · `ANY` · `SOME` | 결과 **모두**보다 · **하나라도**보다 — `>` 같은 비교 연산자와 함께 (실습 3-1 · 다음 수업) |
| `EXISTS` | 하위질의 결과가 **존재하면 참**, 아니면 거짓 |
| `NOT EXISTS` | 하위질의 결과가 **존재하지 않으면 참** (24번) |

> 🤖 하위질의는 **괄호 안부터** 실행 → 나온 값을 바깥 WHERE 에 넣어요 (20 · 21번) · 결과가 **1행**이면 `=` · **여러 행**이면 `IN` — 여러 행인데 `=` 를 쓰면 **ERROR 1242** (Subquery returns more than 1 row · MySQL 8.0.46 로 확인) · 24번처럼 바깥 테이블(D)을 괄호 안에서 쓰면 바깥 **행마다** 하위질의를 다시 실행해요 = **상관 중첩 질의** (강의자료 20 · 25쪽).

- **행 순서** — 내 엑셀 답 · 학교 · 이 맥 MySQL 8.0.46 의 행 순서가 서로 달라요 (ORDER BY 가 없으면 정해지지 않음) → 행 내용 · 개수로 확인
- `INTERSECT` · `EXCEPT` — 학교와 같은 **MySQL 8.0.46** 에서도 돼요 (11주차에 걱정했던 “학교 MySQL 이 낮은 버전이면 오류” 는 해당 없음) · 기말은 합집합만
- 12주차 실습 SQL 의 omember 는 `('103','F')` — 11주차 수업요약의 `('102','F')` 오타가 고쳐졌어요 (엑셀과 같음)
- (미리 확인) 강의자료 25쪽 상관중첩질의 답 `… from employee E where salary > (select AVG(salary) from employee E where E.dno = employee.dno);` → 바깥 · 안쪽 별칭이 둘 다 **E** 라서 `employee.dno` 를 못 찾아 **ERROR 1054** (MySQL 8.0.46) → 바깥 `E1` · 안쪽 `E2` 로 쓰면 `… where E2.dno = E1.dno` → 이수민 · 박영권 · 이성래 (수업 전 · 노션에 없음)
