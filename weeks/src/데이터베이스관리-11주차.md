## 1. 🔥 [Quiz 11-1] 직원 — 집계함수 · GROUP BY · HAVING (강의자료 4쪽) · 3번부터 시험
✍️ **필기** — “직원테이블 퀴즈 3번문제(직책의 개수를 중복없이 검색하시오)부터 시험문제” → **3 · 4 · 5 · 6번**

| 직원코드 | 성명 | 직책 | 연봉 |
|---|---|---|---|
| 161353 | 김미나 | 대리 | 2300 |
| 181323 | 최영락 | 사원 | 1900 |
| 151453 | 홍진호 | 과장 | 2800 |
| 135485 | 구준표 | 과장 | 3000 |
| 104895 | 김나래 | 팀장 | 3600 |
| 165484 | 김하늘 | 대리 | 2400 |

```sql
drop table if exists 직원;                                   -- 있으면 지우고 새로 만들기
create table 직원 (
    직원코드  varchar(8)   NOT NULL ,                        -- 직원 번호 (기본키)
    성명      varchar(20)  NOT NULL ,                        -- 이름은 꼭 입력
    직책      varchar(10) ,                                  -- 대리 · 사원 · 과장 · 팀장
    연봉      int ,                                          -- 숫자 → MAX · AVG 계산 가능
    PRIMARY KEY(직원코드)                                      -- 직원코드로 행을 구별
);
insert into 직원 values('161353','김미나','대리',2300);      -- 6명 입력 (수업요약 그대로)
insert into 직원 values('181323','최영락','사원',1900);
insert into 직원 values('151453','홍진호','과장',2800);
insert into 직원 values('135485','구준표','과장',3000);
insert into 직원 values('104895','김나래','팀장',3600);
insert into 직원 values('165484','김하늘','대리',2400);
SELECT MAX(연봉) FROM 직원;                                  -- 1) 최대 연봉 → 6명 중 가장 큰 값
SELECT COUNT(*) FROM 직원;                                   -- 2) 사원수 → 행 개수
```
| MAX(연봉) |
|---|
| 3600 |

| COUNT(*) |
|---|
| 6 |

### 🔥 3) 직책의 개수를 중복없이 검색하시오
```sql
SELECT COUNT(DISTINCT 직책)                                  -- ② 같은 직책은 한 번만 세기
FROM 직원;                                                   -- ① 직책 6칸 = 대리 · 사원 · 과장 · 과장 · 팀장 · 대리 → 종류 4개
```
| COUNT(DISTINCT 직책) |
|---|
| 4 |

### 🔥 4) 직책별 연봉의 평균 · 5) 직책별 사원수
```sql
SELECT 직책, AVG(연봉)                                       -- ③ 묶음마다 평균 (대리 = (2300 + 2400) ÷ 2)
FROM 직원                                                    -- ① 직원에서
GROUP BY 직책;                                               -- ② 같은 직책끼리 한 묶음
SELECT 직책, COUNT(*)                                        -- ③ 묶음마다 행 수
FROM 직원                                                    -- ① 직원에서
GROUP BY 직책;                                               -- ② 같은 직책끼리
```
| 직책 | AVG(연봉) |
|---|---|
| 팀장 | 3600.0000 |
| 과장 | 2900.0000 |
| 대리 | 2350.0000 |
| 사원 | 1900.0000 |

| 직책 | COUNT(*) |
|---|---|
| 팀장 | 1 |
| 과장 | 2 |
| 대리 | 2 |
| 사원 | 1 |

### 🔥 6) 연봉이 2500 이상인 사원이 2명 이상인 직책의 사원수
```sql
SELECT 직책, COUNT(*)                                        -- ⑤ 직책 · 사원수
FROM 직원                                                    -- ① 직원에서
WHERE 연봉>=2500                                             -- ② 행 조건 먼저 → 홍진호 2800 · 구준표 3000 · 김나래 3600 만 남음
GROUP BY 직책                                                -- ③ 직책끼리 → 과장 {2800, 3000} · 팀장 {3600}
HAVING COUNT(*)>=2;                                          -- ④ 그룹 조건 → 2명 이상인 과장만
```
| 직책 | COUNT(*) |
|---|---|
| 과장 | 2 |

> ✍️ 내 SQL 답 6개 모두 ✅ (MySQL 8.4 로 실행) · 🤖 6) 에서 `WHERE 연봉>=2500` 을 빼면 대리(2300 · 2400)도 2명이라 **과장 2 · 대리 2** 가 나와요 — “연봉이 2500 이상인 사원” = 행 조건 **WHERE** · “2명 이상인 직책” = 그룹 조건 **HAVING** ([9주차 실행 순서](데이터베이스관리-9주차.html)) · AVG 는 MySQL 이 3600.0000 처럼 소수 4자리로 보여 줘요 · 그룹의 행 순서는 MySQL 이 정함 (ORDER BY 를 써야 보장).

- ✍️ 노션 10주차 페이지 맨 아래에 붙인 “실습한 SQL코드” (fruit 2-1 ~ 2-7 · 고객 2-1 ~ 2-4) 를 MySQL 8.4 로 다시 실행 → **10주차 페이지 결과와 모두 같아요** ✅

```sql
SELECT 등급, AVG(적립금) FROM 고객                            -- ✍️ 고객 2-4 내 답 (AVG 뒤를 한 칸 띄움)
GROUP BY 등급 HAVING AVG (적립금)>=1000;                      -- AVG 는 띄워도 됨 → gold 3500 · vip 2500
SELECT COUNT (*) FROM 고객;                                   -- 🤖 COUNT 를 띄우면 → ERROR 1064
SELECT SUM (적립금) FROM 고객;                                -- 🤖 SUM 을 띄우면 → ERROR 1630 (FUNCTION …SUM does not exist)
```
| 등급 | AVG(적립금) |
|---|---|
| gold | 3500.0000 |
| vip | 2500.0000 |

> 🤖 MySQL 은 `COUNT` · `SUM` · `MAX` · `MIN` 같은 함수는 이름과 `(` 사이에 공백이 있으면 함수로 안 봐요 (`MAX (적립금)` 도 ERROR 1630 · 이 맥 MySQL 8.4 로 확인) · `AVG` 는 띄워도 되지만 시험 답안은 **붙여 쓰기** (`AVG(적립금)`) 가 안전해요.

## 3. 🔥 [Quiz 11-3] NULL 과 SUM — 기말고사 문제 (강의자료 6쪽)
✍️ **필기** — “-- 1) **기말고사 문제** `SELECT sum(col2) FROM tab1;`” · 실습 엑셀 quiz-3 시트 “**중요! 기말고사 시험문제**”

> 다음 중 테이블 tab1 에 아래와 같은 데이터가 존재할 경우에 대한 설명으로 가장 적절한 것은? (각 칼럼의 타입은 number 이다.)
> ① `select sum(col2) from tab1` 의 결과는 NULL 이다. · ② `select sum(col1 + col2 + col3) from tab1` 의 결과는 185 이다. · ③ `select sum(col2 + col3) from tab1` 의 결과는 90 이다. · ④ `select sum(col2) + sum(col3) from tab1` 의 결과는 90 이다.

| col1 | col2 | col3 |
|---|---|---|
| 10 | 20 | NULL |
| 15 | NULL | NULL |
| 50 | 70 | 20 |

```sql
CREATE TABLE tab1 (col1 int, col2 int, col3 int);           -- 문제의 number 는 Oracle 자료형 → MySQL 은 int 로
INSERT INTO tab1 VALUES (10, 20, NULL);                      -- 1행
INSERT INTO tab1 VALUES (15, NULL, NULL);                    -- 2행
INSERT INTO tab1 VALUES (50, 70, 20);                        -- 3행
SELECT col1, col2, col3, col1+col2+col3, col2+col3 FROM tab1;   -- 🤖 행마다 먼저 더해 보기 → NULL 이 섞인 행은 NULL
```
| col1 | col2 | col3 | col1+col2+col3 | col2+col3 |
|---|---|---|---|---|
| 10 | 20 | NULL | NULL | NULL |
| 15 | NULL | NULL | NULL | NULL |
| 50 | 70 | 20 | 140 | 90 |

```sql
select sum(col2) from tab1;                                  -- ① 집계함수는 NULL 을 빼고 → 20 + 70 = 90
select sum(col1 + col2 + col3) from tab1;                    -- ② 행마다 NULL · NULL · 140 → NULL 을 빼고 합 → 140
select sum(col2 + col3) from tab1;                           -- ③ 행마다 NULL · NULL · 90 → 90
select sum(col2) + sum(col3) from tab1;                      -- ④ 열마다 따로 합 → 90 + 20 = 110
```
| 보기 | 결과 (MySQL) | 판단 |
|---|---|---|
| ① `sum(col2)` | **90** | ✕ — NULL 이 아니라 90 |
| ② `sum(col1 + col2 + col3)` | **140** | ✕ — 185 가 아니라 140 |
| 🔥 ③ `sum(col2 + col3)` | **90** | ⭕ **정답** |
| ④ `sum(col2) + sum(col3)` | **110** | ✕ — 90 이 아니라 110 |

> 6쪽 정리 — 1. **컬럼 간 연산**할 때 NULL 이 포함되면 항상 **NULL** 을 반환 · 2. 집계함수(SUM() · AVG() · MIN() · MAX() · COUNT())는 여러 행을 읽어 집계할 때 **NULL 값을 연산 대상에서 제외** (결과는 정상 반환)

> ✍️ 엑셀 답 “① X 90나옴 · ② X 140 나옴 · ③ O 90나옴 · ④ X 110나옴” → 전부 ✅ (MySQL 로 확인) · 정답 **③** · 🤖 ② 의 185 = 10 + 20 + 15 + 50 + 70 + 20 (NULL 을 0 처럼 보고 다 더한 값) 함정 — 실제로는 1 · 2행 전체가 NULL 이 되어 합에서 빠져요.

## 4. [Quiz 11-4] 관계대수 — 집합 연산 R · S (강의자료 7쪽)
> 다음을 관계대수로 나타내고 SQL 문법과 실행결과를 작성하라 · 노트(엑셀)에 실행결과를 작성하시오

| R.A | R.B | R.C |
|---|---|---|
| a1 | b1 | c1 |
| a2 | b1 | c1 |
| a3 | b1 | c2 |
| a4 | b2 | c3 |

| S.B | S.C | S.D |
|---|---|---|
| b1 | c1 | d1 |
| b1 | c1 | d2 |
| b2 | c2 | d3 |

```sql
CREATE TABLE R (A char(2), B char(2), C char(2));           -- R(A, B, C)
CREATE TABLE S (B char(2), C char(2), D char(2));           -- S(B, C, D) — B · C 가 공통
INSERT INTO R VALUES ('a1','b1','c1'), ('a2','b1','c1'), ('a3','b1','c2'), ('a4','b2','c3');   -- 슬라이드(7쪽) 값
INSERT INTO S VALUES ('b1','c1','d1'), ('b1','c1','d2'), ('b2','c2','d3');
SELECT R.B, R.C FROM R UNION SELECT S.B, S.C FROM S;        -- 1) B · C 열만 뽑아 합치고 중복은 한 번만
SELECT R.B, R.C FROM R INTERSECT SELECT S.B, S.C FROM S;    -- 2) 양쪽에 다 있는 것
SELECT R.B, R.C FROM R EXCEPT SELECT S.B, S.C FROM S;       -- 3) 슬라이드는 MINUS → MySQL 은 EXCEPT
SELECT * FROM R, S;                                          -- 4) 모든 짝
```
| 문제 (7쪽) | 관계대수식 | 결과 (MySQL 8.4) |
|---|---|---|
| 1) `UNION` | π B,C (R) ∪ π B,C (S) | **4행** — (b1, c1) · (b1, c2) · (b2, c3) · (b2, c2) |
| 2) `INTERSECT` | π B,C (R) ∩ π B,C (S) | **1행** — (b1, c1) |
| 3) `MINUS` | π B,C (R) − π B,C (S) | ⚠️ `MINUS` → ERROR 1064 · `EXCEPT` → **2행** (b1, c2) · (b2, c3) |
| 4) `FROM R, S` | R × S | **12행** (4 × 3) · 열 6개 (A · B · C · B · C · D) |

> ✍️ 내 1) 답 `SELECT R.B,R.C FROM R UNION SELECT S.B,S.C FROM S` ✅ (끝에 `;` 만 더하기) · 🤖 `UNION ALL` 이면 중복까지 7행 · ⚠️ 수업요약 txt 의 R INSERT 3행은 `('a2','b1','c2')` 라 슬라이드의 **a3** 와 달라요 (오타로 보임) — 1) ~ 3) 은 B · C 만 써서 결과가 같고 4) 의 A 열만 달라져요 (위 결과는 슬라이드 값) · 🤖 MySQL **8.0.31+** 는 `INTERSECT` · `EXCEPT` 지원 (이 맥 8.4 로 확인 · 학교 MySQL 이 낮은 버전이면 오류) · 기말은 **합집합만** (10주차 🔥).

## 5. 조인 요약 — 내부조인 · 외부조인 (강의자료 11 · 12쪽)
✍️ **필기**
- 조인 : 두 개 이상의 테이블에서 원하는 결과를 검색 (공통 필드)
- 1) **내부조인**(INNER JOIN) : 2개 이상의 테이블에서 **일치하는 행** 검색
- 2) **외부조인**(OUTER JOIN) : 2개 이상의 테이블에서 **일치하지 않는 행도** 검색

| 조인 | 종류 | MySQL |
|---|---|---|
| **내부조인** | 세타조인 (theta) · 동등조인 (equi) · 자연조인 (natural) | `INNER JOIN … ON` · `NATURAL JOIN` |
| **외부조인** | 왼쪽 (left) · 오른쪽 (right) · 완전 (full) 외부조인 | `LEFT OUTER JOIN` · `RIGHT OUTER JOIN` · 완전 = 왼쪽 `UNION` 오른쪽 |

| 쓰는 법 (12쪽) | 모양 |
|---|---|
| 방법1 | `SELECT … FROM 테이블1, 테이블2 WHERE 테이블1.키 = 테이블2.키 AND …` |
| 방법2 | `SELECT … FROM 테이블1 INNER JOIN 테이블2 ON 테이블1.키 = 테이블2.키 WHERE … AND …` |
| 외부조인 | 방법2 모양 — `FROM 테이블1 LEFT OUTER JOIN 테이블2 ON …` (수업 답안도 방법2) |

> 🤖 방법1 처럼 `WHERE 테이블1.키 = 테이블2.키` 로 짝을 맞추면 짝 없는 행은 빠져서 **내부조인**(동등조인) 결과가 돼요 — 짝 없는 행을 살리는 외부조인은 `LEFT/RIGHT OUTER JOIN … ON` 으로.

## 6. [실습] freshman · dmember — 조인 6가지 (강의자료 13 ~ 19쪽)
| freshman.name | address |
|---|---|
| 김광식 | 서울 |
| 김현정 | 대전 |
| 조영수 | 대전 |

| dmember.name | dept_name |
|---|---|
| 김광식 | 컴퓨터공학과 |
| 김현정 | 산업공학과 |
| 이진영 | 전자공학과 |

```sql
CREATE TABLE freshman (name VARCHAR(12) NOT NULL, address VARCHAR(9));       -- 신입생 (이름 · 주소)
CREATE TABLE dmember (name VARCHAR(12) NOT NULL, dept_name VARCHAR(30));     -- 학과 회원 (이름 · 학과)
INSERT INTO freshman VALUES('김광식','서울'), ('김현정','대전'), ('조영수','대전');
INSERT INTO dmember VALUES('김광식','컴퓨터공학과'), ('김현정','산업공학과'), ('이진영','전자공학과');
SELECT * FROM freshman, dmember;                             -- 1. 카티션 프로덕트 — 조건 없이 모든 짝 (= CROSS JOIN)
```
→ 3 × 3 = **9행** · 열 4개 (name · address · name · dept_name) — `SELECT * FROM freshman CROSS JOIN dmember;` 도 9행

### 2. 동등조인 · 3. 자연조인
```sql
SELECT * FROM freshman, dmember                              -- 2. 동등조인 방법1 — FROM 에 두 테이블
WHERE freshman.name = dmember.name;                          -- 이름이 같은 짝만
SELECT * FROM freshman INNER JOIN dmember                    -- 2. 동등조인 방법2 — INNER JOIN
ON freshman.name = dmember.name;                             -- ON 에 조건 → 결과 같음
SELECT freshman.name, address, dept_name                     -- 3. 자연조인 — 같은 name 은 한 번만 (freshman.name)
FROM freshman INNER JOIN dmember
ON freshman.name = dmember.name;                             -- 방법1 (WHERE) 로 써도 같음
```
| name | address | name | dept_name |
|---|---|---|---|
| 김광식 | 서울 | 김광식 | 컴퓨터공학과 |
| 김현정 | 대전 | 김현정 | 산업공학과 |

| name | address | dept_name |
|---|---|---|
