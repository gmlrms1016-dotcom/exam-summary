## 1. 수업 필기 — ✍️ 원문 그대로 + ⚠️ 팩트체크

> ✍️ “VMWARE에서 하드디스크를 60개의 SCSI장치를 설정할수있다”

- ✅ 맞음 — 📖 VMware 가상머신에는 **SCSI 슬롯(컨트롤러)이 4개**(SCSI 0 ~ 3)이고 슬롯마다 **0 ~ 15번** 중 **7번을 뺀 15개**를 꽂을 수 있음 → **4 × 15 = 60개**
- 🤖 7번이 빠지는 이유 = SCSI 컨트롤러 자신이 7번을 씀 · 디스크 설정 창 **Advanced** 의 `SCSI 0:1` = 0번 슬롯의 1번 자리 (과제에서 고장 낼 디스크를 이걸로 찾음 — 4-1)

> ✍️ “저번주차 해봤던 디스크 추가하는 절차를 복습”

- 9주차 1-1 그대로 — VM 을 끄고 **Edit virtual machine settings → Add → Hard Disk → SCSI → 크기** (이번엔 **2GB · 1GB** 두 번)
- ⚠️ 학교 PC VMware 는 디스크 종류 기본값이 **NVMe** 였음 → 꼭 **SCSI** 로 골라야 `/dev/sdb` · `/dev/sdc` 로 보임 (🤖 NVMe 로 붙이면 `/dev/nvme0n1` 같은 다른 이름)

> ✍️ “하드웨어는 RAID는 안정적이지만 상당히 비싸다”

- ✅ 맞음 — 📖 **하드웨어 RAID** = 하드웨어 제조업체가 만든 **RAID 컨트롤러 장비**로 구성 → 안정적이지만 **비쌈**
- 📖 **소프트웨어 RAID** = 비싼 하드웨어 RAID 대신 **운영체제가 지원**하는 RAID → 저렴하지만 신뢰성 · 속도는 조금 떨어질 수 있음 · **이번 실습은 전부 소프트웨어 RAID** (리눅스의 `mdadm`)

> ✍️ “claude야 정리해[ RAID {단순 볼륨 , Linear RAID , RAID0(스트라이핑 방식+날려도 되는 데이터<팩트체크 필요함>) , RAID1(미러링+결함허용+신뢰 상승) , RAID5(데이터 복구가 쉽다<짝수가 되어야함>) , RAID6} ]”

- 🤖 답 = **2절 표** (교재 그림 6-23 기준)
- ⚠️ 팩트체크 **RAID0 “날려도 되는 데이터”** → ✅ **맞음** — 📖 399쪽 “RAID 0은 **빠른 성능을 요구하되 혹시 전부 잃어버려도 큰 문제가 되지 않는 데이터**를 저장하는 데 적절한 방식이다.” (디스크 하나만 고장 나도 **모든 데이터를 잃음**)
- ⚠️ 팩트체크 **RAID5 “짝수가 되어야함”** → ✅ **맞음** — 📖 402쪽 “**짝수 패리티**를 사용했는데, 짝수 패리티란 각 행이 짝수가 되게 만들려고 숫자를 채우는 것” → 디스크 **개수**가 짝수여야 한다는 뜻이 아님 (RAID 5 는 📖 **최소 3개** · 3 · 4 · 5개 다 됨)
  - 🤖 노션의 학교 PC 보충은 이 메모를 “디스크 개수”로 읽고 “틀림”이라고 했는데, 교재 402쪽을 보면 **패리티 이야기라 필기가 맞음**
- ⚠️ **RAID5 “데이터 복구가 쉽다”** → 정확히는 **디스크 1개**가 고장 나면 패리티로 그 디스크의 값을 계산해 되살림 · **2개가 동시에** 고장 나면 복구 못 함 → 그래서 RAID 6 (2-5)

> ✍️ 명령 메모 (수업 중 그대로)

```text
mdadm --create /dev/md9 --level=linear --raid-devices=2/dev/sda1 /dev/sdb1 mdadm -detail /dev/md9
mkfs.ext4 /dev/md9
mkdir /raidLinear
mount /dev/md9 /raidLinear
df
cp anTAB키 /raidLinear/test1
cp anTAB키 /raidLinear/test2
ls -l/rainLinear
alias gedit="gnome-text-editor"
gedit /etc/fstab
(맨밑에 추가:/dev/md9 /raidLinear ext4 defaults 0 0)
```

| 메모 | ⚠️ 바로잡기 | 왜 |
|---|---|---|
| `--raid-devices=2/dev/sda1 /dev/sdb1` | `--raid-devices=2 /dev/sdb1 /dev/sdc1` | `2` 뒤 **띄어쓰기** · **sda 는 리눅스가 깔린 디스크**(/ = sda2) → RAID 에 쓰면 안 됨 · 새로 붙인 sdb · sdc 의 파티션 |
| `mdadm -detail /dev/md9` (같은 줄) | 다음 줄에 `mdadm --detail /dev/md9` | 긴 옵션은 **빼기 2개** `--` · 명령 두 개를 한 줄에 이어 쓰면 안 됨 |
| `cp anTAB키` | 🤖 `cp anaconda-ks.cfg …` | `an` + **Tab** = 자동 완성 → root 홈의 `anaconda-ks.cfg`(설치 기록 파일) · 아무 파일이나 복사해 보는 시험용 |
| `ls -l/rainLinear` | `ls -l /raidLinear` | `-l` 뒤 띄어쓰기 · rain → **raid** 오타 |

> ✍️ “하드를 지우고 다시 만드는 문제를 일으켜서 다시 복구하는거 했음” → **4절** (고장 → 복구 로그)

## 2. RAID 개념 (📖 396 ~ 404쪽)

### 2-1. RAID 란

- 📖 **RAID**(Redundant Array of Inexpensive/Independent Disks) = **여러 개의 디스크를 하나의 디스크처럼** 사용하는 방식 → 비용 절감 · 신뢰성 향상 · 성능 향상
- 📖 **기본 구성 7가지** — Linear RAID · RAID 0 · 1 · 2 · 3 · 4 · 5
- 📖 **실무에서 주로 쓰는 것** — **Linear RAID · RAID 0 · RAID 1 · RAID 5** · RAID 5 의 변형인 **RAID 6** · RAID 1 과 0 의 혼합인 **RAID 1+0**
- 📖 **단순 볼륨** = 디스크 하나를 볼륨(묶음) 하나로 사용 → **RAID 에는 포함되지 않음** (9주차에 디스크를 추가해 쓴 방식)

### 2-2. 종류 한눈에 — 📖 그림 6-23 각 RAID 방식 비교

| 방식 | 저장 방식 | 최소 디스크 | 쓸 수 있는 용량 (1TB × N개) | 디스크 고장 | 특징 |
|---|---|---|---|---|---|
| 단순 볼륨 | 디스크 1개 그대로 | 1 | 1TB | — | **RAID 아님** |
| **Linear RAID** | 첫 번째 디스크를 **다 채운 뒤** 다음 디스크 | **2개 이상** | **N** (크기 달라도 전부) | 결함 허용 ✗ | 디스크 추가 가능 · 공간 효율 100% |
| **RAID 0** | **스트라이핑**(Striping · 교재 표기 Stripping) — 모든 디스크에 **동시에** 나눠 저장 | **2개 이상** | **N** | 하나만 고장 나도 **전부 잃음** | **가장 빠름** |
| **RAID 1** | **미러링**(Mirroring) — 같은 데이터를 **2벌** | **2개** | **N / 2** | 1개 고장 나도 됨 | **결함 허용** · 공간 효율 50% |
| **RAID 5** | **패리티** 1개분으로 복구 | **3개 이상** (대개 5개 이상) | **N − 1** | **1개**까지 | 결함 허용 + 공간 효율 좋음 |
| **RAID 6** | 패리티 **2개분** | **4개 이상** | **N − 2** | **2개**까지 | RAID 5 의 개선 · 신뢰도 ↑ · 속도는 RAID 5 보다 약간 ↓ |
| RAID 1+0 | RAID 1 로 묶은 것을 다시 RAID 0 | 🤖 4개 | 🤖 N / 2 | 🤖 묶음마다 1개씩 | 신뢰성 + 속도 둘 다 (📖 교재만 · 수업 필기엔 없음) |

- 📖 NOTE — Linear RAID 를 **뺀** 나머지(RAID 0 · 1 · 5 · 6 · 1+0)는 **같은 용량의 디스크**를 쓰는 게 일반적 (가능하면 같은 회사 · 같은 모델)
- 📖 399쪽 — RAID 0 을 **100TB + 1TB** 디스크로 만들면 쓸 수 있는 용량은 **2TB 뿐** (작은 디스크에 맞춰짐) · **Linear RAID** 로 만들면 **101TB** 전부

### 2-3. Linear RAID vs RAID 0 vs RAID 1 — 📖 그림 6-24 · 6-25

📖 **‘안녕하세요?우재남입니다’**(12바이트)를 디스크에 저장한다고 할 때 (한 글자 저장에 1초 · 이해하기 쉽게 글자 단위로 가정):

| | 디스크 1 | 디스크 2 | 디스크 3 | 시간 | 저장한 양 |
|---|---|---|---|---|---|
| **Linear RAID** | 안녕하세요?우재남입니다 | (비어 있음) | (비어 있음) | **12초** | 12바이트 |
| **RAID 0** (디스크 3개) | 안 세 우 입 | 녕 요 재 니 | 하 ? 남 다 | **4초** | 12바이트 |
| **RAID 1** (디스크 2개) | 안녕하세요?우재남입니다 | 안녕하세요?우재남입니다 | — | **12초** (동시에 저장) | **24바이트** |

- **Linear** — 앞 디스크가 **다 차야** 다음 디스크를 씀 · 속도 이득 없음
- **RAID 0** — 📖 두 번째 디스크가 고장 나면 ‘**안X하세X?우X남입X다**’ → 원래 데이터를 알 수 없음 = **전부 잃음** · 디스크를 늘릴수록 빨라지지만 📖 “**데이터 소실 위험성은 더 증가**”
- **RAID 1** — 📖 2개 중 하나가 고장 나도 데이터가 그대로 = **결함 허용**(Fault Tolerance) · 대신 비용 2배 (1TB 2개 → 1TB 만 사용 · 공간 효율 50%) · 📖 “디스크가 고장 나도 절대 잃으면 안 되는 중요한 데이터” 에 사용

📖 표 6-1 RAID 0 과 RAID 1 비교

| | RAID 0 | RAID 1 |
|---|---|---|
| 성능(속도) | **뛰어남** | 변화 없음 |
| 데이터 안전성(결함 허용) | 보장 못 함 (✗) | **보장함** (○) |
| 공간 효율성 | **좋음** | 나쁨 |

### 2-4. RAID 5 — 짝수 패리티 (📖 그림 6-26 ~ 6-28)

📖 12비트 **‘000 111 010 011’** 을 디스크 **4개**(sda ~ sdd)로 된 RAID 5 에 저장 — 행마다 한 칸은 **패리티 자리**(첫 행 sdd · 둘째 sdc · 셋째 sdb · 넷째 sda 처럼 돌아가며)

| 행 | sda | sdb | sdc | sdd | 패리티 정하기 (1 의 합이 **짝수**가 되게) |
|---|---|---|---|---|---|
| 1 (000) | 0 | 0 | 0 | **[0]** | 0+0+0+**P** = 짝수 → P = **0** |
| 2 (111) | 1 | 1 | **[1]** | 1 | 1+1+**P**+1 = 짝수 → P = **1** |
| 3 (010) | 0 | **[1]** | 1 | 0 | 0+**P**+1+0 = 짝수 → P = **1** |
| 4 (011) | **[0]** | 0 | 1 | 1 | **P**+0+1+1 = 짝수 → P = **0** |

- **복구** — 📖 sdb 가 고장 나면: 첫 행 ‘0 + **?** + 0 + 0 = 짝수’ → sdb 는 **0** · 나머지 행도 같은 식으로 → sdb 의 원래 값 **0110** 을 알아냄 → 데이터 손실 없음
- **공간 효율** — 📖 1TB × 4개 → **3TB**(75%) · 1TB × 10개 → **9TB**(90%) = **N − 1** → 디스크가 많을수록 효율 ↑
- 🤖 패리티 칸을 한 디스크에 몰지 않고 **행마다 돌아가며** 둠 (그림 6-26)

### 2-5. RAID 6 · RAID 1+0

- 📖 **RAID 6** = RAID 5 를 개선해 **패리티 2개** → **디스크 2개가 동시에 고장 나도** 데이터 이상 없음 · 1TB × 10개 → **8TB**(N − 2) · **최소 4개** (RAID 5 는 최소 3개)
- 📖 RAID 6 은 공간 효율이 RAID 5 보다 약간 낮지만 **신뢰도는 더 높음** · 패리티를 2개 만들어야 해서 쓰기 알고리즘이 복잡 → **속도는 RAID 5 보다 약간 느림**
- 📖 **RAID 1+0**(또는 10) = RAID 1(미러링)로 구성한 데이터를 다시 RAID 0(스트라이핑)으로 → 신뢰성 + 속도 · 그림 6-29: 디스크당 6글자 → **6초** · 24바이트 사용 · 왼쪽 · 오른쪽 RAID 1 에서 **각각 1개씩** 고장 나도 안전

## 3. 수업 실습 — Server 에 Linear RAID (/dev/md9 → /raidLinear)

### 흐름 한눈에

```text
(VM 끄고) SCSI 2GB · 1GB 디스크 추가 → 부팅 → ls -l /dev/sd*   (sdb · sdc 확인)
→ fdisk /dev/sdb · fdisk /dev/sdc   (파티션 1개씩 + 타입 fd = Linux raid autodetect)
→ mdadm --create /dev/md9 --level=linear --raid-devices=2 /dev/sdb1 /dev/sdc1   (RAID 만들기)
→ mdadm --detail /dev/md9           (확인)
→ mkfs.ext4 /dev/md9 → mkdir /raidLinear → mount /dev/md9 /raidLinear → df
→ /etc/fstab 에 /dev/md9 /raidLinear ext4 defaults 0 0 → (mdadm.conf 저장) → reboot
```

- 9주차와 다른 점 = **디스크 2개**를 묶은 **/dev/md9**(RAID 장치)를 **하나의 디스크처럼** 포맷 · 마운트 (파티션 `/dev/sdb1` 을 바로 쓰지 않음)

### 3-1. 실습에 쓴 디스크

| 장치 | 크기 | 용도 |
|---|---|---|
| `/dev/sda` | 100GB (Server) · 80GB (Server(B)) | 리눅스가 깔린 디스크 — sda1 · **sda2 = /** → **RAID 에 쓰면 안 됨** |
| `/dev/sdb` | **2GB** | → `/dev/sdb1` (타입 fd) |
| `/dev/sdc` | **1GB** | → `/dev/sdc1` (타입 fd) |
| `/dev/md9` | 2GB + 1GB ≈ **3GB** | sdb1 + sdc1 을 묶은 **Linear RAID** → ext4 → **/raidLinear** |

- 🤖 `md` = multiple device (리눅스 소프트웨어 RAID 장치 이름) · `9` 는 실습에서 정한 번호 (과제 2 의 RAID 0 은 `md0`)

### 3-2. fdisk — 파티션 + 타입 **fd** (Linux raid autodetect)

수업 로그 (디스크를 새로 바꾼 뒤 sdb 를 다시 나눈 장면 — 처음 만들 때도 sdb · sdc 에 똑같이):

```term root@localhost:~#
$ ls -l /dev/sd*  ## sdb (8, 16) 는 파티션이 없음 = 새로 바꾼 2GB 디스크 · sdc1 (8, 33) 은 그대로
brw-rw---- 1 root disk 8,  0 11월  5일  15:10 /dev/sda
brw-rw---- 1 root disk 8,  1 11월  5일  15:10 /dev/sda1
brw-rw---- 1 root disk 8,  2 11월  5일  15:10 /dev/sda2
```

## 6. 트러블슈팅 · 작업 방식에서 배운 점

| 상황 | 원인 | 해결 |
|---|---|---|
| 새 디스크가 `/dev/sdb` 로 안 보임 | VMware 디스크 종류 기본값 **NVMe** | 디스크 추가 때 **SCSI** 로 고르기 |
| Server(B) 에서 `mdadm` 이 없음 | 스냅샷에 패키지가 안 깔려 있음 | `dnf -y install mdadm` |
| `deadm` · `mdeadm` → 명령을 찾을 수 없습니다 | 오타 | **`mdadm`** |
| `appears to be part of a raid array … [y/N]?` | 그 파티션에 **예전 RAID 정보**가 남아 있음 | 새로 만들 거면 `y` (`n` 이면 create aborted) |
| 디스크를 뺀 뒤 부팅이 1분 30초 멈췄다가 응급 모드 | fstab 의 /dev/md9 를 못 찾음 | root 로그인 → `mdadm --stop /dev/md9` → fstab 줄에 `#` → `reboot` |
| `mdadm --run` → not enough drives present | Linear 는 디스크가 다 있어야 작동 | 새 디스크 → 다시 `--create` (데이터는 복구 ✗) |
| 재부팅 뒤 `gedit` 이 없음 | `alias` 는 그 터미널에서만 | 다시 alias 를 치거나 `~/.bashrc` 에 추가 · 그냥 `vi` |
| 디스크를 빼자 1GB 디스크가 `sdb` 가 됨 | 장치 이름은 붙은 순서대로 다시 매겨짐 (9주차와 같음) | `ls -l /dev/sd*` · `lsblk` 로 확인하고 작업 |

- 비밀번호(응급 모드 · 로그인) 입력은 직접
- 워드 파일이 열려 있으면 저장 · 덮어쓰기가 안 됨 → 먼저 닫기 (9주차와 같음)

## 7. 명령어 한 줄 사전

| 명령 | 역할 |
|---|---|
| `fdisk /dev/sdX` → `t` → `fd` | 파티션 종류를 **Linux raid autodetect** 로 |
| `dnf -y install mdadm` | RAID 관리 프로그램 설치 |
| `mdadm --create /dev/md9 --level=linear --raid-devices=2 /dev/sdb1 /dev/sdc1` | **Linear RAID** 만들기 |
| `mdadm --create /dev/md0 --level=0 --raid-devices=2 /dev/sdb1 /dev/sdc1` | **RAID 0** 만들기 (🤖 RAID 1 · 5 · 6 은 `--level=1` · `5` · `6`) |
| `mdadm --detail /dev/md9` | RAID 상세 정보 (방식 · 크기 · 상태 · 장치) |
| `mdadm --detail --scan` | 모든 RAID 를 `ARRAY …` 한 줄씩 |
| `mdadm --detail --scan > /etc/mdadm.conf` | RAID 정보를 설정 파일에 저장 (부팅 때 같은 이름으로) |
| `mdadm --stop /dev/md9` | RAID 멈추기 |
| `mdadm --run /dev/md9` | RAID 강제로 켜기 (Linear 는 디스크가 모자라면 실패) |
| `mkfs.ext4 /dev/md9` | RAID 장치를 ext4 로 포맷 |
| `mount /dev/md9 /raidLinear` | RAID 장치 마운트 |
| `lsblk -S` | SCSI 장치 목록 + **HCTL** (VMware SCSI 0:N 과 맞춰 보기) |
| `alias gedit="gnome-text-editor"` | 명령에 별명 붙이기 (터미널을 닫으면 사라짐) |
| `cp /boot/vmlinuz-6* /raidLinear/testFile` | 시험용 큰 파일(커널 ≈ 15MB) 복사 |
| `halt -p` | 끄기 (전원까지) |

## 8. 🔥 시험 대비 핵심 요약 (10줄)

1. **RAID** = 여러 디스크를 **하나처럼** · 하드웨어 RAID(컨트롤러 장비 · 안정적 · **비쌈**) vs 소프트웨어 RAID(**운영체제** 지원 · 저렴 · 이번 실습 `mdadm`)
2. 기본 7가지 = Linear · RAID 0 ~ 5 · 실무 = **Linear · 0 · 1 · 5 · 6 · 1+0** · 단순 볼륨은 **RAID 아님**
3. **Linear** = 앞 디스크를 **다 채운 뒤** 다음 · 크기가 달라도 전부 사용(100TB + 1TB = 101TB) · **결함 허용 ✗**
4. **RAID 0** = **스트라이핑** · 동시에 저장 → **가장 빠름**(12초 → 4초) · 하나만 고장 나도 **전부 잃음** → “잃어도 큰 문제 없는 데이터” · 최소 2개 · 용량 N
5. **RAID 1** = **미러링** · 같은 데이터 2벌 → **결함 허용** · 공간 효율 **50%** · 속도 변화 없음 · 최소 2개
6. **RAID 5** = **패리티** · **최소 3개** · 용량 **N − 1** · **1개** 고장까지 복구 · **짝수 패리티** = 행의 1 개수가 짝수가 되게 채움 (0+0+0+P → P=0)
7. **RAID 6** = 패리티 **2개** · **최소 4개** · 용량 **N − 2** · **2개** 동시 고장까지 · RAID 5 보다 신뢰도 ↑ 속도 약간 ↓ · **RAID 1+0** = 미러링 후 스트라이핑
8. VMware **SCSI 60개** = 슬롯 4개 × 15개(0:7 제외) · 디스크 추가 땐 **SCSI** 로
9. Linear RAID 순서: `fdisk`(**t → fd**) → `mdadm --create /dev/md9 --level=linear --raid-devices=2 /dev/sdb1 /dev/sdc1` → `mdadm --detail` → `mkfs.ext4 /dev/md9` → `mount` → `/etc/fstab` → `mdadm --detail --scan > /etc/mdadm.conf`
10. 디스크 고장 → fstab 의 md9 를 못 찾아 **응급 모드** · `mdadm --run` = **not enough drives** → `mdadm --stop` + fstab `#` 로 부팅 → 새 디스크 · 다시 `--create`(y) · `mkfs` · mdadm.conf · fstab `#` 지우기 → **장치는 복구 · 데이터(testFile)는 복구 ✗**
