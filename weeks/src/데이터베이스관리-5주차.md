## 1. 키(Key) 5가지 ★암기 (11 · 28 · 29 · 32p)
> 🔑 **키** = 각 투플을 고유하게 식별할 수 있는 **하나 이상의 애트리뷰트(속성)들의 모임**

| 키 | 성질 ★ | 설명 |
|---|---|---|
| **수퍼키** (Super Key) | **유일성** | 각 투플을 유일하게 구별할 수 있는 속성들의 모임 (필요 없는 속성이 섞여 있어도 됨) |
| **후보키** (Candidate Key) | **유일성 + 최소성** | 유일하게 식별하는 **최소한의** 속성들의 모임 |
| **기본키** (Primary Key) | **중복불가 · 필수입력** | 후보키 중에서 **선택한 하나**의 키 |
| **대체키** (Alternate Key) | UNIQUE | 후보키 중에서 **기본키로 선택되지 않은** 키 |
| **외래키** (Foreign Key) | 참조 | **다른 릴레이션의 기본키를 참조**하는 키 (개체와 개체를 연결) |
| (참고) **대리키** (Surrogate Key) | 인위적 | 식별자가 너무 길거나 여러 속성일 때 **새로 만들어 붙인** 식별자 |

### 신입생 예제 (12 · 30p) — 필기 그대로
```text
-- 신입생(학번, 주민등록번호, 이름, 주소, 학과명)

후보키 : {학번} , {주민등록번호}      ← 유일성 + 최소성
기본키 : {학번}
대체키 : {주민등록번호}
수퍼키 : 학번 또는 주민등록번호를 포함한 모든 조합
        (학번,이름) (학번,주소) (주민등록번호,이름) (학번,주민등록번호,이름) …
```
> ✍️ **필기 — "다음은 후보키인가? 이유를 쓰시오"** · `(학번, 주민등록번호)` **X** · `(주민등록번호, 이름)` **X**<br>→ 둘 다 유일성은 있지만 **필요 없는 속성이 붙어 있어 최소성을 만족하지 못하므로 후보키가 아니라 수퍼키**입니다.

### 수강 예제 (31p)
```text
-- 수강(학번, 과목번호, …)
후보키 : {학번, 과목번호}      ← 두 개를 합쳐야 유일 (복합키)
기본키 : {학번, 과목번호}      ← 후보키가 하나뿐이라 그대로 기본키
대체키 : 없음
```

## 2. 관계 데이터 모델 용어 복습 (7~9p)
| 용어 | 뜻 |
|---|---|
| **릴레이션**(Relation) | 행과 열로 구성된 **2차원 테이블** |
| **속성**(attribute) | 열 · 컬럼 · 필드 |
| **투플**(tuple) | 행 · 레코드 |
| **도메인**(domain) | 한 속성에 나타날 수 있는 **값들의 집합** (유형 · 크기 · 범위) |
| **차수**(degree) ★ | 한 릴레이션의 **속성(열) 개수** |
| **카디널리티**(cardinality) ★ | **투플(행) 개수** |

> ⭐ **시험** — 표를 주고 **차수와 카디널리티 개수**를 묻습니다. 차수 = 세로줄(열), 카디널리티 = 가로줄(행)로 외우세요.
> 🧩 **도메인 예** — 나이 → 0 이상의 정수 · 성별 → {남, 여} · 학년 → {1, 2, 3, 4}

## 3. 릴레이션의 특성 4가지 (26p)
| 특성 | 내용 |
|---|---|
| 투플의 **유일성** | 하나의 릴레이션에 **동일한 투플이 존재할 수 없다** |
| 투플의 **무순서성** | 투플 사이의 **순서는 무의미**하다 |
| 속성의 **무순서성** | 속성 사이의 **순서는 무의미**하다 |
| 속성의 **원자성** | 속성 값으로 **원자값만** 사용할 수 있다 |

## 4. 데이터 모델 3요소 — SOC (16p)
- **구조**(Structure) — 데이터를 어떤 형태로 저장하는지에 대한 추상적 표현
- **연산**(Operation) — 그 구조 안의 데이터를 어떤 방식으로 처리하는지
- **제약조건**(Constraint) — 저장할 때의 구조적 제약 + 연산할 때의 행위적 제약

> 💡 **데이터 모델** = 데이터베이스 **구조를 명세하기 위한 개념**. 외우는 순서는 **SOC**(구조 · 연산 · 제약조건)

## 5. 스키마 3단계 구조와 데이터 독립성 (19 · 24 · 34p)
```text
        ┌─────────────┐
사용자 →│ 외부 스키마 │  외부 뷰(view) — 사용자·응용 프로그램이 보는 관점
        ├─────────────┤   ↕ 논리적 데이터 독립성
        │ 개념 스키마 │  조직 전체 관점 (테이블·관계·제약조건)
        ├─────────────┤   ↕ 물리적 데이터 독립성
        │ 내부 스키마 │  저장 장치에 실제로 저장되는 방법
        └─────────────┘
          database
```
- **논리적 데이터 독립성** — **개념** 스키마가 바뀌어도 **외부** 스키마는 영향받지 않는다
- **물리적 데이터 독립성** — **내부** 스키마가 바뀌어도 **개념 · 외부** 스키마는 영향받지 않는다
- **스키마** = 데이터베이스를 구성하는 데이터의 **구조**와 **제약조건**에 대한 명세

> ✍️ **필기** — 파일시스템 단점 = **중복성 · 종속성** ↔ DBMS 장점 = **데이터 독립성**(논리적 · 물리적)

## 6. 뷰(view) ★핵심 (35 · 40~43p)
> 💡 **뷰** = 다른 테이블을 기반으로 만들어진 **가상의 테이블**. 실제 데이터는 원래 테이블에 있고, 뷰는 **보여 주는 창**입니다.
> 🎯 **뷰의 장점 2가지 ★** — ① **보안** (필요한 열만 보여 줌) ② **사용의 편의성** (복잡한 조회를 이름 하나로)

```sql
-- 뷰 정의(생성)
CREATE VIEW 뷰이름
as
SELECT 열이름
FROM   테이블이름;

DROP VIEW 뷰이름;        -- 뷰 삭제
DROP TABLE 테이블이름;   -- 테이블 삭제
```

### 실습 5-1 — 직원 테이블 만들고 뷰 만들기 (41~43p)
```sql
USE testdb;
DROP TABLE if exists 직원;

-- 직원(이름, 주소, 전화번호, 연봉)
CREATE TABLE 직원(
    이름      VARCHAR(20)   NOT NULL ,
    주소      VARCHAR(100) ,
    전화번호  CHAR(13)      NOT NULL ,
    연봉      INT           DEFAULT 0 ,
    PRIMARY KEY(이름)
);

INSERT INTO 직원 VALUES('우태하','서울시 서초구','010-1111-1111',1000);
INSERT INTO 직원 VALUES('김선우','서울시 구로구','010-2222-2222',2000);
INSERT INTO 직원 VALUES('이영지','서울시 마포구','010-3333-3333',3000);
INSERT INTO 직원 VALUES('유희정','서울시 마포구','010-4444-4444',4000);
INSERT INTO 직원 VALUES('오형준','부산시 연산구','010-5555-5555',5000);
INSERT INTO 직원 VALUES('고진수','서울시 구로구','010-6666-6666',6000);

SELECT * FROM 직원;
SELECT 이름, 전화번호 FROM 직원;   -- 이름과 전화번호만 조회
```
입력한 직원 테이블 (차수 **4** · 카디널리티 **6**):

| 이름 | 주소 | 전화번호 | 연봉 |
|---|---|---|---|
| 우태하 | 서울시 서초구 | 010-1111-1111 | 1000 |
| 김선우 | 서울시 구로구 | 010-2222-2222 | 2000 |
| 이영지 | 서울시 마포구 | 010-3333-3333 | 3000 |
| 유희정 | 서울시 마포구 | 010-4444-4444 | 4000 |
| 오형준 | 부산시 연산구 | 010-5555-5555 | 5000 |
| 고진수 | 서울시 구로구 | 010-6666-6666 | 6000 |

```sql
-- 뷰 생성: 직원_뷰(이름, 전화번호)
CREATE VIEW 직원_뷰
as
SELECT 이름, 전화번호
FROM   직원;

-- 뷰 조회
SELECT * FROM 직원_뷰;

-- 뷰에 데이터 입력
INSERT INTO 직원_뷰(이름, 전화번호) VALUES('신재영','010-9999-9999');

SELECT * FROM 직원_뷰;   -- 뷰 조회
SELECT * FROM 직원;      -- 테이블 조회 → 신재영이 여기에도 들어가 있다
```
> ⭐ **핵심** — 뷰에 넣은 데이터는 **기반 테이블(직원)에 들어갑니다**. 뷰에 없는 열(주소 · 연봉)은 값을 주지 않았으므로 **주소는 NULL, 연봉은 기본값 0**이 됩니다.
> ⚠️ **내 실습과 다른 점** — 강의요약에 적은 CREATE TABLE 은 `NOT NULL` · `DEFAULT 0` 없이 만들어서 연봉이 **NULL**이 됩니다. 또 요약에 `CREATE TABLE 작원(` 이라고 **오타**가 있으니 시험 답안에는 **직원**으로 쓰세요.

### 실습 — 3단계 구조를 뷰로 만들어 보기 (44~47p)
```sql
use studydb;
drop table 가입고객;

-- 가입고객(번호, 이름, 성별, 나이, 직업, 주소, 연락처)   ← 개념 스키마
CREATE TABLE 가입고객(
    번호    int       NOT NULL,
    이름    char(10),
    성별    char(2) ,
    나이    int ,
    직업    char(10),
    주소    char(20) ,
    연락처  char(20) ,
    PRIMARY KEY(번호)
);
INSERT INTO 가입고객 VALUES (1, '홍길동', '남', 20, '학생', '서울', NULL) ,
                            (2, '임꺽정', '남', 22, '학생', '인천', '010-1111-1111') ,
                            (3, '신아로미', '여', 20, '학생', '서울', '010-2222-2222') ;
select * from 가입고객;

-- 외부 스키마 ① 고객분석팀(성별, 나이, 직업)
CREATE VIEW 고객분석팀
as
SELECT 성별, 나이, 직업
FROM   가입고객;
select * from 고객분석팀;

-- 외부 스키마 ② 상품배송팀(고객번호, 고객이름, 주소, 연락처)
CREATE VIEW 상품배송팀(고객번호, 고객이름, 주소, 연락처)
as
SELECT 번호, 이름, 주소, 연락처
FROM   가입고객;
select * from 상품배송팀;
```
> ⭐ **핵심** — 뷰 이름 뒤 **괄호에 이름을 적으면 뷰의 열 이름을 새로 붙일 수 있습니다** (번호 → 고객번호, 이름 → 고객이름). 같은 테이블 하나로 팀마다 **다른 외부 스키마(뷰)** 를 주는 것이 3단계 구조의 핵심이고, 필요 없는 열을 감추니 **보안**도 됩니다.
> 💡 여러 줄을 한 번에 넣을 때는 `VALUES (…) , (…) , (…) ;` 처럼 **쉼표로 이어서** 씁니다.

## 7. 널 값(NULL) ★ (37 · 38p)
> 🕳️ **널 값** = **알려지지 않은 값**(Unknown). 특정 투플의 속성 값을 **모르거나 적합한 값이 없을 때** 사용합니다. **숫자 0도 아니고 공백(' ')도 아닙니다.**

```sql
-- 주소록(이름, 전화번호, 주소, 생일)
CREATE TABLE 주소록(
    이름      char(10)   NOT NULL ,
    전화번호  char(13) ,
    주소      varchar(10) ,
    생일      varchar(11) ,
    PRIMARY KEY(이름)
);

-- ① 값 자리에 NULL 을 그대로 쓰기
INSERT INTO 주소록(이름, 전화번호, 주소, 생일)
VALUES('이건우','010-2132-2345', NULL, NULL);

-- ② 넣을 열만 쓰기 (나머지는 자동으로 NULL)
INSERT INTO 주소록(이름, 전화번호)
VALUES('이건우','010-2132-2345');

-- ③ 열을 생략하고 전체 값 넣기
INSERT INTO 주소록
VALUES('홍길동','010-1234-5678','서울','3월15일');
```
> ⚠️ **따옴표 주의** — `'NULL'` 처럼 따옴표로 감싸면 **널 값이 아니라 "NULL"이라는 글자**가 들어갑니다. 널 값은 **따옴표 없이 NULL**.
> ⚠️ **필기 오타** — 요약의 `INSERT INTO VALUES('D002',…)` 는 **테이블 이름이 빠져서** 실행되지 않습니다. `INSERT INTO 사원 VALUES(…)` 가 맞습니다.

## 8. [실습 5-2] 사원 테이블 — 널 값 넣어 보기 (49p)
```sql
DROP TABLE 사원;

-- 사원(사원번호, 사원명, 연락처, 생일)
CREATE TABLE 사원(
    사원번호  char(4) ,
    사원명    varchar(20) ,
    연락처    char(13) ,
    생일      varchar(15) ,
    PRIMARY KEY(사원번호)
);

INSERT INTO 사원 VALUES('D001','정지영', NULL, NULL);
INSERT INTO 사원 VALUES('D002','김선주','010-1111-1111', NULL);
INSERT INTO 사원 VALUES('D003','정성호', NULL, '10월4일');
SELECT * FROM 사원;
```
> ⭐ **시험 연결** — 사원 테이블의 **차수 = 4**(사원번호 · 사원명 · 연락처 · 생일), 위처럼 3줄을 넣으면 **카디널리티 = 3**.

## 9. INSERT 5가지 방법 ★ (50~52p · clubmember)
```sql
-- clubmember(mno, mname, mbirth, mreg_date, mgpa)
CREATE TABLE clubmember (
    mno         int            NOT NULL ,              -- 회원번호
    mname       varchar(20)    NOT NULL ,              -- 회원명
    mbirth      date ,                                 -- 생일
    mreg_date   TIMESTAMP      DEFAULT NOW()  ,        -- 등록일자 (MySQL)
    mgpa        decimal(3, 1) ,                        -- 평점
    PRIMARY KEY (mno)
);
```

| 방법 | SQL |
|---|---|
| **1-1** 열 개수와 값 개수가 같으면 **열 이름 생략 가능** | `INSERT INTO clubmember VALUES(121,'홍길동','19900315','140320',4.3);` |
| **1-2** **NULL** 값 입력 | `INSERT INTO clubmember VALUES(123,'이정진', NULL, '140425', NULL);` |
| **3** 열 **순서 변경 가능** (열 이름을 값 순서대로 적기) | `INSERT INTO clubmember(mno,mbirth,mreg_date,mname,mgpa) VALUES(510,'19841210','140816','이정무',3.8);` |
| **4** 넣을 **열 이름만** 적기 | `INSERT INTO clubmember(mno,mname,mbirth,mreg_date) VALUES(210,'김윤식','1994-05-08','140912');` |
| **5** **DEFAULT** 값으로 두기 | `INSERT INTO clubmember(mno,mname,mbirth) VALUES(325,'홍진아','1994-12-14');` |

> ⭐ **DEFAULT NOW()** — `mreg_date TIMESTAMP DEFAULT NOW()` 로 만들어 두면 **값을 넣지 않았을 때 현재 날짜·시간이 자동으로** 들어갑니다. (`datetime DEFAULT CURRENT_TIMESTAMP` 도 같은 뜻)
> 💡 값을 직접 **DEFAULT** 라고 써도 기본값이 들어갑니다 — 과제에서 쓴 `INSERT INTO 상품 VALUES (5, '필통', 5000, DEFAULT);`

## 10. 과제 — Quiz 6-1 · 6-2 (54 · 55p)
- **Quiz 6-1 뷰(View)** — ① 직원 테이블 생성 ② 직원 테이블 기반으로 뷰 생성 ③ 뷰에 데이터 입력 ④ 테이블 조회 · 뷰 조회
- **Quiz 6-2 INSERT (생성형 AI 사용)** — ① 도서 테이블 생성 ② AI로 INSERT 예제 5가지 검색 ③ 도서 테이블에 적용해 입력 ④ 조회
- 제출: **생성형 AI 프롬프트 + 작성한 SQL + 실행 화면 캡처**
- 내가 쓴 프롬프트: *"MySQL에서 테이블을 하나 만들고 데이터 입력에 쓰는 INSERT 문법을 유형별 예제 5가지로 설명해줘"*
- 도서 테이블에 적용한 5가지 = 전체 값 · **NULL** · 열 **순서 변경** · 열 **일부만** · **DEFAULT** (9번 표와 같은 5가지)

```sql
-- 과제: 도서(도서번호, 도서명, 저자, 출판사, 출판연도, 분류)
CREATE TABLE 도서 (
    도서번호  INT,
    도서명    VARCHAR(50),
    저자      VARCHAR(30),
    출판사    VARCHAR(20),
    출판연도  INT DEFAULT 2026,
    분류      VARCHAR(10),
    PRIMARY KEY (도서번호)
);
INSERT INTO 도서 VALUES (1, '클로드 코드 제대로 시작하기', '주홍철, 황진성', '길벗', 2026, 'IT모바일');
INSERT INTO 도서 VALUES (2, '뚝딱 바로 써먹는 AI 3대장', '코리아교육그룹 연구소', '안경다리BOOKS', NULL, 'IT모바일');
INSERT INTO 도서 (도서명, 저자, 도서번호, 분류, 출판연도, 출판사) VALUES ('교사를 지키는 단단한 생활지도', '이종혁', 3, '사회 정치', 2026, '테크빌교육');
INSERT INTO 도서 (도서번호, 도서명, 저자, 출판사, 분류) VALUES (4, '휴대폰과 독화살', '장준호', '시월', '여행');
INSERT INTO 도서 VALUES (5, '아름다운 것들은 비밀을 품고 있다', '파묘', '모티브', DEFAULT, '예술');
SELECT * FROM 도서;
```
