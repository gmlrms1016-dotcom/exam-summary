## 1. 관계 연산자 · SELECT 실행 순서 ✍️
| 뜻 | SQL 기호 | 영어 약자 |
|---|---|---|
| 초과 | `>` | gt (greater than) |
| 이상 | `>=` | gte |
| 같다 | `=` | equal |
| 같지 않다 | `<>` · `!=` | ne (not equal) |
| 이하 | `<=` | lte |
| 미만 | `<` | lt (less than) |

> ⚠️ **정정** — 필기에 이하를 `let` 으로 적었는데 **`lte`**(less than or equal) 예요. SQL 의 “같다”는 `==` 가 아니라 **`=` 하나**.

```sql
SELECT 필드명      -- ③ 보여 줄 열을 고른다
FROM   테이블명    -- ① 어느 테이블에서
WHERE  조건절;     -- ② 조건에 맞는 행(레코드)만 남기고
```
> ✍️ **필기** — 쓰는 순서는 SELECT → FROM → WHERE 지만 **실행(컴파일) 순서는 ① FROM → ② WHERE → ③ SELECT**

## 2. [실습 6-1] 데이터 조회 — customer ★시험예상
```sql
-- customer(cno, cname, city, point)
CREATE TABLE customer (                         -- customer 테이블 만들기 시작
      cno        char(4)         NOT NULL   ,   -- 고객번호 — 문자 4자리 · 필수
      cname     varchar(10)    NOT NULL ,       -- 이름 — 최대 10자 · 필수
      city         varchar(20) ,                -- 도시 — 최대 20자
      point      int ,                          -- 포인트 — 정수
      PRIMARY KEY(cno)                          -- cno 를 기본키로
);                                              -- CREATE TABLE 끝
insert into customer values('c101','홍길동','서울',500);   -- c101 · 홍길동 · 서울 · 500
insert into customer values('c102','임꺽정','인천',300);   -- c102 · 임꺽정 · 인천 · 300
insert into customer values('c103','박찬호','안양',800);   -- c103 · 박찬호 · 안양 · 800
insert into customer values('c204','신동엽','과천',350);   -- c204 · 신동엽 · 과천 · 350
insert into customer values('c205','정진우','고양',400);   -- c205 · 정진우 · 고양 · 400

-- ✍️ 내 답
-- 1) customer 테이블을 검색하라
SELECT *                                        -- 모든 열
FROM customer;                                  -- customer 에서 → 5행

-- 2) customer 테이블에서 cname, city 검색하라
SELECT cname, city                              -- 이름 · 도시 두 열만
FROM customer;                                  -- customer 에서 → 5행

-- 3) cno가 c101 인 고객을 검색
SELECT *                                        -- 모든 열
FROM customer                                   -- customer 에서
WHERE cno="c101";                               -- cno 가 c101 인 행만 → 홍길동 1행

-- 4) customer 테이블에서 point가 400 이하인 고객을 검색하라
SELECT *                                        -- 모든 열
FROM customer                                   -- customer 에서
WHERE point<=400;                               -- point 가 400 이하 → 임꺽정 · 신동엽 · 정진우
```
4) 의 실행 결과

| cno | cname | city | point |
|---|---|---|---|
| c102 | 임꺽정 | 인천 | 300 |
| c204 | 신동엽 | 과천 | 350 |
| c205 | 정진우 | 고양 | 400 |

> ⭐ **강조** — **400 이하** = `<=` 라서 point 가 **딱 400 인 정진우도 나와요** (미만 `<` 이면 2명). 내 실습의 `"c101"` 큰따옴표는 MySQL 에서 되지만, 문자는 **작은따옴표 `'c101'`** 가 기본이니 답안은 작은따옴표로.

## 4. [실습 6-2] 데이터 조작 — 주소록 INSERT(NULL) · UPDATE · DELETE ★시험예상
| 명령 | 문법 | 단위 |
|---|---|---|
| **SELECT** 조회 | `SELECT 필드명 FROM 테이블명 WHERE 조건;` | 필드(열) |
| **INSERT** 입력 | `INSERT INTO 테이블명(필드명, …) VALUES(값, …);` | 레코드 추가 |
| **UPDATE** 수정 | `UPDATE 테이블명 SET 필드명 = 수정후값 WHERE 필드명 = 값;` | 필드(열) |
| **DELETE** 삭제 | `DELETE FROM 테이블명 WHERE 필드명 = 값;` | **레코드(행) 통째로** |

```sql
-- 주소록(이름, 전화번호, 주소, 생일)
DROP TABLE if exists 주소록;                       -- 주소록 테이블이 있으면 지움
CREATE TABLE 주소록(                               -- 주소록 테이블 만들기 시작
    이름        char(10)           NOT NULL ,     -- 이름 — 고정 10자 · 필수
    전화번호  char(13) ,                            -- 전화번호 — 13자리
    주소        varchar(10) ,                     -- 주소 — 최대 10자
    생일        varchar(11) ,                     -- 생일 — 최대 11자 문자
    PRIMARY KEY(이름)                             -- 이름을 기본키로
);                                              -- CREATE TABLE 끝
INSERT INTO 주소록 VALUES('홍길동','010-1234-5678','서울','3월 15일');   -- 홍길동 · 서울
INSERT INTO 주소록 VALUES('이몽룡','010-3354-5643','부산','12월 14일');   -- 이몽룡 · 부산
INSERT INTO 주소록 VALUES('최용만','321-2345','대전','5월 8일');   -- 최용만 · 대전

-- (MySQL) safe mode 해제
SET SQL_SAFE_UPDATES = 0;                       -- 키 열 조건 없이 UPDATE · DELETE 해도 막지 않게 (MySQL Workbench 설정)

-- [지시사항] 이건우의 데이터를 입력하시오 (널 값)
INSERT INTO 주소록 VALUES('이건우','010-2132-2345', NULL, NULL);   -- 주소 · 생일 자리에 NULL 직접
-- ✍️ 둘다 같은말 (둘 중 하나만!)
INSERT INTO 주소록(이름,전화번호) VALUES('이건우','010-2132-2345');   -- 넣을 열만 → 나머지 NULL (위와 같은 결과 · 둘 다 하면 기본키 중복 오류)
```
> ⚠️ **정정** — ① “둘다 같은말” = 결과가 같은 **두 가지 방법**이라 **하나만** 실행해요. 둘 다 실행하면 기본키(이름) '이건우'가 겹쳐 **Error 1062 Duplicate entry** ② 필기의 `INSERT INTO주소록(…)` 은 **띄어쓰기가 빠져 Error 1064**(문법 오류) → `INSERT INTO 주소록(…)`

```sql
-- ✍️ 내 답
-- 1. 홍길동의 전화번호를 '010-3245-4368' 로 수정하라
UPDATE 주소록                 -- 주소록의 값을 고친다
SET 전화번호="010-3245-4368"   -- 전화번호를 새 값으로
WHERE 이름='홍길동';            -- 이름이 홍길동인 행만 (WHERE 가 없으면 모든 행이 바뀜)

-- 2. 이건우의 주소는 '서울', 생일은 '8월 23일' 로 수정하라
UPDATE 주소록                 -- 주소록의 값을 고친다
SET 주소='서울',생일='8월23일'          -- 여러 필드는 쉼표로
WHERE 이름='이건우';            -- 이름이 이건우인 행만

-- 3. 최용만의 레코드를 삭제하라
DELETE                     -- 행을 지운다
FROM 주소록                   -- 주소록에서 (조건은 다음 줄 WHERE)
WHERE 이름='최용만';  -- ✍️ 최용만의 이름말고 전화번호,주소 같은것을 WHERE절에 적어도 이상없이 작동함

SELECT * FROM 주소록;         -- 확인 → 최용만은 없고 홍길동 · 이건우 값이 바뀐 결과
```
1 · 2 · 3 실행 후 결과

| 이름 | 전화번호 | 주소 | 생일 |
|---|---|---|---|
| 이건우 | 010-2132-2345 | 서울 | 8월23일 |
| 이몽룡 | 010-3354-5643 | 부산 | 12월 14일 |
| 홍길동 | 010-3245-4368 | 서울 | 3월 15일 |

> ✍️ **필기** — **DELETE 주의사항**: 레코드 단위(한 줄)로 하는 것이라서 **필드명 또는 `*` 을 안 써도 됨** — SELECT · UPDATE 처럼 필드 단위가 아님 (`DELETE * FROM …` ❌)
> ⚠️ **정정** — WHERE 에 전화번호 · 주소를 써도 작동은 하지만, 그 값이 **여러 행에 있으면 전부 지워져요** (예: 2번 뒤 `WHERE 주소='서울'` → 홍길동 · 이건우 2명 삭제). 한 명만 지우려면 **기본키(이름)** 로 지정하는 게 안전해요.

## 5. 무결성 제약조건 4가지 ★시험 ✍️
> 🛡️ **무결성(integrity)** = 데이터의 **정확성** · 제약조건 = constraint

| # | 제약조건 | 내용 | SQL | ✍️ 범위 |
|---|---|---|---|---|
| 1 | **개체 무결성** (엔티티 무결성) | **기본키는 널 값을 가질 수 없다** | `PRIMARY KEY` | **중간 O** |
| 2 | **참조 무결성** ★시험문제 | **참조하는** 테이블의 **외래키** 값은 **참조되는** 테이블의 **기본키** 값에 반드시 존재해야 한다 | `FOREIGN KEY` | **중간 O** |
| 3 | 키 제약조건 | 키는 중복된 값을 갖지 않는다 | `UNIQUE` | 기말 |
| 4 | 도메인 제약조건 | 값의 범위 · 기본값 지정 | `CHECK` · `DEFAULT` | 기말 |

> ✍️ **필기** — 꼭 **“개체”** 라고 써야 함. **“객체”라고 쓰면 오답**
> ✍️ **필기** — 참조 무결성 **빈칸(시험문제!)** · 참조**“하는”** 테이블의 **“외래키”** 값은 참조**“되는”** 테이블의 **“기본키”** 값에 반드시 있어야 한다 → **하는 = 자식(외래키)** · **되는 = 부모(기본키)**
> ⚠️ **정정** — 필기 철자 `intergrity constranint` → **integrity constraint** · `PRIMART KEY` → **PRIMARY KEY** · `FORIGEN KEY` → **FOREIGN KEY**

### 참조 무결성 — 부모 · 자식 테이블에서 검사하는 것 (7 · 24p)
| | 부모 테이블 (참조**되는** · 기본키) | 자식 테이블 (참조**하는** · 외래키) |
|---|---|---|
| **입력** | **제약 없음** (✍️ O) | 부모 테이블에 그 값이 있는지 검증 |
| **수정** | 수정하려는 값을 자식이 참조하고 있는지 검증 | 부모에 있는 **다른 값으로만** 변경 가능 |
| **삭제** | 삭제하려는 값을 자식이 참조하고 있는지 검증 | **제약 없음** (✍️ O) |

> ✍️ **필기** — 필기 표의 **O 두 칸(부모 입력 · 자식 삭제) = “제약 없음”** 칸이에요.

### [Quiz] 25p — 참조 무결성 만족 여부를 **검사할 필요가 있는** 항목에 O
| | INSERT | UPDATE | DELETE |
|---|---|---|---|
| 외래키에 의해 참조되는 기본키 (부모) | | **O** | **O** |
| 외래키 (자식) | **O** | **O** | |

> ⚠️ **정정** — 필기 표는 **부모 INSERT · 자식 DELETE** 에 O 를 쳤는데, 그 두 칸은 **검사할 필요가 없는(제약 없음)** 칸이에요. 25p 문제는 검사할 필요가 **“있는”** 항목에 O → 정답은 **부모 UPDATE · DELETE, 자식 INSERT · UPDATE**. 실제로 실행해 보면 이 4가지에서만 오류가 나요 (아래 6번).

## 6. [실습 6-03] 참조 무결성 — 부서 · 사원 (📸 8 · 9p 캡처) ★시험예상
```sql
-- 부서(부서코드, 부서명)          ← 부모 테이블
-- 사원(사원번호, 이름, 부서코드)    ← 자식 테이블 (부서코드 = 외래키)
drop table 사원;      -- 삭제는 자식 먼저
drop table 부서;                                  -- 그다음 부모(부서) 삭제

CREATE TABLE 부서 (                -- 생성은 부모 먼저
        부서코드 char(2)     NOT NULL ,             -- 부서코드 — 문자 2자리 · 필수
        부서명    varchar(10) ,                    -- 부서명 — 최대 10자
        PRIMARY KEY(부서코드)                       -- 부서코드를 기본키로
);                                              -- CREATE TABLE 끝
CREATE TABLE 사원 (                               -- 사원 테이블(자식) 만들기 시작
        사원번호 char(4)     NOT NULL ,             -- 사원번호 — 문자 4자리 · 필수
        이름     varchar(12) ,                    -- 이름 — 최대 12자
        부서코드 char(2) ,                          -- 부서코드 — 부서 테이블을 가리킬 열
        PRIMARY KEY(사원번호) ,                     -- 사원번호를 기본키로
        FOREIGN KEY (부서코드) REFERENCES 부서(부서코드)  -- 외래키 — 부서 테이블에 있는 부서코드만 넣을 수 있음
);                                              -- CREATE TABLE 끝
insert into 부서 values('AA','총무부');              -- AA 총무부
insert into 부서 values('BB','영업부');              -- BB 영업부
insert into 부서 values('CC','기획부');              -- CC 기획부

insert into 사원 values('1111','홍길동','AA');       -- 홍길동 → AA(총무부)
insert into 사원 values('2222','임꺽정','AA');       -- 임꺽정 → AA
insert into 사원 values('3333','박찬호','BB');       -- 박찬호 → BB(영업부)
insert into 사원 values('4444','선동열','BB');       -- 선동열 → BB
insert into 사원 values('5555','차두리','AA');       -- 차두리 → AA
insert into 사원 values('6666','신동엽','BB');       -- 신동엽 → BB
```
“다음 문법을 실행하라. 실행 가능한가? 그 이유는?” — 위에서부터 차례로 실행한 실제 결과

| 번호 | SQL | 결과 | 이유 |
|---|---|---|---|
| **1-1** | `INSERT INTO 사원 VALUES('7777','이승엽','BB');` | ✅ 성공 | 자식 입력 — 부서에 **BB 가 있음** |
| **1-2** | `UPDATE 부서 SET 부서코드='DD' WHERE 부서코드='BB';` | ❌ Error 1451 | 부모 수정 — 사원이 **BB 를 참조 중** |
| **1-3** | `INSERT INTO 부서 VALUES('DD','개발부');` | ✅ 성공 | 부모 입력 — **제약 없음** |
| **1-4** | `DELETE FROM 부서 WHERE 부서코드='DD';` | ✅ 성공 | 부모 삭제 — DD 를 **참조하는 사원이 없음** |
| **1-5** | `UPDATE 사원 SET 부서코드='AA' WHERE 사원번호='7777';` | ✅ 성공 | 자식 수정 — 부모에 있는 **다른 값(AA)** 으로 변경 |
| **1-6** | `UPDATE 사원 SET 부서코드='FF' WHERE 사원번호='7777';` | ❌ Error 1452 | 자식 수정 — 부서에 **FF 가 없음** |
| **1-7** | `DELETE FROM 사원 WHERE 사원번호='7777';` | ✅ 성공 | 자식 삭제 — **제약 없음** |

> 🧾 **1451** Cannot delete or update a **parent** row (부모 쪽 수정 · 삭제) · **1452** Cannot add or update a **child** row (자식 쪽 입력 · 수정)

## 7. 수강 테이블의 키 (📸 19p 캡처) ✍️
| 학번 | 과목번호 | 성적 |
|---|---|---|
| 1111 | CS100 | 98 |
| 1111 | CS102 | 88 |
| 2222 | CS102 | 90 |
| 3333 | CS100 | 92 |

```text
-- 수강(학번, 과목번호, 성적)       ✍️ 내 답
1. 수퍼키 : (학번, 과목번호) , (학번, 과목번호, 성적)
2. 후보키 : (학번, 과목번호)
3. 기본키 : (학번, 과목번호)       ← 빨간 글씨 20p PRIMARY KEY(학번, 과목번호)
4. 대체키 : 없다
```
> 🤖 **설명** (필기 “claude야 여기 설명해”) — 학번 하나로는 X(1111 이 두 번) · 과목번호 하나로도 X(CS102 · CS100 이 두 번씩) → **(학번, 과목번호)** 를 합치면 모든 행이 달라 **유일성 O**, 하나라도 빼면 겹치니 **최소성 O** → **후보키**. 후보키가 **하나뿐**이라 그대로 **기본키**(복합키), 기본키로 안 뽑힌 후보키가 없으니 **대체키는 없다**. 수퍼키는 **유일성만** 있으면 돼서 성적을 붙인 것도 수퍼키 — 내 답 모두 맞아요 ✅ · 외래키: 수강.학번 → 학생.학번 · 수강.과목번호 → 과목.과목번호

> ❓ **“다음은 후보키인가? 이유를 쓰시오 — (학번, 과목번호, 성적)”** → **후보키가 아니다.** 유일성은 있지만 성적을 빼도 (학번, 과목번호) 만으로 유일하게 구별되므로 **최소성을 만족하지 않는다** → 후보키가 아니라 **수퍼키**.
> ⚠️ **함정** — 지금 데이터만 보면 성적(98 · 88 · 90 · 92)도 안 겹치지만, 성적은 같은 점수가 나올 수 있는 값이라 키가 될 수 없어요. 키는 **속성의 의미**로 정해요.

## 8. 용어 — 같은 말 찾기 · 쓰기 (중간고사 용어문제) ✍️
| ✍️ 외우는 법 | 같은 말 |
|---|---|
| — | **테이블 = 릴레이션**(relation) |
| **투레행** | **투플**(tuple) = **레코드**(record) = **행**(row) |
| **필속열** | **필드**(field) = **속성**(attribute · 애트리뷰트) = **열**(column) = 컬럼 |
| 차수(degree) | **필드(열)의 개수** |
| 카디날리티(cardinality) | **레코드(행)의 개수** |

> ✍️ **필기** — 투플(행)들의 **모음 = 인스턴스** · **DELETE 의 삭제 단위 = 레코드(행)** (필기의 `DELECT` 는 DELETE 오타)
> 📸 **13p 캡처** — 릴레이션 **스키마** = **내포**(intension) · **정적** / 릴레이션 **인스턴스** = **외연**(extension) · **동적** · 예) 사원 스키마 = `사원번호 | 사원명 | 연락처 | 생일`, 인스턴스 = D001 · D002 · D003 행들
