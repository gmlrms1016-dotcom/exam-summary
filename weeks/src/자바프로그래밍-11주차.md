## 1. 메소드 오버라이딩 — 부모 메소드를 자식이 다시 쓰기 (5장 32 · 35 · 41쪽)
| 말 | 뜻 (5장) |
|---|---|
| **메소드 오버라이딩** (Method Overriding) | 슈퍼 클래스의 메소드를 **서브 클래스에서 재정의** — 메소드의 **이름 · 매개변수 타입 및 개수 · 리턴 타입** 등 모든 것을 **동일하게** 작성 (32쪽) |
| 다른 번역 | 메소드 무시하기 · 덮어쓰기 (32쪽) |
| 일어나는 일 | **동적 바인딩** — 서브 클래스에 오버라이딩된 메소드가 **무조건 실행** (32쪽 · 아래 2번) |
| 목적 = **다형성** | 같은 이름(`draw()`)인데 Line 은 선 · Circle 은 원 · Rect 는 사각형을 그림 — “하나의 인터페이스(같은 이름)에 서로 다른 내용 구현” (35쪽) |
| `@Override` 🤖 | 컴파일러에게 “오버라이딩이에요” 라고 알리는 표시 — 이름 · 매개변수가 부모와 다르면 `method does not override or implement a method from a supertype` 로 잡아 줌 · **붙이는 건 선택**(빼도 오버라이딩은 됨 · 실수를 잡으려고 붙이는 관례) |

### ① Weapon → Cannon (수업 파일 Overriding.java · 5장 41쪽 예제 5-6)
```java
// Overriding.java — 메소드 오버라이딩 · 기본 무기 1 → 대포 10 (5장 41쪽 예제 5-6)
class Weapon {                                  // 슈퍼 클래스 — 기본 무기
    protected int fire() {                      // 살상 능력을 돌려주는 메소드
        return 1;                               // 기본 무기 → 1
    }                                           // fire 끝
}                                               // Weapon 끝
class Cannon extends Weapon {                   // 서브 클래스 — 대포 (Weapon 상속)
    @Override                                   // 부모 fire() 를 다시 쓴다는 표시 (이름 · 매개변수가 다르면 컴파일 오류로 알려 줌)
    protected int fire() {                      // 이름 · 매개변수 · 리턴 타입이 부모와 같음 → 오버라이딩
        return 10;                              // 대포 → 10
    }                                           // fire 끝
}                                               // Cannon 끝
public class 연습 {                              // 원래 이름 Overriding → 파일 이름도 연습.java
    public static void main(String[] args) {    // 프로그램 시작
        Weapon weapon;                          // 슈퍼 클래스 타입 레퍼런스 변수 (아직 객체 없음)
        weapon = new Weapon();                  // Weapon 객체를 가리킴
        System.out.println("기본 무기의 살상 능력은 " + weapon.fire());   // Weapon 의 fire() → 1 → "기본 무기의 살상 능력은 1"
        weapon = new Cannon();                  // 같은 변수가 이제 Cannon 객체를 가리킴 (업캐스팅)
        System.out.println("대포의 살상 능력은 " + weapon.fire());     // 변수 타입은 Weapon 이지만 실제 객체는 Cannon → 오버라이딩된 fire() → 10
    }                                           // main 끝
}                                               // 연습 끝
```
```output
기본 무기의 살상 능력은 1
대포의 살상 능력은 10
```

### ② Animal → Dog · Cat (수업 파일 Main.java)
```java
// Main.java — 부모 타입 변수로 자식 객체를 가리키고 sound() 호출 (수업 예제 Animal → Dog · Cat)
class Animal {                                  // 슈퍼 클래스
    void sound() {                              // 기본 소리
        System.out.println("소리를 냅니다.");      // 부모 버전 (이 예제에서는 안 불림)
    }                                           // sound 끝
}                                               // Animal 끝
class Dog extends Animal {                      // Animal 상속
    @Override                                   // 부모 sound() 를 다시 씀
    void sound() {                              // 이름 · 매개변수 같음
        System.out.println("멍멍 소리를 냅니다.");  // Dog 버전
    }                                           // sound 끝
}                                               // Dog 끝
class Cat extends Animal {                      // Animal 상속
    @Override                                   // 부모 sound() 를 다시 씀
    void sound() {                              // 이름 · 매개변수 같음
        System.out.println("미야오 소리를 냅니다."); // Cat 버전
    }                                           // sound 끝
}                                               // Cat 끝
public class 연습 {                              // 원래 이름 Main → 파일 이름도 연습.java
    public static void main(String[] args) {    // 프로그램 시작
        Animal a1 = new Dog();                  // 부모 타입 변수 a1 → 실제 객체는 Dog (업캐스팅)
        a1.sound();                             // 실제 객체 Dog 의 sound() → "멍멍 소리를 냅니다."
        Animal a2 = new Cat();                  // 부모 타입 변수 a2 → 실제 객체는 Cat
        a2.sound();                             // 실제 객체 Cat 의 sound() → "미야오 소리를 냅니다."
    }                                           // main 끝
}                                               // 연습 끝
```
```output
멍멍 소리를 냅니다.
미야오 소리를 냅니다.
```

| 이렇게 쓰면 (🤖 javac 로 확인) | 결과 |
|---|---|
| 자식에서 접근 범위를 **좁힘** — `private int fire()` (부모는 protected) | 컴파일 오류 `fire() in Cannon cannot override fire() in Weapon` · `attempting to assign weaker access privileges; was protected` |
| `@Override` 를 붙였는데 매개변수가 다름 — `protected int fire(int n)` | 컴파일 오류 `method does not override or implement a method from a supertype` |
| `@Override` 없이 같은 모양으로 씀 | 오버라이딩 됨 (결과 같음) — `@Override` 는 선택 |

## 2. 동적 바인딩 · super · 오버라이딩 vs 오버로딩 (5장 35 · 39 · 40 · 42쪽)
| 말 | 뜻 (5장) |
|---|---|
| **동적 바인딩** | 실행할 메소드를 **실행 시(run time)에 결정** — 오버라이딩 메소드가 **항상** 호출 (39쪽) |
| 부모 메소드 안에서 부른 메소드도 | 39쪽 그림 — Shape 의 `paint()` 안에서 `draw()` 를 불러도 **실제 객체가 Circle 이면 Circle 의 draw()** |
| **super** | 슈퍼 클래스의 멤버를 접근할 때 쓰는 레퍼런스 · **서브 클래스에서만** 사용 · 슈퍼 클래스의 메소드 호출 · 컴파일러는 super 의 접근을 **정적 바인딩**으로 처리 (40쪽 · 10주차 TV 의 `super.printInfo()`) |
| 다형성 | 오버라이딩 = **실행 시간** 다형성 (동적 바인딩) · 오버로딩 = **컴파일 타임** 다형성 (35쪽) |

```java
// 동적 바인딩 — paint() 안의 draw() 도 실제 객체의 것이 불림 (5장 39쪽 그림 코드)
class Shape {                                   // 슈퍼 클래스
    public void paint() {                       // 그리기
        draw();                                 // 여기 draw() 는 ‘지금 이 객체’의 draw() → 실행할 때 정해짐
    }                                           // paint 끝
    public void draw() {                        // 부모 버전
        System.out.println("Shape");            // "Shape"
    }                                           // draw 끝
}                                               // Shape 끝
class Circle extends Shape {                    // Shape 상속
    @Override                                   // draw() 를 다시 씀
    public void draw() {                        // 자식 버전
        System.out.println("Circle");           // "Circle"
    }                                           // draw 끝
}                                               // Circle 끝
public class 연습 {                              // 39쪽은 Shape · Circle 에 main 이 따로 → 한 파일로 합침
    public static void main(String[] args) {    // 프로그램 시작
        Shape a = new Shape();                  // Shape 객체
        a.paint();                              // Shape 의 paint() → draw() → 객체가 Shape → Shape 의 draw() → "Shape"
        Shape b = new Circle();                 // 변수 타입은 Shape · 실제 객체는 Circle
        b.paint();                              // paint() 는 부모 것 → 그 안의 draw() 는 실제 객체 Circle 의 draw() (동적 바인딩) → "Circle"
    }                                           // main 끝
}                                               // 연습 끝
```
```output
Shape
Circle
```

### 오버로딩 vs 오버라이딩 (42쪽 표)
| 비교 요소 | 메소드 **오버로딩** | 메소드 **오버라이딩** |
|---|---|---|
| 선언 | 같은 클래스나 상속 관계에서 **동일한 이름의 메소드 중복 작성** | 서브 클래스에서 슈퍼 클래스에 있는 메소드와 **동일한 이름의 메소드 재작성** |
| 관계 | 동일한 클래스 내 혹은 상속 관계 | **상속 관계** |
| 목적 | 이름이 같은 여러 개의 메소드를 중복 작성하여 사용의 편리성 향상 · 다형성 실현 | 슈퍼 클래스에 구현된 메소드를 무시하고 서브 클래스에서 새로운 기능의 메소드를 재정의 · 다형성 실현 |
| 조건 | 메소드 이름은 반드시 동일하고, **매개변수 타입이나 개수가 달라야** 성립 | 메소드의 이름, 매개변수 타입과 개수, **리턴 타입이 모두 동일**하여야 성립 |
| 바인딩 | **정적** 바인딩 — 호출될 메소드는 **컴파일 시**에 결정 | **동적** 바인딩 — **실행 시간**에 오버라이딩된 메소드 찾아 호출 |

## 3. 추상 메소드 · 추상 클래스 (5장 43 ~ 50쪽)
| 말 | 뜻 (5장) |
|---|---|
| **추상 메소드** (abstract method) | 선언되어 있으나 **구현되어 있지 않은** 메소드 · `abstract` 로 선언 · 몸체 `{ }` 없이 `;` 로 끝 · **서브 클래스에서 오버라이딩하여 구현**해야 함 (43쪽) |
| **추상 클래스** 2종류 (43쪽) | ① 추상 메소드를 **하나라도 가진** 클래스 → 클래스 앞에 **반드시 abstract** ② 추상 메소드가 하나도 없지만 abstract 로 선언된 클래스 |
| 객체 생성 | **추상 클래스는 객체를 생성할 수 없다** — `new Shape()` 컴파일 오류 (45쪽) · 레퍼런스 변수 선언은 가능 |
| 상속 2가지 (46쪽) | ① **단순 상속** — 추상 메소드를 구현하지 않으면 서브 클래스도 추상 클래스 → abstract 로 선언해야 함 ② **구현 상속** — 서브 클래스에서 추상 메소드를 구현(오버라이딩) → 서브 클래스는 추상 클래스 아님 |
| 용도 (48쪽) | **설계와 구현 분리** — 슈퍼 클래스에서는 개념 정의 · 서브 클래스마다 다른 구현이 필요한 메소드는 추상 메소드로 선언 → 각 서브 클래스에서 구체적 행위 구현 |

### Calculator → GoodCal (수업 파일 CalcMain.java · 5장 49 · 50쪽 예제 5-7)
```java
// CalcMain.java — 추상 클래스 Calculator 의 추상 메소드 3개를 GoodCal 이 구현 (5장 49 · 50쪽 예제 5-7)
abstract class Calculator {                     // 추상 클래스 — abstract 메소드가 있으니 클래스 앞에도 abstract 필수
    abstract int add(int a, int b);             // 추상 메소드 — 몸체 없이 ; → 자식이 꼭 구현
    abstract int subtact(int a, int b);         // 수업 파일 그대로 subtact (교재는 subtract) — 부모 · 자식 이름만 같으면 문제없음
    abstract double average(int[] arr);         // 배열 평균 → double
}                                               // Calculator 끝
class GoodCal extends Calculator {              // 추상 클래스 상속 → 추상 메소드 3개를 모두 구현해야 일반 클래스
    @Override                                   // add 구현
    int add(int a, int b) {                     // a=2, b=3
        return a + b;                           // 2 + 3 → 5
    }                                           // add 끝
    @Override                                   // subtact 구현
    int subtact(int a, int b) {                 // a=2, b=3
        return a - b;                           // 2 - 3 → -1
    }                                           // subtact 끝
    @Override                                   // average 구현
    double average(int[] arr) {                 // arr = {2, 3, 4}
        double sum = 0;                         // 합계를 double 로 → 나눗셈도 실수 나눗셈
        for (int i = 0; i < arr.length; i++) {  // i = 0, 1, 2
            sum += arr[i];                      // 0 → 2 → 5 → 9
        }                                       // for 끝 → sum = 9.0
        return sum / arr.length;                // 9.0 / 3 → 3.0
    }                                           // average 끝
}                                               // GoodCal 끝
public class 연습 {                              // 원래 이름 CalcMain → 파일 이름도 연습.java
    public static void main(String[] args) {    // 프로그램 시작
        GoodCal c = new GoodCal();              // 구현한 클래스로 객체 생성 (new Calculator() 는 컴파일 오류)
        System.out.println(c.add(2, 3));        // 5
        System.out.println(c.subtact(2, 3));    // -1
        System.out.println(c.average(new int[] {2, 3, 4}));   // 배열을 그 자리에서 만들어 넘김 → 9.0 / 3 → 3.0
    }                                           // main 끝
}                                               // 연습 끝
```
```output
5
-1
3.0
```

| 이렇게 쓰면 (🤖 javac 로 확인) | 결과 |
|---|---|
| `Calculator c = new Calculator();` | 컴파일 오류 `Calculator is abstract; cannot be instantiated` (45쪽) |
| 추상 메소드 하나만 구현 — `class Half extends Calculator { int add(…) {…} }` | 컴파일 오류 `Half is not abstract and does not override abstract method …` → 다 구현하거나 `abstract class Half` 로 (46쪽 ①) |
| 일반 클래스에 추상 메소드 — `class Shape { abstract public void draw(); }` | 컴파일 오류 (클래스 앞에 abstract 가 없어서) |
| 추상 메소드 없이 `abstract class Shape { … }` | 됨 (43쪽 ② — 객체만 못 만듦) |

## 4. 인터페이스 — 정해진 규격 · implements (5장 51 ~ 57쪽)
| 말 | 뜻 (5장) |
|---|---|
| 실세계의 인터페이스 (51쪽) | 정해진 **규격**에 맞기만 하면 연결 가능 · 각 회사마다 구현 방법은 다름 · 규격에 맞지 않으면 연결 불가 |
| **자바의 인터페이스** (52쪽) | 클래스가 **구현해야 할 메소드들이 선언되는 추상형** · `interface` 키워드로 선언 · 인터페이스에는 **필드(멤버 변수) 선언 불가** |
| 버전 (52쪽) | Java 7까지 = 상수 + 추상 메소드만 · Java 8부터 **default** 메소드 · Java 9 private 메소드 · static 메소드 |
| **implements** (56쪽) | 인터페이스의 추상 메소드를 **모두 구현한** 클래스 작성 · 여러 개의 인터페이스 **동시 구현 가능** |

| 인터페이스 구성 요소 (54쪽) | 특징 |
|---|---|
| **상수** | public 만 허용 · **`public static final` 생략** — `int TIMEOUT = 10000;` |
| **추상 메소드** | **`public abstract` 생략 가능** — `void sendCall();` |
| **default 메소드** | 인터페이스에 코드가 작성된 메소드 · 구현하는 클래스에 **자동 상속** · public 만 허용(생략 가능) |
| private 메소드 | 인터페이스 안에 코드가 있어야 함 · 인터페이스 안의 다른 메소드에서만 호출 |
| static 메소드 | public · private 모두 지정 가능 · 생략하면 public |

> ⚠️ **팩트체크** — 52쪽은 static 메소드를 “Java 9” 줄에 적었는데, 인터페이스의 **static 메소드는 Java 8**부터 돼요 (default 와 같이 들어옴 · 이 맥의 Java 8 javac 로 컴파일 확인). Java 9 에 새로 들어온 건 **private** 메소드예요.

## 5. 인터페이스 상속 · 다중 구현 — SmartPhone (수업 파일 InterfaceEx.java · 5장 58 ~ 61쪽 예제 5-9)
| 말 | 뜻 (5장) |
|---|---|
| **인터페이스 상속** (58쪽) | 인터페이스가 다른 인터페이스를 상속 — **extends** 키워드 · **다중** 인터페이스 상속 가능 (`interface MusicPhoneInterface extends MobilePhoneInterface, MP3Interface`) |
| **다중 인터페이스 구현** (60쪽) | 클래스는 **하나 이상의 인터페이스를 구현**할 수 있음 · 클래스에서 인터페이스의 메소드를 구현할 때 **public 을 생략하면 오류** |

```java
// InterfaceEx.java — 인터페이스 상속(extends) + 클래스 상속과 인터페이스 다중 구현을 동시에 (5장 61쪽 예제 5-9)
interface PhoneInterface {                      // 기본 전화 규격 (PhoneInterface.java 와 같음)
    int TIMEOUT = 10000;                        // 상수 (public static final 생략)
    void sendCall();                            // 추상 메소드
    void receiveCall();                         // 추상 메소드
    default void printLogo() {                  // default 메소드 → 구현 클래스에 자동 상속
        System.out.println("** Phone **");      // 로고
    }                                           // printLogo 끝
}                                               // PhoneInterface 끝
interface MobilePhoneInterface extends PhoneInterface {   // 인터페이스가 인터페이스를 상속 → extends
    void sendSMS();                             // 새 추상 메소드 (sendCall · receiveCall 은 물려받음)

}                                               // MobilePhoneInterface 끝 → 추상 메소드 모두 4개
interface MP3Interface {                        // 음악 규격
    public void play();                         // public 을 써도 되고 생략해도 같음
    public void stop();                         // 추상 메소드
}                                               // MP3Interface 끝
class PDA {                                     // 보통 클래스
    public int calculate(int x, int y) {        // 계산기 기능
        return x + y;                           // 3 + 5 → 8
    }                                           // calculate 끝
}                                               // PDA 끝
class SmartPhone extends PDA implements MobilePhoneInterface, MP3Interface {   // 클래스 하나 상속 + 인터페이스 두 개 구현
    @Override                                   // PhoneInterface 에서 온 것
    public void sendCall() {                    // public 꼭
        System.out.println("따르릉따르릉~~");      // 전화 걸기
    }                                           // sendCall 끝
    @Override                                   // PhoneInterface 에서 온 것
    public void receiveCall() {                 // public
        System.out.println("전화 왔어요.");        // 전화 받기
    }                                           // receiveCall 끝
    @Override                                   // MobilePhoneInterface 에서 새로 생긴 것
    public void sendSMS() {                     // public
        System.out.println("문자 갑니다.");        // 문자 보내기
    }                                           // sendSMS 끝
    @Override                                   // MobilePhoneInterface 에서 새로 생긴 것
    public void receiveSMS() {                  // public
        System.out.println("문자 왔어요.");        // 문자 받기
    }                                           // receiveSMS 끝
    @Override                                   // MP3Interface 에서 온 것
    public void play() {                        // public
        System.out.println("음악 연주합니다.");     // 재생
    }                                           // play 끝
    @Override                                   // MP3Interface 에서 온 것
    public void stop() {                        // public
        System.out.println("음악 중단합니다.");     // 정지
    }                                           // stop 끝
    public void schedule() {                    // 인터페이스에 없는 SmartPhone 만의 메소드 추가

    }                                           // schedule 끝
}                                               // SmartPhone 끝 → 추상 메소드 6개를 모두 구현해서 일반 클래스

    public static void main(String[] args) {    // 프로그램 시작

## 6. 추상 클래스 vs 인터페이스 (5장 62쪽)
| | 추상 클래스 | 인터페이스 |
|---|---|---|
| 공통점 | 객체를 생성할 수 없고, 상속을 위한 슈퍼 클래스로만 사용 · 클래스의 **다형성**을 실현하기 위한 목적 | (같음) |
| 목적 | 서브 클래스에서 필요로 하는 대부분의 기능을 구현해 두고 서브 클래스가 상속받아 활용 · 서브 클래스에서 구현할 수밖에 없는 기능만 추상 메소드로 선언 | 객체의 기능을 모두 공개한 **표준화 문서**와 같은 것 · 인터페이스를 상속받는 클래스의 목적에 따라 **모든 추상 메소드를 만들도록** 함 |
| 구성 | 추상 메소드와 **일반 메소드** 모두 포함 · 상수, **변수 필드** 모두 포함 | **변수 필드(멤버 변수)는 포함하지 않음** · 상수 · 추상 메소드 · default 메소드 · static 메소드 · **protected 접근 지정 선언 불가** · **다중 상속 지원** |
| 키워드 (🤖) | `abstract class` · 자식은 `extends` (하나만) | `interface` · 클래스는 `implements` (여러 개) · 인터페이스끼리는 `extends` |

> ⚠️ **팩트체크** — 62쪽 인터페이스 구성 칸에 “일반 메소드” 도 적혀 있는데, 인터페이스에 **default 없이 몸체가 있는 메소드**를 쓰면 `interface abstract methods cannot have body` 컴파일 오류예요. 코드가 있는 메소드는 **default · static · private** 만 돼요 (54쪽 표와 같음).

// Main3.java — 3형식 [메서드 완성하기] 정답 (수업 파일 Main3.java)
interface Shape {                               // 도형 규격
    double calculateArea();                     // 면적을 돌려주는 추상 메소드
}                                               // Shape 끝
class Circle implements Shape {                 // 원

    @Override                                   // 수업 파일은 @Override 를 붙임 (문제지는 없음 · 선택)
    public double calculateArea() {             // public 꼭
        return radius * radius * Math.PI;       // [작성란] 5 × 5 × π → 78.53981633974483
    }                                           // calculateArea 끝
}                                               // Circle 끝
class Rectangle implements Shape {              // 사각형
    double width = 4;                           // 가로 4
    double height = 5;                          // 세로 5
    @Override                                   // 구현
    public double calculateArea() {             // public
        return width * height;                  // [작성란] 4.0 × 5.0 → 20.0 (double 끼리라 .0)
    }                                           // calculateArea 끝
}                                               // Rectangle 끝
public class 연습 {                              // 원래 이름 Main3 → 파일 이름도 연습.java
    public static void main(String[] args) {    // 프로그램 시작
        Shape myCircle = new Circle();          // 인터페이스 타입 변수 → Circle 객체
        Shape myRectangle = new Rectangle();    // 인터페이스 타입 변수 → Rectangle 객체
        System.out.println("원 면적: " + myCircle.calculateArea());       // Circle 의 것 → "원 면적: 78.53981633974483"
        System.out.println("사각형 면적: " + myRectangle.calculateArea()); // Rectangle 의 것 → "사각형 면적: 20.0"
    }                                           // main 끝
}                                               // 연습 끝
```
```output
원 면적: 78.53981633974483
사각형 면적: 20.0
```
> 힌트대로 `3.14` 를 쓰면 `radius * radius * 3.14` → **78.5** 가 나와요 (문제지 주석의 `78.5397...` 은 Math.PI 를 썼을 때).

### ③ 5형식 [전체 코딩하기] 5번 문제 — 요리하기 (문제 txt · 수업 파일 Main5.java)
> 📝 **교수님 메모** [문제] 아래의 요구사항을 읽고 인터페이스, 구현 클래스, 메인 메서드까지 전체 코드를 직접 작성하세요.
> 1. Cookable 인터페이스를 생성하고, 반환 타입이 없고 매개변수도 없는 cook() 메서드를 정의하세요.
> 2. Cookable 을 구현하는 RamenCooker 클래스를 만드세요. cook() 호출 시 "물을 끓이고 스프와 면을 넣습니다." 를 출력해야 합니다.
> 3. Cookable 을 구현하는 SteakCooker 클래스를 만드세요. cook() 호출 시 "고기를 굽습니다." 를 출력해야 합니다.
> 4. Main5 클래스의 main 메서드 안에서 Cookable 타입의 레퍼런스 변수를 사용하여 RamenCooker 객체와 SteakCooker 객체를 생성하고 cook() 메서드를 호출하세요.

<details>
<summary>정답 보기 — 전체 코드 + 실행</summary>

```java
// Main5.java — 5형식 [전체 코딩하기] 정답 (수업 파일 Main5.java)
interface Cookable {                            // 1. 인터페이스 Cookable
    void cook();                                // 반환 타입 void · 매개변수 없음 (public abstract 생략)
}                                               // Cookable 끝
class RamenCooker implements Cookable {         // 2. Cookable 구현
    @Override                                   // cook 구현
    public void cook() {                        // public 꼭
        System.out.println("물을 끓이고 스프와 면을 넣습니다.");   // 라면
    }                                           // cook 끝
}                                               // RamenCooker 끝
class SteakCooker implements Cookable {         // 3. Cookable 구현
    @Override                                   // cook 구현
    public void cook() {                        // public
        System.out.println("고기를 굽습니다.");    // 스테이크
    }                                           // cook 끝
}                                               // SteakCooker 끝
public class 연습 {                              // 4. 원래 이름 Main5 → 파일 이름도 연습.java
    public static void main(String[] args) {    // 프로그램 시작
        Cookable ramen = new RamenCooker();     // Cookable 타입 레퍼런스 변수 → RamenCooker 객체
        Cookable steak = new SteakCooker();     // Cookable 타입 레퍼런스 변수 → SteakCooker 객체
        ramen.cook();                           // "물을 끓이고 스프와 면을 넣습니다."
        steak.cook();                           // "고기를 굽습니다."
    }                                           // main 끝
}                                               // 연습 끝
```
```output
물을 끓이고 스프와 면을 넣습니다.
고기를 굽습니다.
```
