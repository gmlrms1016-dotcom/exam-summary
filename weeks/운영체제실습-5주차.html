3. cron — 정해진 시각에 반복 실행

💡 crond 서비스가 1분마다 /etc/crontab 을 보고, 시각이 맞는 줄의 명령을 실행합니다.

3-1. /etc/crontab 열어 보기

gnome-text-editor /etc/crontab
SHELL=/bin/bash
PATH=/sbin:/bin:/usr/sbin:/usr/bin
MAILTO=root

# For details see man 4 crontabs

# Example of job definition:
# .---------------- minute (0 - 59)
# |  .------------- hour (0 - 23)
# |  |  .---------- day of month (1 - 31)
# |  |  |  .------- month (1 - 12) OR jan,feb,mar,apr ...
# |  |  |  |  .---- day of week (0 - 6) (Sunday=0 or 7) OR sun,mon,tue,wed,thu,fri,sat
# |  |  |  |  |
# *  *  *  *  * user-name  command to be executed
칸뜻범위
1분 (minute)0 ~ 59
2시 (hour)0 ~ 23
3일 (day of month)1 ~ 31
4월 (month)1 ~ 12
5요일 (day of week)0 ~ 6 (일요일 = 0 또는 7)
6실행할 사용자예: root
7명령예: run-parts /etc/cron.monthly

3-2. 맨 아래에 한 줄 추가 ★

01 3 15 * * root run-parts /etc/cron.monthly
# 01 → 1분 · 3 → 3시 · 15 → 15일 · * → 매월 · * → 모든 요일 → 매월 15일 03:01 에 root 가 run-parts /etc/cron.monthly 실행
  • ✍️ 필기 매월 15일 새벽 3시 1분에 /etc/cron.monthly 디렉토리 안의 모든 파일을 실행하라는 의미
  • run-parts 디렉터리 → 그 디렉터리 안의 실행 권한이 있는 파일을 차례로 실행 (그래서 스크립트에 chmod 755 를 줌)
  • ⚠️ 정정 순서는 분 → 시 → 일. 01 15 3 * * 로 쓰면 매월 3일 15시 01분이 됩니다 (과제 캡처의 /etc/crontab 이 이렇게 되어 있었어요)

4. 월간 백업 스크립트 — mybackup.sh

cd /etc/cron.monthly
gnome-text-editor mybackup.sh
#!/bin/sh
set $(date)                    # date 결과를 띄어쓰기로 나눠 $1 $2 $3 … 에 차례로 넣음
fname="backup-$2$3tar.xz"      # $2 · $3 = date 결과의 두 번째 · 세 번째 칸 (월 · 일)
tar cfJ /backup/$fname /home   # c 묶기 · f 파일 이름 지정 · J xz 압축 → /home 을 묶어 /backup/$fname 으로 저장

4-1. 파일 이름이 어떻게 만들어지나 ★

화면 언어date 결과$2 · $3backup-$2$3tar.xz
한국어 (GUI 서버)2035. 01. 15. (월) 03:00:00 KST01. · 15.backup-01.15.tar.xz
영어 (Server(B))Mon Jan 15 03:00:00 AM KST 2035Jan · 15backup-Jan15tar.xz
  • 한국어 화면은 date 결과에 점(.) 이 붙어 있어서 → "backup-" + "01." + "15." + "tar.xz" → 우연히 backup-01.15.tar.xz 가 됨
  • 영어 화면은 점이 없어서 → backup-Jan15tar.xz → 확장자 앞 점이 빠짐 → fname="backup-$2$3.tar.xz" 로 고치면 backup-Jan15.tar.xz
  • (한국어 화면에서 점을 넣어 고치면 15. + .tar.xz → backup-01.15..tar.xz 처럼 점이 두 개가 됩니다)

4-2. 실행 권한 주기 · 저장 폴더 만들기

ls -l
합계 4
-rw-r--r-- 1 root root 77 10월  1일  14:38 mybackup.sh
chmod 755 mybackup.sh   # 7 = rwx (소유자) · 5 = r-x (그룹) · 5 = r-x (나머지) → 실행 권한이 생겨야 run-parts 가 실행함
ls -l
합계 4
-rwxr-xr-x 1 root root 77 10월  1일  14:38 mybackup.sh
mkdir /backup           # 백업을 저장할 폴더 — 없으면 tar 가 저장하지 못함
systemctl restart crond
  • ✍️ 필기 cannot access '/backup' : No such file or directory → /backup 폴더가 아직 없어서 나온 오류 → mkdir /backup 으로 해결 (Server(B) 캡처에서도 같은 오류 → mkdir 뒤 total 0)
  • ⚠️ 정정 GPT 질문 기록에는 "run-parts 는 .sh 처럼 확장자가 붙은 파일을 건너뛸 수 있다"고 되어 있지만, 그건 Debian · Ubuntu 의 run-parts 이야기입니다. 이번 Rocky Linux 실습에서는 mybackup.sh 그대로 백업 파일이 만들어졌어요 (아래 5번).

5. date 로 시계를 바꿔서 테스트

형식예뜻
date MMDDhhmmYYYYdate 01150200203501월 15일 02시 00분 2035년
date 0115030020352035년 1월 15일 03:00
date 0215030020352035년 2월 15일 03:00
date 011502002035       # 01 15 02 00 2035 → 1월 15일 02:00 (2035년)
2035. 01. 15. (월) 02:00:00 KST
systemctl restart crond
ls -l /backup           # 아직 02시 → 03:01 이 안 됐으니 백업 없음
합계 0
date 021503002035       # 2월 15일 03:00 → 1분 뒤 03:01 에 cron 이 실행
2035. 02. 15. (목) 03:00:00 KST
date 01503002035        # ✍️ 실수 — 숫자 11자리
date: 부적절한 날짜 `01503002035'
date 011503002035       # 12자리로 다시 → 1월 15일 03:00
ls -l /backup           # 2월 15일 03:01 에 만들어진 백업이 먼저 보임
합계 4
-rw-r--r-- 1 root root 668 2035년  2월 15일 backup-02.15.tar.xz
ls -l /backup           # 1분 뒤 (03:01) 다시 보기 → 1월 백업도 생김
합계 8
-rw-r--r-- 1 root root 668  1월 15일  03:01 backup-01.15.tar.xz
-rw-r--r-- 1 root root 668 2035년  2월 15일 backup-02.15.tar.xz
  • systemctl restart crond 는 서비스를 다시 켜는 것이지 백업을 바로 실행하지 않습니다 → 시계를 03:00 으로 맞추고 1분 기다리면 03:01 에 cron 이 실행
  • 1월 백업 시각이 03:01 → crontab 의 01 3 (3시 1분) 그대로
  • 바로 테스트하고 싶으면 run-parts /etc/cron.monthly 를 직접 실행 (GPT 질문 기록)
📸 노션 캡처 (Server(B) · 영어 화면) — date 021503002035 · date 011503002035 → systemctl restart crond → ls -l /backup 이 처음엔 No such file or directory → mkdir /backup → total 0. 시계를 뒤로 돌리자 systemd-journald … Time jumped backwards 메시지도 보입니다.

6. at — 딱 한 번만 예약

rdate -s time.bora.net     # 시간 서버 time.bora.net 의 시각으로 시스템 시계를 맞춤 (2035년 → 오늘로 되돌리기) · 2번에서 설치한 openrdate
at 4:00 am tomorrow        # 내일 새벽 4시에 한 번 실행할 명령 입력 시작
warning: commands will be executed using /bin/sh
at Fri Oct  2 04:00:00 2026
at> dnf -y update
at> reboot
at> <EOT>
job 1 at Fri Oct  2 04:00:00 2026
  • at> 에 명령을 한 줄씩 입력 → Ctrl + D 로 끝 (<EOT>) → 1번 작업으로 예약
at -l       # 예약 목록 → 1번 · 실행 시각 · 사용자
1	Fri Oct  2 04:00:00 2026 a root
atrm 1      # 1번 예약 취소
at -l       # 아무것도 안 나옴 → 취소됨
cronat
몇 번정해진 시각마다 반복한 번만
설정/etc/crontab 한 줄at 시각 → at> 에 명령 → Ctrl + D
확인 · 취소파일에서 줄 지우기at -l · atrm 번호
  • ✍️ 필기 CRON과 AT은 백업을 받는 명령어이다.
  • ⚠️ 정정 cron · at 은 작업을 예약하는 명령입니다. 백업은 오늘 예약한 작업의 예일 뿐이고, 같은 방법으로 업데이트(dnf -y update) · 재부팅(reboot) 같은 어떤 명령이든 예약할 수 있어요.
