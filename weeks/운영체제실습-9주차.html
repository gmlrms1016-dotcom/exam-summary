1. 수업 실습 — Server 에 10GB 디스크 → /mydata → /etc/fstab

흐름 한눈에

(VM 끄고) 디스크 추가 → 부팅 → ls -l /dev/sd*  (새 디스크 sdb 확인)
→ fdisk /dev/sdb      (파티션 sdb1 만들기)
→ mkfs.ext4 /dev/sdb1 (ext4 로 포맷)
→ mkdir /mydata → mount /dev/sdb1 /mydata  (연결)
→ vi /etc/fstab       (자동 마운트 등록) → reboot → df 로 확인

1-1. [보충] VMware 에서 SCSI 디스크 추가 (VM 끈 상태)

📖 교재 실습 17 Step 0 — “[Edit virtual machine settings] 를 클릭한다. [Virtual Machine Settings] 창이 열리면 새로운 10GB 크기의 SCSI 디스크를 하나 장착한다.”

  1. Server 를 끈다 — poweroff (또는 VMware 의 Power Off). 디스크는 VM 이 꺼진 상태에서 붙이는 게 교재 순서
  2. VM 탭 → Edit virtual machine settings → 아래 Add… → Hard Disk → Next
  3. 디스크 종류 SCSI → Create a new virtual disk
  4. 크기 10 GB (과제 1 은 3 GB · 과제 2 는 10 GB) → Next → Finish → OK
  5. Server 를 켜고 root 로 로그인 → 아래 1-3 처럼 ls -l /dev/sd* 로 새 디스크 확인
  • ⚠️ 어느 VM 에 붙이는지 꼭 확인 — 과제 1 때 Server(B) 가 아니라 Server 에 붙이는 실수를 했음 (2절)

1-2. 디스크 추가 전 — 지금 있는 디스크 보기

  • ls -l /dev/sd* — 디스크 장치 파일 목록. sd = SCSI · SATA 디스크, 뒤 글자 a · b · c = 디스크 순서, 숫자 = 파티션 번호 (sda2 = 첫째 디스크의 2번 파티션)
    • 맨 앞 b = 블록 장치(디스크처럼 덩어리로 읽고 쓰는 장치) · 8, 0 = 장치 번호 (8 = SCSI 디스크 · 0 = sda, 디스크마다 16씩 → sdb = 16 · sdb1 = 17)
  • mount (옵션 없이) — 지금 마운트된 것 전부 출력. 첫 줄 /dev/sda2 on / type xfs → 루트(/)는 sda2 · xfs 파일 시스템
  • 지금은 디스크가 sda 하나(파티션 sda1 · sda2)뿐

1-3. 디스크 추가 후 — sdb 가 생김

  • 새 디스크 = /dev/sdb (8, 16) — 아직 파티션이 없어서 sdb1 같은 숫자 붙은 이름이 없음
  • mount 결과는 그대로 → sdb 는 아직 어디에도 연결 안 됨

1-4. fdisk 로 파티션 1개 만들기

입력어느 질문에서뜻
nCommand (m for help)new — 새 파티션 만들기
pSelect (default p)primary — 주 파티션 (MBR 디스크는 주 파티션 최대 4개 → 4 free)

dCommand (m for help)delete — 파티션 지우기 (과제 1 에서 잘못 나눈 걸 지울 때)
wCommand (m for help)write — 디스크에 저장하고 끝
[보충] qCommand (m for help)저장하지 않고 끝 (실수했을 때 처음부터)

  • ⚠️ p 는 질문에 따라 뜻이 달라요 — Select 에서는 primary, Command 에서는 print
  • 출력 첫머리 “Changes will remain in memory only, until you decide to write them.” → w 를 누르기 전에는 디스크가 안 바뀜 (그래서 d · q 로 되돌릴 수 있음)
  • Disklabel type: dos = MBR 방식 · Id 83 Linux = 리눅스용 파티션

1-5. sdb1 확인 → ext4 로 포맷

  • 이제 /dev/sdb1 (8, 17) 이 보임 = 파티션이 만들어짐
  • mkfs.ext4 /dev/sdb1 — 파티션에 ext4 파일 시스템을 만듦 (= 포맷 · 안의 내용은 지워짐) · 2621184 4k blocks = 약 10GB
  • Filesystem UUID: 0c9daa77-… = 이 파일 시스템의 고유 번호 → 장치 이름이 바뀌어도 그대로라 fstab 에 쓰기 좋음 (5절 예방법)
  • 🤖 포맷하면 lost+found 디렉터리가 생겨요 (파일 시스템 검사(fsck)가 되살린 파일을 넣는 곳) → 마운트 뒤 ls 에 보이는 이유
  • ⚠️ 파티션(/dev/sdb1)을 포맷해야 해요. /dev/sdb(디스크 전체)를 포맷하면 방금 만든 파티션 표가 덮어써짐 (5절 기타 실수)

1-6. 마운트할 디렉터리 만들기 · cp 실수 3번

  • mkdir /mydata — 디스크를 연결할 빈 디렉터리(마운트 포인트) · 맨 앞 / = 루트 바로 아래 (절대경로)
  • ❌ cp anaconda-ks.cfg mydata/test1 — 앞에 / 가 빠져 상대경로 → 지금 위치(~ = /root) 기준 /root/mydata/test1 이 됨 → /root/mydata 가 없어서 “일반 파일을 만들 수 없습니다: 그런 파일이나 디렉터리가 없습니다”
  • ❌ cp anaconda-ks.cfg/mydata/test1 — 띄어쓰기가 빠져 인자가 하나로 붙음 → cp 는 원본 · 대상 2개가 필요해서 “다음 대상 파일 피연산자 빠짐”
  • ❌ 같은 상대경로 실수를 한 번 더 → 같은 오류
  • ✅ cp anaconda-ks.cfg /mydata/test1 — 원본(지금 위치의 anaconda-ks.cfg) · 대상(/mydata/test1) 둘 다 제대로
    • 🤖 anaconda-ks.cfg = 설치할 때 /root 에 생긴 설치 설정 파일 → 실습에서는 복사해 보는 연습용 파일
  • ls -k /mydata/ — ⚠️ -l 을 치려다 -k 로 친 것으로 보여요. -k 는 크기를 KB 단위로 세는 옵션이라 -l 없이 쓰면 이름만 나옴 → test1
  • 🤖 test1 은 아직 마운트 전이라 루트 디스크(sda2)의 /mydata 에 저장됨 → 다음 단계에서 중요

1-7. 마운트 → test1 이 사라지고, umount → 다시 보임

  • mount /dev/sdb1 /mydata — sdb1 을 /mydata 에 연결. 이제 /mydata 로 들어가면 sdb1 의 내용이 보임
  • ls -l (위치 없이) = 지금 위치 /root 의 목록 — anaconda-ks.cfg 와 한글 기본 디렉터리들
  • cp … /mydata/test2 후 ls -l /mydata/ → lost+found · test2 만 있고 test1 이 없음
  • mount 마지막 줄 /dev/sdb1 on /mydata type ext4 (rw,relatime) → 연결된 게 확인됨
  • umount /dev/sdb1 — 연결 끊기 (umount /mydata 처럼 디렉터리로 써도 됨) → 다시 ls 하면 test1 이 그대로 있음 (시각도 14:27 그대로)

왜 이렇게 보이나?

시점/mydata 로 들어가면 보이는 곳보이는 파일
마운트 전루트 디스크 sda2 의 /mydata 디렉터리test1
mount /dev/sdb1 /mydata 뒤새 디스크 sdb1lost+found · test2 (test1 은 가려짐)
umount 뒤다시 sda2 의 /mydatatest1 (지워진 게 아니라 원래 자리에 그대로)
  • 마운트하면 그 디렉터리의 원래 내용은 지워지지 않고 가려질 뿐 → umount 하면 다시 보임
  • [보충] 마운트 포인트 안에 들어가 있는 상태(cd /mydata)에서는 umount 가 “target is busy”(사용 중)로 안 됨 → cd 로 나온 뒤에

1-8. /etc/fstab 에 등록 — 재부팅해도 자동 마운트

✍️ 로그 속 메모 (그대로) — '''etc/fstab 맨밑줄에:dev/sdb1 /mydata ext4 defaults 0 0 입력하고 저장함'''
  • ⚠️ 메모의 dev/sdb1 은 / 가 빠짐 → 실제로는 /dev/sdb1 (1-9 에서 자동 마운트가 됐으니 파일에는 제대로 썼던 것). 정말 dev/sdb1 로 쓰면 장치를 못 찾아 부팅 때 마운트 실패 → 응급 모드 (5절)
  • 등록한 줄: /dev/sdb1 /mydata ext4 defaults 0 0

1-9. 재부팅 후 — 자동으로 마운트됨

  • 아무것도 마운트하지 않았는데 /mydata 에 lost+found · test2(sdb1 의 내용)가 보임 → fstab 자동 마운트 성공
  • [보충] 로그에 없는 단계: reboot → 다시 로그인 → df (또는 df -h) → /dev/sdb1 … /mydata 줄이 있으면 성공

2. 과제 1 — VITAMIN QUIZ 6-1 (Server(B) · 3GB → 2GB / 1GB)

📖 문제: “Server(B) 가상머신에서 3GB SCSI 디스크를 1개 추가한 후 2GB와 1GB의 파티션으로 분할하자. 그리고 /disk1과 /disk2 디렉터리에 마운트하자.”
📖 HINT1 “부팅 시 /dev/sda와 /dev/sdb가 바뀔 수도 있다. df 명령으로 /에 마운트된 장치를 제외한 다른 장치에서 작업한다.”
📖 HINT2 첫 번째 파티션은 Last Sector 에 +2G, 두 번째 파티션은 First · Last Sector 모두 기본값(Enter)

전체 명령어 순서 [보충 — 로그가 없어서 교재 HINT · 내 메모로 정리]

(VM 끈 상태) Server(B) → Edit virtual machine settings → Add → Hard Disk → SCSI → 3 GB
ls -l /dev/sd*                 # 새 디스크 이름 확인
df                             # / 가 어느 장치인지 확인 (HINT1 — 그 장치는 건드리지 않기)
fdisk /dev/sdb                 # 새 디스크 (그때의 이름)
  n → p → 1 → Enter → +2G      # 1번 파티션 2GB
  n → p → 2 → Enter → Enter    # 2번 파티션 = 나머지 1GB
  p → w                        # 확인하고 저장
mkfs.ext4 /dev/sdb1
mkfs.ext4 /dev/sdb2
mkdir /disk1 /disk2            # 맨 앞 / 꼭 (절대경로)
mount /dev/sdb1 /disk1
mount /dev/sdb2 /disk2
vi /etc/fstab                  # G → o → 아래 두 줄 → Esc → :wq
  /dev/sdb1  /disk1  ext4  defaults  0  0
  /dev/sdb2  /disk2  ext4  defaults  0  0
reboot
df                             # 캡처

vi/etc/fstabvi 뒤 띄어쓰기가 빠져 명령으로 인식 안 됨vi /etc/fstab
vi etc/fstab → E212 에러/ 가 빠져 /root/etc/fstab 이라는 엉뚱한 새 파일이 열림 → /root/etc 디렉터리가 없어 저장 실패 (E212 = 쓰기용으로 파일을 열 수 없음):q! 로 나와서 vi /etc/fstab
dafaultsdefaults 오타 → 마운트 옵션을 못 알아봄defaults 로 고침
입력 모드에서 :wq명령이 아니라 글자로 들어감Esc 먼저 → :wq
재부팅 후 장치 이름이 바뀜루트가 sdb2, 새 디스크가 sda 로 잡힘 (HINT1)fstab 을 /dev/sda1 · /dev/sda2 로 고침

3. 과제 2 — VITAMIN QUIZ 6-9 (Server(B) · 실습 17 쿼터)

📖 문제: “Server(B) 가상머신에 실습 17과 동일한 사양으로 쿼터를 설정하자.”
📖 실습 17 사양: 10GB SCSI 디스크 → /userHome 에 마운트 · 사용자 blackpink · mamamoo · blackpink 에게 soft 40MB / hard 50MB · mamamoo 에게도 같은 한도

① 응급 모드 복구 (시작하자마자)

  • 디스크를 붙였다 뗐다 하는 사이에 이름이 다시 바뀌어서, fstab 의 /dev/sda1 · /dev/sda2 가 실제로는 sdb1 · sdb2 → 부팅 때 마운트 실패 → 응급 모드
sed -i '/disk/s/sda/sdb/' /etc/fstab     # disk 가 들어간 줄에서 sda → sdb 로 바꿔 저장
reboot
  • sed -i = 파일을 직접 고침 · /disk/ = “disk” 가 들어간 줄만 · s/sda/sdb/ = 그 줄의 첫 sda 를 sdb 로
  • [보충] 바꾸기 전에 grep disk /etc/fstab 로 바뀔 줄을 먼저 보면 안전 (다른 줄에 disk 라는 글자가 있으면 같이 바뀜)

② 10GB SCSI 디스크 추가 — 재부팅 없이 인식

echo "- - -" | tee /sys/class/scsi_host/host*/scan    # 모든 SCSI 컨트롤러에 “새 디스크 찾아봐”
  • "- - -" = 채널 · 타깃 · LUN 을 전부(와일드카드) 다시 검색 · tee 로 host0 · host1 … 모든 scan 파일에 한 번에 씀
  • Server(B) 는 sdb 를 /disk1 · /disk2 가 쓰고 있어서 새 디스크는 /dev/sdc 로 잡힘 → 교재의 sdb 대신 sdc 로 진행
  • 📖 교재는 VM 을 끄고 추가하는 방법 (실습 17 Step 0)

③ quota 패키지 (없으면 설치)

dnf -y install quota

④ 교재 실습 17 순서대로 (sdb → sdc)

4. 쿼터 개념 정리

defaults vs defaults,usrquota,grpquota

옵션뜻
defaults기본 마운트 옵션 묶음 (rw · suid · dev · exec · auto · nouser · async)
usrquota사용자별 용량 제한 기능 켜기
grpquota그룹별 용량 제한 기능 켜기
  • 옵션을 넣는다고 바로 제한이 걸리지 않고 준비만 됨 — edquota 로 한도를 정하기 전에는 아무도 제한받지 않음 (📖 soft · hard 의 0 은 “한도 0”이 아니라 “제한 안 함”)
  • 그래서 순서: fstab 옵션 → (ext4) tune2fs -O quota → 다시 마운트 → quotacheck → quotaon → edquota 로 한도 → quota · repquota 로 확인

명령 한 줄씩

명령역할
tune2fs -O quota 장치ext4 파일 시스템에 쿼터 기능 자체를 켬 (마운트 해제 상태에서)
quotacheck디스크를 훑어 사용자 · 그룹별 사용량을 세고 쿼터 DB(aquota.*)를 만듦
quotaon / quotaoff설정된 쿼터를 켜기 / 끄기
edquota -u 사용자그 사용자의 한도(soft · hard) 편집 (vi 처럼)
edquota -p A BA 의 한도를 B 에게 복사 (p = prototype)
[보충] edquota -t유예 기간(grace) 바꾸기 — 📖 기본 7일
quota나(현재 사용자) 의 사용량 · 한도 보기
repquota 마운트위치그 파일 시스템의 모든 사용자 사용량 · 한도 보고서

soft vs hard

soft (소프트)hard (하드)
넘을 수 있나넘을 수 있음 — 유예 기간(기본 7일) 동안만절대 못 넘음 — 넘는 순간 Disk quota exceeded
이번 실습40960 KB = 40MB51200 KB = 50MB
유예 기간이 끝나면🤖 soft 아래로 줄이기 전까지 더 못 씀—
  • 단위: blocks · soft · hard 는 KB (📖 40MB = 40,960KB · 50MB = 51,200KB)

ext4 vs xfs

  • 이번 실습 = ext4 (tune2fs · quotacheck · aquota 파일)
  • 🤖 xfs 는 방식이 달라요 — 마운트 옵션(uquota · gquota 등)으로 켜고 xfs_quota 명령으로 한도를 정함 · quotacheck · aquota 파일을 쓰지 않음 (Server 의 루트 / 가 xfs)

5. 트러블슈팅

Server 응급 모드

  • 상황: 디스크를 빼고 재부팅 → “You are in emergency mode” · “EXT4-fs (sdb1): VFS: Can't find ext4 filesystem”
  • 원인: fstab 에 /dev/sdb1 /mydata 줄이 남아 있는데, 디스크가 빠지면서 장치 이름이 바뀌어 sdb1 이 그 ext4 파티션이 아님 → 부팅 중 마운트 실패
  • init 5(GUI 모드)를 쳐도 부팅 때 마운트가 또 실패해서 다시 응급 모드로 돌아옴
  • 해결: root 비밀번호 입력 → vi /etc/fstab → 그 줄 맨 앞에 # (주석 처리) → :wq → reboot → 바뀐 이름을 확인해서 fstab 을 고침
  • fstab 줄을 지우거나 # 로 막아도 디스크 데이터는 그대로 — 자동 마운트만 꺼짐
  • 실수: 입력 모드에서 G · 0 · i · # 를 눌러 글자로 들어감 → Esc → :q! 로 저장 없이 나와서 다시 함
  • [보충] 저장할 때 read-only(읽기 전용) 에러가 나면 mount -o remount,rw / 로 루트를 쓰기 가능하게 다시 마운트한 뒤 저장
  • [보충] 예방법: 장치 이름 대신 blkid 로 확인한 UUID 를 fstab 에 쓰면 이름이 바뀌어도 안전
blkid /dev/sdb1                                                          # UUID 확인
UUID=0c9daa77-fddb-466a-a9ca-920232579830  /mydata  ext4  defaults  0  0   ← fstab 에 이렇게

(위 UUID 는 1-5 의 mkfs.ext4 로그에 나온 실제 값)

  • [보충] 옵션을 defaults,nofail 로 쓰면 그 디스크가 없어도 응급 모드로 가지 않고 부팅이 계속됨

Server(B) 응급 모드

  • 디스크 추가 · 제거 후 sda · sdb 이름이 또 바뀌어 /disk1 · /disk2 마운트 실패 → sed -i '/disk/s/sda/sdb/' /etc/fstab 로 한 번에 고쳐서 해결 (3절 ①)

6. 작업 방식에서 배운 점

  • VMware 콘솔에는 붙여넣기가 안 됨 → 키를 한 글자씩 입력
  • VM 에 키가 들어가게: Ctrl + Alt(입력 해제) → Ctrl + G(입력 잡기)
  • 다른 창에 입력하면 포커스가 넘어가 VM 입력이 끊김 → 작업 중엔 다른 창 클릭 피하기
  • 한워드에 열려 있는 파일은 덮어쓰거나 지울 수 없음 → 먼저 닫기
  • 자동 캡처는 흐림 → 명령 실행 후 직접 캡처하는 게 가장 선명
  • 비밀번호(passwd) 입력은 직접

8. 🔥 시험 대비 핵심 요약 (✍️ 내가 정한 10줄)

  1. 새 디스크 순서: (VM 끄고) 추가 → fdisk 파티션 → mkfs.ext4 포맷 → mkdir → mount → /etc/fstab 등록 → reboot · df 로 확인
  2. fstab 한 줄 6칸 = 장치 · 마운트 위치 · 파일 시스템 · 옵션 · dump · fsck 순서 — 예) /dev/sdb1 /mydata ext4 defaults 0 0
  3. fdisk 키: n 새로 · p primary(Select) / print(Command) · d 삭제 · w 저장 — w 전까지는 디스크가 안 바뀜
  4. 마운트하면 그 디렉터리의 원래 내용은 가려질 뿐 — umount 하면 다시 보임 (test1 ↔ test2)
  5. 장치 이름(sda · sdb · sdc)은 부팅 · 디스크 추가 · 제거에 따라 바뀔 수 있음 → df 로 / 장치 확인 · fstab 엔 UUID(blkid)가 안전
  6. fstab 의 장치를 못 찾으면 부팅 중 마운트 실패 → 응급 모드 → root 로그인 → vi /etc/fstab 에서 그 줄을 고치거나 # 주석 → reboot (데이터는 그대로)
  7. / 로 시작 = 절대경로 · 아니면 지금 위치 기준 상대경로 (mydata/test1 = /root/mydata/test1 · vi etc/fstab = /root/etc/fstab)
  8. vi: 명령 모드 ↔ 입력 모드(i · o) · Esc 먼저 → :wq 저장 · :q! 저장 안 함 · G 맨 아래 · dd 줄 삭제 · u 되돌리기
  9. 쿼터 순서: fstab 옵션 defaults,usrquota,grpquota → tune2fs -O quota → 다시 마운트 → quotacheck · quotaon → edquota -u 로 한도 → quota · repquota · edquota -p A B = 한도 복사
  10. soft = 유예 기간(기본 7일) 동안 넘을 수 있음 · hard = 절대 못 넘음(Disk quota exceeded) · 단위 KB (40960 = 40MB · 51200 = 50MB) · 0 = 제한 없음
