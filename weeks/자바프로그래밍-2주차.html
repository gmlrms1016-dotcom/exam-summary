1. 프로그래밍 언어와 자바의 태동

  • 기계어(0·1) → 어셈블리어(니모닉) → 고급언어(C/C++, Java, C#)
  • 자바: 1991년 선마이크로시스템즈 제임스 고슬링의 그린 프로젝트, 1995년 발표 (초기명 오크 OAK)
  • ⭐ 강조 — 자바 개발 목적 = 플랫폼 독립성 (기존 언어의 플랫폼 종속성 문제 해결)
  • 2009년 오라클이 선마이크로시스템즈 인수

2. WORA와 JVM ★핵심

  • ⭐ 강조 — WORA(Write Once Run Anywhere): 한 번 작성한 코드가 모든 플랫폼에서 실행
  • ⭐ 강조 — 바이트코드(byte code): 자바 소스를 컴파일한 CPU 중립적 목적코드 (.class에 저장)
  • ⭐ 강조 — JVM(Java Virtual Machine): 바이트코드를 인터프리터 방식으로 해석·실행하는 가상기계
  • ✍️ 필기 — JVM 자체는 플랫폼에 종속적(OS마다 별도) 이지만, 바이트코드는 플랫폼 독립적
    • 컴파일: 자바 .java → .class / C : .c → .obj → .exe

3. 자바 vs C/C++ 실행 환경

  • ⭐ 강조 — 자바는 링크 과정이 없다 — 필요한 클래스를 실행 중 동적 로딩(클래스로더)
  • C/C++: 컴파일→링크로 하나의 실행파일(.exe) 생성, 플랫폼마다 다시 컴파일 필요
  • 느린 실행 개선: JIT(Just In Time) 컴파일러가 바이트코드를 해당 CPU 기계어로 변환

4. JDK / JRE / API

  • ⭐ 강조 — JDK(개발 키트) = 개발도구 + JRE / JRE(실행 환경) = JVM + 표준 라이브러리
  • 주요 도구: javac(컴파일러), java(실행기), javadoc, jar, javap(디어셈블러), jdb(디버거)
  • 자바 API = JDK에 포함된 클래스 라이브러리, 패키지(package) 단위로 제공 (import하여 사용)
  • Java 9부터 모듈(module) 프로그래밍 도입 (플랫폼 모듈화, jmods)

5. 자바의 특성 ★암기

  • ⭐ 강조 — 플랫폼 독립성 · 객체지향(상속·다형성·캡슐화) · 멀티스레드 자체 지원
  • ⭐ 강조 — 가비지 컬렉션: 메모리 반환 기능 없이 new(할당)만 있고 JVM이 자동 회수 (실시간 시스템엔 부적합)
  • 포인터 개념 없음 → 안전하고 작성이 쉬움, 타입 체크 엄격
  • ✍️ 필기 — 소스(.java)당 public 클래스는 1개만 가능하고, 파일명 = public 클래스명이어야 한다
  • IDE: 이클립스(Eclipse), IntelliJ IDEA
