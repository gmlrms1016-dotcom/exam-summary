특성영문

3. 파일시스템 vs DBMS ★핵심3주차

구분내용
파일시스템 단점① 데이터 중복성 ② 데이터 종속성(프로그램이 변경되면 데이터도 변경해야 함)
DBMS 장점① 중복 최소화 ② 데이터 독립성(논리적·물리적)
DBMS 단점비용, 교육

DBMS = 데이터베이스를 관리하는 시스템 소프트웨어. 사용자·응용프로그램과 DB 사이의 인터페이스 역할을 하는 논리적 프로그램.

대표 DBMS — MySQL · Oracle · MS SQL · DB2 · MariaDB · CUBRID · PostgreSQL

구성요소 암기 — 데이터(데이터베이스) · 하드웨어(HW) · DBMS · 사용자 · (데이터언어)
사용자역할
DBA (데이터베이스 관리자)슈퍼유저. DB를 구축하고 시스템을 자체적으로 운영·통제
응용 프로그래머응용 프로그램을 작성

DBA 역할 — 구성요소 선정, 구조 정의, 물리적 저장구조·접근방법 결정, 무결성 제약조건 정의, 보안·접근권한 정책, 백업·회복 기법, 성능 감시·분석, DB 재구성

6. 키(Key) ★핵심3주차

종류설명
기본키 (Primary Key)각 투플을 유일하게 구별하는 하나 이상의 속성 집합 · 중복 불가 · 필수 입력
외래키 (Foreign Key)다른 테이블을 참조하는 키
복합키두 개 이상의 속성을 묶어 기본키로 사용
-- 복합키 예: 수강(학번, 과목번호, 성적)
CREATE TABLE 수강(
  학번      char(5),
  과목번호  char(5),
  성적      int,
  PRIMARY KEY(학번, 과목번호)   -- 복합키
);
[Quiz 32p] 기본키 찾기 정답 — 인사기록: 사원번호 / 가족관계: {사원번호, 이름} / 거래처: {사원명, 거래처}

7. MySQL 실습2~3주차

실습 4단계 ★ — ① 데이터베이스(스키마) 생성 → ② 테이블 생성 → ③ 데이터 입력 → ④ 데이터 조회

① 학생 테이블

CREATE DATABASE testdb DEFAULT CHARACTER SET utf8mb4;
USE testdb;

CREATE TABLE 학생(
  학번      int          NOT NULL,
  이름      varchar(30)  NOT NULL,
  성적      int,
  지도교수  char(2),
  PRIMARY KEY(학번)
);
insert into 학생 values('100','Kim',92,'P1');
insert into 학생 values('200','Park',88,'P2');
select * from 학생;

② 제품 테이블 + 조건 검색

USE testdb;
DROP TABLE if exists 제품;
CREATE TABLE 제품(
  제품번호  char(3)      NOT NULL,
  제품명    varchar(20),
  재고량    int,
  단가      int,
  제조업체  varchar(20),
  PRIMARY KEY(제품번호)
);
INSERT INTO 제품 VALUES('P01','그냥만두',5000,4500,'대한식품');
INSERT INTO 제품 VALUES('P02','매운쫄면',2500,5500,'민국푸드');

-- 제품명, 재고량 검색
SELECT 제품명, 재고량 FROM 제품;
-- 제조업체가 '대한식품'인 제품명·단가·제조업체 검색
SELECT 제품명, 단가, 제조업체 FROM 제품 WHERE 제조업체='대한식품';

9. 기본키 · 외래키 ★시험4주차

구분내용 (10p · 11p · 39p · 40p)
기본키
PRIMARY KEY		각 투플을 유일하게 구별할 수 있는 하나 이상의 속성 집합
중복 불가 · 필수 입력(NOT NULL)
외래키
FOREIGN KEY		다른 릴레이션의 기본키를 참조하는 키
참조되는 릴레이션의 기본키 값에 반드시 존재해야 한다 → 참조 무결성 제약조건
외래키는 널(NULL) 값 입력을 허용한다
⭐ 시험문제 (필기) — 외래키는 참조하는 열과 참조되는 열의 데이터 형식이 같아야 한다. 예) 학생.학과번호 int ↔ 학과.학과번호 int
🔑 부모 · 자식 테이블 — 기본키를 주는 쪽이 부모(학과), 외래키로 참조하는 쪽이 자식(학생)입니다.

10. 테이블 2개일 때 순서 ★시험단골4주차

작업순서와 이유
테이블 생성부모(학과) → 자식(학생)
참조할 기본키가 먼저 있어야 외래키를 걸 수 있다
데이터 입력부모(학과) → 자식(학생)
학과번호가 없으면 학생 입력이 거부된다 (참조 무결성)
테이블 삭제자식(학생) → 부모(학과)
자식이 참조 중이면 부모를 지울 수 없다
-- 삭제는 자식(학생)부터
DROP TABLE IF EXISTS 학생;
DROP TABLE IF EXISTS 학과;

11. 스키마와 인스턴스 (24p) ★시험4주차

스키마(Schema) = 데이터베이스를 구성하는 구조와 제약조건에 대한 명세를 기술한 것
구분설명 · 예 (학생 스키마)
데이터 구조 (정적)어떤 속성으로 이루어지는가
예) 학생(학번, 이름, 학년, 성별)
제약 조건 (동적)각 속성에 어떤 값이 올 수 있는가
예) 학번 = 문자 4자리 · 이름 = 문자 최대 10자리
학년 = 정수 1~4 · 성별 = '남' 또는 '여'
인스턴스데이터베이스에 실제 저장된 값
예) (1292001, 김광식, 1, 남)
⭐ 스키마 표기법 쓰는 법 — 테이블명(속성1, 속성2, …) 으로 쓰고 기본키에 밑줄을 긋습니다.
예) 학생(번호, 이름, 학년, 분반, 학과번호) · 학과(학과번호, 학과명)

12. 3단계 스키마 구조 · 데이터 독립성 (5p · 25~27p) ★시험4주차

스키마 (단계)누가 보는 구조인가
외부 스키마 (외부 뷰 A · B · N)
외부 단계		사용자 · 응용 프로그램이 보는 부분 구조 = 뷰(view) · 여러 개
개념 스키마
개념 단계		조직 전체의 논리적 구조 (테이블 전체) · 데이터베이스마다 1개
내부 스키마
내부 단계		디스크에 실제로 저장되는 구조 (저장 방식 · 인덱스)
데이터 독립성뜻
논리적 데이터 독립성개념 스키마가 변해도 외부 스키마는 영향받지 않는다
물리적 데이터 독립성내부 스키마가 변해도 개념 · 외부 스키마는 영향받지 않는다
🔗 단계와 단계를 이어주는 것을 사상(mapping)이라고 합니다 — 외부/개념 사상, 개념/내부 사상. 위(외부)로 갈수록 추상화 수준이 높습니다.

19. 키(Key) 5가지 총정리 ★암기5주차

🔑 키 = 각 투플을 고유하게 식별할 수 있는 하나 이상의 속성(애트리뷰트)들의 모임
키성질 ★설명
수퍼키 Super Key유일성유일하게 구별할 수 있는 속성들의 모임 (필요 없는 속성이 섞여도 됨)
후보키 Candidate Key유일성 + 최소성유일하게 식별하는 최소한의 속성들의 모임
기본키 Primary Key중복불가 · 필수입력후보키 중에서 선택한 하나
대체키 Alternate KeyUNIQUE후보키 중 기본키로 뽑히지 않은 키
외래키 Foreign Key참조다른 릴레이션의 기본키를 참조하는 키
(참고) 대리키 Surrogate Key인위적식별자가 너무 길거나 여러 속성일 때 새로 만들어 붙인 식별자

-- 신입생(학번, 주민등록번호, 이름, 주소, 학과명)
후보키 : {학번} , {주민등록번호}      ← 유일성 + 최소성
기본키 : {학번}
대체키 : {주민등록번호}

        (학번,이름) (학번,주소) (주민등록번호,이름) (학번,주민등록번호,이름) …
✍️ 필기 — "다음은 후보키인가? 이유를 쓰시오" · (학번, 주민등록번호) X · (주민등록번호, 이름) X
→ 유일성은 있지만 필요 없는 속성이 붙어 최소성을 만족하지 못하므로 후보키가 아니라 수퍼키입니다.

20. 뷰(view) ★핵심5주차

💡 뷰 = 다른 테이블을 기반으로 만든 가상의 테이블. 실제 데이터는 원래 테이블에 있고 뷰는 보여 주는 창입니다.
🎯 장점 2가지 ★ — ① 보안(필요한 열만 보여 줌) ② 사용의 편의성(복잡한 조회를 이름 하나로)
-- 뷰 정의(생성)
CREATE VIEW 뷰이름
as
SELECT 열이름
FROM   테이블이름;

DROP VIEW 뷰이름;        -- 뷰 삭제
DROP TABLE 테이블이름;   -- 테이블 삭제

실습 5-1 — 직원 → 직원_뷰 (41~43p)

-- 뷰 생성: 직원_뷰(이름, 전화번호)
CREATE VIEW 직원_뷰
as
SELECT 이름, 전화번호
FROM   직원;

SELECT * FROM 직원_뷰;                                        -- 뷰 조회
INSERT INTO 직원_뷰(이름, 전화번호) VALUES('신재영','010-9999-9999');  -- 뷰에 입력
SELECT * FROM 직원;                                           -- 신재영이 테이블에도 들어감
⭐ 핵심 — 뷰에 넣은 데이터는 기반 테이블(직원)에 저장됩니다. 뷰에 없는 열(주소 · 연봉)은 값을 주지 않았으니 주소 NULL · 연봉 기본값 0이 됩니다.

3단계 구조를 뷰로 (44~47p)

-- 가입고객(번호,이름,성별,나이,직업,주소,연락처)   ← 개념 스키마
CREATE VIEW 고객분석팀
as
SELECT 성별, 나이, 직업
FROM   가입고객;

-- 뷰의 열 이름을 새로 붙이기
CREATE VIEW 상품배송팀(고객번호, 고객이름, 주소, 연락처)
as
SELECT 번호, 이름, 주소, 연락처
FROM   가입고객;
⭐ 뷰 이름 뒤 괄호에 이름을 적으면 뷰의 열 이름을 바꿀 수 있습니다(번호 → 고객번호). 팀마다 다른 외부 스키마(뷰) 를 주는 것이 3단계 구조 · 필요 없는 열을 감추니 보안도 됩니다. → 3단계 구조는 12번

21. 널 값(NULL) ★5주차

🕳️ 널 값 = 알려지지 않은 값(Unknown). 값을 모르거나 적합한 값이 없을 때 씁니다. 숫자 0도 아니고 공백도 아닙니다.
-- 주소록(이름, 전화번호, 주소, 생일)
-- ① 값 자리에 NULL 을 그대로
INSERT INTO 주소록(이름, 전화번호, 주소, 생일) VALUES('이건우','010-2132-2345', NULL, NULL);

-- ② 넣을 열만 쓰기 (나머지는 자동으로 NULL)
INSERT INTO 주소록(이름, 전화번호) VALUES('이건우','010-2132-2345');

-- ③ 열을 생략하고 전체 값 넣기
INSERT INTO 주소록 VALUES('홍길동','010-1234-5678','서울','3월15일');
⚠️ 'NULL' 처럼 따옴표로 감싸면 널 값이 아니라 "NULL" 이라는 글자가 들어갑니다. 널 값은 따옴표 없이 NULL.

22. INSERT 5가지 방법 ★5주차

-- clubmember(mno, mname, mbirth, mreg_date, mgpa)
CREATE TABLE clubmember (
    mno         int            NOT NULL ,              -- 회원번호
    mname       varchar(20)    NOT NULL ,              -- 회원명
    mbirth      date ,                                 -- 생일
    mreg_date   TIMESTAMP      DEFAULT NOW()  ,        -- 등록일자 (MySQL)
    mgpa        decimal(3, 1) ,                        -- 평점
    PRIMARY KEY (mno)
);
방법SQL
1-1 열 개수 = 값 개수면 열 이름 생략INSERT INTO clubmember VALUES(121,'홍길동','19900315','140320',4.3);
1-2 NULL 입력INSERT INTO clubmember VALUES(123,'이정진', NULL, '140425', NULL);
3 열 순서 변경 (열 이름을 값 순서대로)INSERT INTO clubmember(mno,mbirth,mreg_date,mname,mgpa) VALUES(510,'19841210','140816','이정무',3.8);
4 넣을 열 이름만INSERT INTO clubmember(mno,mname,mbirth,mreg_date) VALUES(210,'김윤식','1994-05-08','140912');
5 DEFAULT 값으로INSERT INTO clubmember(mno,mname,mbirth) VALUES(325,'홍진아','1994-12-14');
⭐ DEFAULT NOW() — 값을 넣지 않으면 현재 날짜·시간이 자동으로 들어갑니다. (datetime DEFAULT CURRENT_TIMESTAMP 도 같은 뜻) · 값 자리에 DEFAULT 라고 써도 기본값이 들어갑니다.

[Quiz 5-1] 직원 테이블 (41 · 42p)

USE testdb;
DROP TABLE if exists 직원;

-- 직원(이름, 주소, 전화번호, 연봉)
CREATE TABLE 직원(
    이름      VARCHAR(20)   NOT NULL ,
    주소      VARCHAR(100) ,
    전화번호  CHAR(13)      NOT NULL ,
    연봉      INT           DEFAULT 0 ,
    PRIMARY KEY(이름)
);

INSERT INTO 직원 VALUES('우태하','서울시 서초구','010-1111-1111',1000);
INSERT INTO 직원 VALUES('김선우','서울시 구로구','010-2222-2222',2000);
INSERT INTO 직원 VALUES('이영지','서울시 마포구','010-3333-3333',3000);
INSERT INTO 직원 VALUES('유희정','서울시 마포구','010-4444-4444',4000);
INSERT INTO 직원 VALUES('오형준','부산시 연산구','010-5555-5555',5000);
INSERT INTO 직원 VALUES('고진수','서울시 구로구','010-6666-6666',6000);

⚠️ 강의요약에 CREATE TABLE 작원( 이라고 오타가 있습니다 — 시험 답안에는 직원으로 쓰세요. 내 실습본에는 NOT NULL·DEFAULT 0 이 빠져 있어 뷰로 입력하면 연봉이 NULL이 됩니다.

[실습 5-2] 사원 테이블 — 널 값 (49p)

DROP TABLE 사원;

-- 사원(사원번호, 사원명, 연락처, 생일)
CREATE TABLE 사원(
    사원번호  char(4) ,
    사원명    varchar(20) ,
    연락처    char(13) ,
    생일      varchar(15) ,
    PRIMARY KEY(사원번호)
);

INSERT INTO 사원 VALUES('D001','정지영', NULL, NULL);
INSERT INTO 사원 VALUES('D002','김선주','010-1111-1111', NULL);
INSERT INTO 사원 VALUES('D003','정성호', NULL, '10월4일');
SELECT * FROM 사원;
⭐ 시험 연결 — 사원 테이블의 차수 = 4(사원번호·사원명·연락처·생일), 위처럼 3줄 넣으면 카디널리티 = 3
⚠️ 필기의 INSERT INTO VALUES('D002',…) 는 테이블 이름이 빠져 실행되지 않습니다.

1데이터베이스 정의 4가지에 해당하지 않는 것은?

2파일시스템과 비교한 DBMS 의 장점은?

정답 C — 파일시스템 단점 = 중복성·종속성 / DBMS 장점 = 중복 최소화·데이터 독립성 / DBMS 단점 = 비용·교육

3DML(데이터 조작어) 에 속하지 않는 명령은?

정답 D — CREATE 는 DDL(정의어)입니다. DML = INSERT · SELECT · UPDATE · DELETE

4기본키(Primary Key)에 대한 설명으로 옳지 않은 것은?

정답 C — 기본키는 중복 불가 · 필수 입력입니다.

5주민등록번호처럼 길이가 고정된 문자열에 알맞은 자료형은?

정답 B — char(n) 고정 문자열 · varchar(n) 가변 문자열(주소, 영화제목)

6데이터베이스 정의 4가지 중 중복의 최소화를 뜻하는 것은?

정답 B — 통합(integrated) = 중복의 최소화 · 공유 = 여러 응용시스템이 함께 사용

7데이터베이스의 특성이 아닌 것은?

정답 D — 특성 4가지 = 실시간 접근 · 계속 변화 · 동시 공유 · 내용으로 참조

8데이터베이스 시스템의 구성요소가 아닌 것은?

정답 D — 구성요소 = 데이터 · 하드웨어 · DBMS · 사용자 (+ 데이터 언어)

9DBMS 의 단점으로 옳은 것은?

정답 C — DBMS 단점 = 비용, 교육 / 중복·종속은 파일시스템의 단점

10MySQL Workbench 에서 여러 줄(전체)을 실행하는 단축키는? (강의 기준)

정답 B — 한 줄 실행 Ctrl+Enter / 여러 줄 실행 Ctrl+Shift+Enter

11차수(degree) 의 뜻으로 옳은 것은?

정답 B — 차수 = 애트리뷰트(열)의 수 · 카디널리티 = 투플(행)의 수 (강의자료 41p)

12신입생(학번, 주민등록번호, 이름, 주소, 학과명) 테이블에 학생 4명이 저장되어 있다. 카디널리티는?

정답 B — 카디널리티 = 투플(행)의 수 = 4 · 차수는 열 5개이므로 5 (42p)

13외래키에 대한 설명으로 옳지 않은 것은?

정답 C — 외래키는 널 값 입력을 허용합니다. 널을 못 넣는 것은 기본키(필수 입력)입니다. (11p · 40p)

14학생 테이블이 학과 테이블을 외래키로 참조할 때 테이블 삭제 순서로 옳은 것은?

정답 B — 삭제는 자식(학생) → 부모(학과) 순서. 생성과 입력은 반대로 부모 → 자식입니다.

15사용자와 응용 프로그램이 보는 부분 구조(뷰)에 해당하는 스키마는?

정답 A — 외부 스키마 = 사용자가 보는 뷰 / 개념 = 조직 전체 논리 구조 / 내부 = 실제 저장 구조 (25p)

16후보키(Candidate Key)가 수퍼키와 다른 점은?

정답 B — 수퍼키는 유일성만, 후보키는 유일성 + 최소성. 그래서 (학번, 이름)은 수퍼키지만 후보키는 아닙니다.

17뷰(view)에 대한 설명으로 옳은 것은?

정답 C — 뷰 = 가상의 테이블. 장점은 보안 · 사용의 편의성이고 DROP VIEW 로 삭제합니다.

18널 값(NULL) 에 대한 설명으로 옳은 것은?

정답 A — 널 값 = Unknown. 0도 공백도 아니며, 기본키는 필수입력이라 널 값을 가질 수 없습니다.
